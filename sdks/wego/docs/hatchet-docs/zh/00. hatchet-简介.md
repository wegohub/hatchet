# 什么是 Hatchet？

Hatchet 是一个开发者平台，帮助工程团队构建和部署关键任务的 AI agent、持久化工作流（durable workflow）以及后台任务。它支持使用 Python、TypeScript、Go 和 Ruby 编写的应用，可以通过 [Hatchet Cloud](https://cloud.hatchet.run) 以服务方式使用，也可以[自托管](<self-hosting/01. index.md>)（我们是[开源项目，采用 100% MIT 许可证](https://github.com/hatchet-dev/hatchet)）。Hatchet 提供了完整的平台能力，包括队列、自动重试、实时监控、告警和日志。

与传统的队列系统不同，Hatchet 围绕持久性（durability）这一概念构建。每个 task 和 agent 调用都会被持久化存储在 Hatchet 中，从而支持调试、重试和重放，以及[持久化工作流](<v1/02. core-concepts（核心概念）/04. durable-execution.md>)等更复杂的特性。

## 核心概念

开始使用 Hatchet 时，需要理解三个主要概念：

- **[Task](<v1/02. core-concepts（核心概念）/01. tasks.md>)** — 最基本的工作单元。一个 task 封装单个函数，并向 Hatchet 提供调度、执行和观察它所需的一切信息。
- **[Worker](<v1/02. core-concepts（核心概念）/02. workers.md>)** — 运行在你的基础设施中的长驻进程，负责获取并执行 task。
- **[持久化工作流（Durable Workflow）](<v1/02. core-concepts（核心概念）/04. durable-execution.md>)** — 将多个 task 组合成具有依赖关系、重试和检查点机制的持久化流水线。

所有 task 和 workflow 都**以代码的形式定义**，因此易于版本管理、测试和部署。

## 使用场景

虽然 Hatchet 是一个通用编排平台，但它特别适合以下场景：

- **AI agent** — Hatchet 的持久化特性允许 agent 在遇到意外错误时自动对当前状态做检查点，并从上次中断的地方继续执行。Hatchet 的可观测性特性和分布式优先的设计，专为大规模调试长时间运行的 agent 而打造。
- **大规模并行化** — Hatchet 能够处理数百万个并行 task 执行而不会使你的 worker 过载。worker 级别的 slot 控制让 worker 只接受自己能够处理的工作量，同时[公平性（fairness）](<v1/05. flow-control（流控）/01. concurrency.md>)和[优先级](<v1/05. flow-control（流控）/03. priority.md>)等特性专为帮助大规模并行摄取而设计。
- **关键任务工作负载** — Hatchet 中的一切默认都是持久化的。这意味着每个 task、DAG、event 或 agent 调用都会存储在持久化事件日志中，随时可以在未来某个时刻重放。

## 自托管

如果你计划自托管，或者有本地部署（on-premise）的需求，需要考虑以下几点：

- **极简的基础设施依赖** — Hatchet 基于 PostgreSQL 构建，对于简单的工作负载，[它就是你所需要的全部](<self-hosting/02. hatchet-lite.md>)。本地开发请参阅[在本地运行 Hatchet](<v1/01. get-started（入门）/04. running-locally.md>)。
- **功能完整的开源版本** — Hatchet 采用 100% MIT 许可证，你可以先在 [Hatchet Cloud](https://cloud.hatchet.run) 上运行相同的应用代码快速上手，在需要更多控制时再进行[自托管](<self-hosting/01. index.md>)。
