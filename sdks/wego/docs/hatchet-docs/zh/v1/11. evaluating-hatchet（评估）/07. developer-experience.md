# 开发者体验

Hatchet 的设计注重日常实用性：用代码编写 workflow，在本地以紧密的反馈循环运行 worker，并以良好的可见性调试生产 run。

## 以代码定义 Workflow

你在应用代码中定义 task 和 workflow，然后用输入数据触发它们。Hatchet 负责那些否则你需要自己搭建的运维部分：

- **持久化**（重启不会丢失工作）
- **重试/超时**
- **并发与速率限制**
- **对"什么在运行、在哪里运行、为什么运行"的可见性**

## 控制台（UI）

控制台是你了解"现在正在发生什么？"的地方：

- **Runs**：状态、输入/输出和执行历史
- **Workers**：已连接的 worker 及其健康状况
- **Workflows**：定义和最近活动
- **Settings**：tenant、API token、配置

它适用于调试、运维检查和临时触发。

## CLI

[Hatchet CLI](<../01. get-started（入门）/01. index.md>) 是在终端中开发和运维 Hatchet 的最快方式：

- **`hatchet worker dev`**：运行带热重载的本地 worker
- **`hatchet trigger`**：从命令行触发 workflow（便于冒烟测试）
- **`hatchet tui`**：runs/workers/workflows 的终端 UI
- **`hatchet profile`**：在 tenant 和环境之间切换

安装和完整命令集请参阅 [CLI 参考](<../01. get-started（入门）/01. index.md>)。

## 编码 agent（MCP）

如果你在编辑器中使用 AI 编码工具，可以通过 [MCP（Model Context Protocol）服务器](<../01. get-started（入门）/03. using-coding-agents.md>)使用 Hatchet 文档。我们还发布了"agent skills"（简短的分步操作手册），让编码 agent 能够运行常见的 Hatchet 工作流——比如启动 worker、触发 workflow、调试 run——而无需猜测 CLI 的用法。

配置方法请参阅[使用编码 Agent](<../01. get-started（入门）/03. using-coding-agents.md>)。
