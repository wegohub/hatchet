# 安全

本页指向 Hatchet 的安全资源，并重点说明 Hatchet Cloud 和自托管部署最重要的安全注意事项。

## 信任中心

Hatchet 已通过 SOC 2 Type II、HIPAA 和 GDPR 合规。公司级安全实践、合规报告和安全文档见 **[Hatchet Trust Center](https://trust.hatchet.run/)**。

## 同一份源码，同样的安全

Hatchet Cloud 和自托管 Hatchet 运行同一份代码库。开源项目 100% MIT 许可，并定期接受第三方渗透测试。发现的问题会在两种部署模式中同步修复，因此安全改进对所有用户一视同仁。

## Hatchet Cloud

Hatchet Cloud 是 Hatchet 的托管服务：

- **传输加密**：所有 API 和 worker 流量均使用 TLS 加密。worker 与 engine 之间的 gRPC 连接默认使用 TLS。
- **静态加密**：存储在 Hatchet Cloud 中的数据静态加密。
- **Tenant 隔离**：每个 tenant 的数据逻辑隔离。请求经过认证并限定于单个 tenant。
- **认证**：API token 按 tenant 划分作用域，可配置过期时间。dashboard 支持 Google、GitHub 等 SSO（更多方式即将推出）。
- **渗透测试**：Hatchet Cloud 定期接受独立安全公司测试。发现的问题按既定时间表跟踪和修复。
- **基础设施**：Hatchet Cloud 运行在 AWS 上，配备私有网络、自动补丁和集中式日志。

最权威的控制措施、策略和合规报告请参考 **[Hatchet Trust Center](https://trust.hatchet.run/)**。

## 自托管

自托管 Hatchet 时，你的安全态势取决于如何部署和运维 Hatchet 服务及其依赖。一个实用的基线：

- **在 API 前置 TLS**：在你的 ingress/负载均衡器（或直接在 API 上）终止 TLS，只向需要的网络暴露服务。
- **将 token 和数据库凭据视为机密**：使用机密管理器并轮换凭据；避免将机密提交到 git 或打包进镜像。
- **限制网络可达性**：将对 Hatchet API 和 PostgreSQL 的访问限制在可信网络内（VPC、私有子网或 Kubernetes network policy）。
- **最小权限**：以所需的最小数据库权限运行 Hatchet；不要复用 "admin" 数据库凭据。
- **保持更新**：及时更新 Hatchet 及其依赖以获取安全修复。

部署和配置指导见[自托管](<../../self-hosting/01. index.md>)，或[联系我们](mailto:support@hatchet.run)获取帮助。
