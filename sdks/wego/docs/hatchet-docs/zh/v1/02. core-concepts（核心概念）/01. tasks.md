# Task

Hatchet 中的基本工作单元是 **task**。在最基础的层面上，task 就是一个函数。你可以单独调用一个 task（"standalone" 独立 task），将多个 task 组合成 [DAG workflow](<../06. durable-execution（持久化执行）/06. directed-acyclic-graphs.md>)，或使用 [durable task 组合](<../06. durable-execution（持久化执行）/02. child-spawning.md>)在运行时派生子 task。

你调用的每个 task 都是 **durable** 的 —— 即使运行结束之后，Hatchet 也会持久化该 task、其状态及其结果。

## 定义 task

一个 task 需要名称和函数。函数接收[输入](#输入与输出)和[上下文](#上下文对象)。

#### Python

```python
class SimpleInput(BaseModel):
    message: str


class SimpleOutput(BaseModel):
    transformed_message: str


# Declare the task to run
@hatchet.task(name="first-task", input_validator=SimpleInput)
def first_task(input: SimpleInput, ctx: Context) -> SimpleOutput:
    print("first-task task called")

    return SimpleOutput(transformed_message=input.message.lower())
```

在 Python SDK 中，task 的参数是按*位置*传递的，因此你可以随意命名。例如，将 task 定义为 `async def my_task(foo: Input, bar: Context) -> None:` 是完全合法的。Hatchet 中的 task 可以是同步或异步的，不过我们通常建议尽可能使用异步。

#### Typescript

```typescript
import { hatchet } from '../hatchet-client';

// (optional) Define the input type for the workflow
export type SimpleInput = {
  Message: string;
};

export const simple = hatchet.task({
  name: 'simple',
  retries: 3,
  fn: async (input: SimpleInput) => {
    return {
      TransformedMessage: input.Message.toLowerCase(),
    };
  },
});
```

在 TypeScript SDK 中，`fn` 参数是一个接收 workflow 输入和上下文对象的函数。上下文对象包含 workflow 运行的相关信息（例如运行 ID、workflow 的输入等）。它可以是同步的，也可以是异步的。

#### Go

```go
type SimpleInput struct {
	Message string `json:"message"`
}

type SimpleOutput struct {
	Result string `json:"result"`
}

task := client.NewStandaloneTask("process-message", func(ctx hatchet.Context, input SimpleInput) (SimpleOutput, error) {
	return SimpleOutput{
		Result: "Processed: " + input.Message,
	}, nil
})
```

#### Ruby

```ruby
FIRST_TASK = HATCHET.task(name: "first-task") do |input, ctx|
  puts "first-task called"
  { "transformed_message" => input["message"].downcase }
end
```

## 输入与输出

每个 task 都接收一个**输入（input）** —— 一个在 task 被触发时传入的 JSON 可序列化对象。task 的返回值即为该 task 的**输出（output）**，调用方在等待 task 结果时会收到它。

Hatchet 的各 SDK 支持 task 输入和输出类型的类型检查与运行时校验，让你能够以类型安全、可预测的方式将 Hatchet task 集成到代码库中，并获得与将 Hatchet task 运行替换为本地函数调用完全相同的保障。

如何为 task 的输入和输出提供校验器，可以参考[上面的示例](#定义task)。

## 上下文对象

除了输入和输出载荷之外，每个 task 还会接收一个**上下文（context）**。上下文提供了可能在运行时对 task 执行有用的 Hatchet 相关信息。例如，你可以从上下文中访问 workflow 运行 ID、task 运行 ID 或重试次数，并让 task 的应用逻辑对这些值进行处理。

上下文还提供了与 Hatchet 众多功能交互的辅助方法，例如[管理取消](<../04. reliability（可靠性）/03. cancellation.md>)、[刷新超时](<../04. reliability（可靠性）/02. timeouts.md#refreshing-timeouts>)、[发布流事件](<../09. operations（运维）/02. streaming.md#publishing-stream-events>)等。

## 配置

task 可以进行配置以应对分布式系统中的常见问题。例如，你可能希望在外部 API 返回瞬时错误时自动重试 task，或者限制同时运行的 task 实例数量，避免压垮下游服务。

| 概念 | 作用 |
| --- | --- |
| [重试（Retries）](<../04. reliability（可靠性）/01. retry-policies.md>) | 在失败时重试 task，可选退避策略。 |
| [超时（Timeouts）](<../04. reliability（可靠性）/02. timeouts.md>) | 限制 task 等待调度或运行的时长。 |
| [并发（Concurrency）](<../05. flow-control（流控）/01. concurrency.md>) | 在客户之间公平分配负载。 |
| [速率限制（Rate limits）](<../05. flow-control（流控）/02. rate-limits.md>) | 在时间窗口内节流 task 执行。 |
| [优先级（Priority）](<../05. flow-control（流控）/03. priority.md>) | 影响相对于其他排队 task 的调度顺序。 |
| [Worker 亲和性（Worker affinity）](<../07. workers（工作进程）/04. worker-affinity.md>) | 为该 task 倾向于或要求使用特定 worker。 |

## task 如何在 worker 上执行

task 不会自己运行，而是由 [worker](<02. workers.md>) 执行。worker 是一个长期运行的进程，它向 Hatchet 注册一个或多个 task。当你触发一个 task 时，Hatchet 会将其放入队列，并分配给一个注册了该 task 的可用 worker。当 task 完成时，运行在 worker 上的 Hatchet SDK 会将结果发回给 Hatchet，由 Hatchet 将该 task 标记为成功或失败、展示结果等。
