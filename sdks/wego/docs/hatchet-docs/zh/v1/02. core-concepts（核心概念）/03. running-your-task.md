# 运行 Task

一旦你[定义了一些 task](<01. tasks.md>) 并将其注册到 [worker](<02. workers.md>) 上，就可以运行它们了！

Hatchet 提供了多种运行 task 的方式，以满足不同的应用需求。大致来说，包括[同步等待](#同步等待)、各种形式的[即发即忘式触发](#即发即忘)，以及让 task [周期性运行](#cron)或在[未来某个特定时间](#计划运行)运行的调度方式。

## 同步等待

fire-and-wait 是一种常见的 task 触发方式，它会阻塞直到 task 完成并返回结果。当你需要对 task 的结果做进一步处理时，这特别有用。例如，如果你的 task 生成一些 LLM 输出，你想将其返回给用户或持久化到数据库中，你可以触发一个 task、等待其完成、收集结果，然后继续你的应用逻辑。

#### Python

在 `Task` 或 `Workflow` 对象上调用 `run` 或 `aio_run` 来触发。这些方法会阻塞直到 task 或 workflow 完成，并返回结果。

```python
from examples.child.worker import SimpleInput, child_task

child_task.run(SimpleInput(message="Hello, World!"))
```

Hatchet Python SDK 的 run 方法也有可供 `await` 的异步版本，以 `aio_` 为前缀，例如 `aio_run`。

```python
result = await child_task.aio_run(SimpleInput(message="Hello, World!"))
```

注意，这里的 `input` 类型是一个 Pydantic 模型，与被触发的 task 或 workflow 的输入 schema 相匹配。

#### Typescript

在 `Task` 对象上调用 `run` 来触发。它返回一个在 task 完成时 resolve 的 promise，并返回结果。

```typescript
const res = await parent.run(
  {
    Message: 'HeLlO WoRlD',
  },
  {
    additionalMetadata: {
      test: 'test',
    },
  }
);

const res3 = await simpleWithZod.run({
  Message: 'HeLlO WoRlD',
});
console.log(res3.TransformedMessage);

// 👀 Access the results of the Task
console.log(res.TransformedMessage);
```

#### Go

在 `Task` 对象上调用 `Run` 来触发。它会阻塞直到 task 完成并返回结果。

```go
result, err := task.Run(context.Background(), SimpleInput{Message: "Hello, World!"})
if err != nil {
	return err
}
```

#### Ruby

在 `Task` 对象上调用 `run` 来触发。它会阻塞直到 task 完成并返回结果。

```ruby
result = CHILD_TASK_WF.run({ "message" => "Hello, World!" })
```

## 即发即忘

另一方面，fire-and-forget 式的触发会将 task 入队而不等待结果。这适用于后台作业，例如发送邮件、处理上传，或启动长时间运行的管道 —— 应用*不*需要等待结果即可继续执行。

#### Python

在 `Task` 或 `Workflow` 对象上调用 `run` 并传入 `wait_for_result=False`，即可即发即忘地将任务入队。它会返回一个 `WorkflowRunRef`，你之后可以用它获取运行 ID 和结果。

```python
ref = say_hello.run(input=HelloInput(name="World"), wait_for_result=False)
```

也有异步版本：

```python
ref = await say_hello.aio_run(
    input=HelloInput(name="Async World"), wait_for_result=False
)
```

注意，这里的 `input` 类型是一个与该 task 输入 schema 匹配的 Pydantic 模型。

#### Typescript

在 `Task` 对象上调用 `runNoWait`，即可在不等待结果的情况下入队。它会返回一个 `WorkflowRunRef`。

```typescript
import { simple } from './workflow';
// ...

async function main() {
  // 👀 Enqueue the workflow
  const run = await simple.runNoWait({
    Message: 'hello',
  });

  // 👀 Get the run ID of the workflow
  const runId = await run.getWorkflowRunId();
  // It may be helpful to store the run ID of the workflow
  // in a database or other persistent storage for later use
  console.log(runId);
```

#### Go

在 `Task` 对象上调用 `RunNoWait`，即可在不等待结果的情况下入队。它会返回一个 `WorkflowRunRef`。

```go
runRef, err := task.RunNoWait(context.Background(), SimpleInput{Message: "Hello, World!"})
if err != nil {
	return err
}

fmt.Println(runRef.RunId)
```

#### Ruby

在 `Task` 对象上调用 `run_no_wait`，即可在不等待结果的情况下入队。它会返回一个 `WorkflowRunRef`。

```ruby
ref = SAY_HELLO.run_no_wait({ "name" => "World" })
```

以即发即忘方式运行 task 时，你之后仍然可以获取结果。这些触发方法返回的 workflow run ref 上有一个 result 方法，需要时可以用它获取被触发 task 的结果。

#### Python

使用 `ref.result()` 阻塞直到结果可用：

```python
result = ref.result()
```

或 await `aio_result`：

```python
result = await ref.aio_result()
```

#### Typescript

```typescript
// the return object of the enqueue method is a WorkflowRunRef which includes a listener for the result of the workflow
const result = await run.output;
console.log(result);

// if you need to subscribe to the result of the workflow at a later time, you can use the runRef method and the stored runId
const ref = hatchet.runRef(runId);
const result2 = await ref.output;
console.log(result2);
```

#### Go

```go
result, err := runRef.Result()
if err != nil {
	return err
}

var resultOutput SimpleOutput
err = result.TaskOutput("process-message").Into(&resultOutput)
if err != nil {
	return err
}

fmt.Println(resultOutput.Result)
```

#### Ruby

```ruby
result = ref.result
```

### 通过事件触发

另一种即发即忘式运行 task 的方法是向 Hatchet [推送事件](<../03. triggers（触发）/04. events.md#pushing-events-to-hatchet>)。如果一个 task 被配置为由某个事件触发，那么当该事件被推送到 Hatchet 时，将使用事件的载荷作为运行输入，触发相应的运行。

你可以使用 SDK 直接向 Hatchet 推送事件，也可以通过 [webhook](<../03. triggers（触发）/05. webhooks.md>)，后者在接入时会在内部转换为 Hatchet 事件。

## Cron

另一种常见的 task 运行方式是按 cron 计划运行，Hatchet [原生支持](<../03. triggers（触发）/02. cron-runs.md>)。cron 适用于每天在固定时间运行的 task，例如数据处理管道、对账作业等。

注意，Hatchet 支持秒级 cron 粒度，不过在大多数情况下，以分钟作为最细粒度就完全够用了。

## 计划运行

最后，Hatchet 还支持[调度运行在未来的特定时间触发](<../03. triggers（触发）/01. scheduled-runs.md>)。这在你想在等待一段已知时间后再运行某个 task 时特别有用，例如向新用户发送跟进邮件或欢迎邮件；或者让你的客户选择他们希望某件事运行的时间，例如发送提醒。

## 从仪表板触发

最后，仪表板中有多个页面带有 `Trigger Run` 按钮。你可以提供运行参数，例如输入、附加元数据和计划时间。
