# Worker

Hatchet 中的 worker 是执行 [task](<01. tasks.md>) 的长期运行进程。从最宽泛的意义上讲，可以把 worker 想象成一个简单的 `while` 循环：从 Hatchet 接收新的 task 分配、执行该 task，然后报告结果。

无论在什么环境中启动 worker —— 本地、虚拟机等 —— 它们都会向 Hatchet 注册自己，以开始接收并执行 task。

## 声明 worker

worker 需要一个名称和一组要注册的 task（或 workflow，稍后详述）：

#### Python

```python
def main() -> None:
    worker = hatchet.worker("dag-worker", workflows=[dag_workflow])

    worker.start()
```

#### Typescript

```typescript
import { hatchet } from '../hatchet-client';
import { simple } from './workflow';
import { parent, child } from './workflow-with-child';
import { simpleWithZod } from './zod';

async function main() {
  const worker = await hatchet.worker('simple-worker', {
    // 👀 Declare the workflows that the worker can execute
    workflows: [simple, simpleWithZod, parent, child],
    // 👀 Declare the number of concurrent task runs the worker can accept
    slots: 100,
  });

  await worker.start();
}

if (require.main === module) {
  main();
}
```

#### Go

```go
worker, err := client.NewWorker("simple-worker", hatchet.WithWorkflows(task))
if err != nil {
	log.Fatalf("failed to create worker: %v", err)
}

interruptCtx, cancel := cmdutils.NewInterruptContext()
defer cancel()

err = worker.StartBlocking(interruptCtx)
if err != nil {
	log.Fatalf("failed to start worker: %v", err)
}
```

#### Ruby

```ruby
def main
  worker = HATCHET.worker("dag-worker", workflows: [DAG_WORKFLOW])
  worker.start
end
```

worker 启动时，会将其所有 task 和 workflow 注册到 Hatchet。从那时起，Hatchet 就知道将匹配的 task 路由到该 worker。

需要注意的一点是，多个 worker 可以注册同一个 task。在这种情况下，Hatchet 会在所有 worker 之间分发工作，从而实现简单的水平扩展。

## 启动 worker

#### CLI（推荐）

在开发阶段运行 worker 最快的方式是使用 Hatchet CLI。它会处理身份认证，并在代码变更时热重载：

```bash
hatchet worker dev
```

#### 脚本

你也可以脱离 CLI 运行 worker，这在生产环境中很可能是你的做法。为此，你首先需要设置 `HATCHET_CLIENT_TOKEN` 环境变量，或在创建 Hatchet 客户端时通过参数提供。

> **Info:** 如果你还没有 token，可以在仪表板 "Settings" 下的 "API Tokens" 部分生成一个。

```bash
export HATCHET_CLIENT_TOKEN="<your-client-token>"
```

如果你运行的自托管引擎未启用 TLS，还需设置：

```bash
export HATCHET_CLIENT_TLS_STRATEGY=none
```

然后运行 worker：

#### Python

```bash
python worker.py
```

#### Typescript

在你的 `package.json` 中添加一个脚本：

```json
"scripts": {
  "start:worker": "ts-node src/worker.ts"
}
```

然后运行：

```bash
npm run start:worker
```

#### Go

```bash
go run main.go
```

#### Ruby

```bash
bundle exec ruby worker.rb
```

worker 启动后，你会看到确认其已连接的日志：

```
[INFO]  🪓 -- starting hatchet...
[DEBUG] 🪓 -- 'test-worker' waiting for ['simpletask:step1']
[DEBUG] 🪓 -- acquired action listener: efc4aaf2-...
[DEBUG] 🪓 -- sending heartbeat
```

> **Info:** 对于自托管引擎，可能还需要额外的 gRPC 配置选项。详情请参阅
>   [Self-Hosting](<../../self-hosting/08. worker-configuration-options.md>) 文档。

## Slot

每个 worker 都有固定数量的 **slot**，控制它可以并发运行的 task 数量，可通过 worker 的 `slots` 选项配置。例如，如果 `slots` 设为 5，worker 在任意时刻最多并发运行 5 个 task；其余 task 会在队列中等待，直到有 slot 空出。slot 是一种**本地**限制，用于保护单个 worker 不会并发运行超出预期的 task 数量，有助于控制 worker 的资源占用。


要设置 slot 数量，在声明 worker 时传入 `slots` 选项：

#### Python

```python
def main() -> None:
    worker = hatchet.worker(
        "concurrency-demo-worker", slots=10, workflows=[concurrency_limit_workflow]
    )

    worker.start()
```

#### Typescript

```typescript
async function main() {
  const worker = await hatchet.worker('timeout-worker', {
    workflows: [timeoutTask, refreshTimeoutTask],
    slots: 50,
  });

  await worker.start();
}
```

#### Go

```go
worker, err := client.NewWorker("concurrency-worker",
	hatchet.WithWorkflows(
		ConcurrencyRoundRobin(client),
		MultipleConcurrencyKeys(client),
		ConcurrencyCancelInProgress(client),
		ConcurrencyCancelNewest(client),
		ConcurrencyCancelQueuedExceptNewest(client),
		ConcurrencyCancelQueuedExceptOldest(client),
		syncCrm,
		generateReport,
		DynamicMaxRuns(client),
	),
	hatchet.WithSlots(10),
)
if err != nil {
	log.Fatalf("failed to create worker: %v", err)
}
```

#### Ruby

```ruby
def main
  worker = HATCHET.worker(
    "concurrency-demo-worker", slots: 10, workflows: [CONCURRENCY_LIMIT_WORKFLOW]
  )
  worker.start
end
```

Hatchet 中 worker 的默认 slot 数量为 100。在很多情况下，尤其是刚开始使用 Hatchet 时，保持默认值就完全没问题。

默认情况下，每个运行中的 task 消耗一个 slot。可以将 task 配置为消耗多个 slot，这样需要更多内存或 CPU 的 task 就会占用 worker 更多的容量。参见 [Task Slot 成本](<../07. workers（工作进程）/05. slot-cost.md>)。
