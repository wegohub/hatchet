# Hatchet Task 中的取消（Cancellation）

Hatchet 提供了一种优雅取消 task 执行的机制，允许你向正在运行的 task 发出应当停止运行的信号。取消可以在 worker 优雅终止时触发，也可以通过并发控制策略（如 [`CANCEL_IN_PROGRESS`](<../05. flow-control（流控）/01. concurrency.md#cancel-in-progress>)）自动触发——当达到并发限制时，该策略会取消当前正在运行的 task 实例，为新实例腾出 slot。

当 task 被取消时，Hatchet 会向其发送一个取消信号。task 可以检查该信号并采取适当的措施，例如清理资源、中止网络请求或优雅地终止自身执行。

## 取消机制

#### Python

```python
@cancellation_workflow.task()
def check_flag(input: EmptyModel, ctx: Context) -> dict[str, str]:
    for i in range(3):
        time.sleep(1)

        # Note: Checking the status of the exit flag is mostly useful for cancelling
        # sync tasks without needing to forcibly kill the thread they're running on.
        if ctx.exit_flag:
            print("Task has been cancelled")
            raise ValueError("Task has been cancelled")

    return {"error": "Task should have been cancelled"}
```
```python
@cancellation_workflow.task()
async def self_cancel(input: EmptyModel, ctx: Context) -> dict[str, str]:
    await asyncio.sleep(2)

    ## Cancel the task
    await ctx.aio_cancel()

    await asyncio.sleep(10)

    return {"error": "Task should have been cancelled"}
```

```typescript
export const cancellation = hatchet.task({
  name: 'cancellation',

    await sleep(10 * 1000);

      throw new Error('Task was cancelled');
    }

    return {
      Completed: true,
    };
  },
});
```

export const abortSignal = hatchet.task({

      }

#### Go

```go
// Add a long-running task that can be cancelled
_ = workflow.NewTask("long-running-task", func(ctx hatchet.Context, input CancellationInput) (CancellationOutput, error) {
	log.Printf("Starting long-running task with message: %s", input.Message)

	// Simulate long-running work with cancellation checking
	for i := 0; i < 10; i++ {
		select {
		case <-ctx.Done():
			log.Printf("Task cancelled after %d steps", i)
			return CancellationOutput{
				Status:    "cancelled",
				Completed: false,
			}, nil
		default:
			log.Printf("Working... step %d/10", i+1)
			time.Sleep(1 * time.Second)
		}
	}

	log.Println("Task completed successfully")
	return CancellationOutput{
		Status:    "completed",
		Completed: true,
	}, nil
}, hatchet.WithExecutionTimeout(30*time.Second))
```

## 取消的最佳实践

在 Hatchet task 中处理取消时，请考虑以下最佳实践：

1. **优雅终止**：当 task 收到取消信号时，应尽量优雅地终止执行。在从 task 函数返回之前，清理资源、中止挂起的操作，并执行任何必要的清理工作。

2. **取消检查**：在长时间运行的 task 或循环中定期检查取消信号。这使 task 能够及时响应取消，避免不必要的处理。

3. **取消传播**：如果 task 调用了其他函数或库，请考虑将取消信号传播给这些依赖。这可以确保取消在整个 task 中被一致地处理。

4. **错误处理**：妥善处理取消错误。区分取消错误与其他类型的错误，以提供有意义的错误信息并采取适当的措施。

## 其他功能

除了这里列出的取消方式之外，Hatchet 还支持[批量取消](<05. bulk-retries-and-cancellations.md>)，允许你通过 ID 或一组过滤器批量取消大量 task，这通常是同时取消多个任务最简单的方式。

## 结语

取消是 Hatchet 中的一项强大功能，让你能够在需要时优雅地停止 task 执行。请记住在实现取消时遵循最佳实践，例如优雅终止、定期取消检查、处理异步操作、正确的错误处理以及取消传播。

通过在 Hatchet task 和 workflow 中引入取消机制，你可以构建更具弹性和响应能力的系统，以适应不断变化的环境和用户需求。
