# 暂停 Workflow

暂停 workflow 会阻止该 workflow 的新运行启动。当你需要临时停止某个 workflow，而又不想删除其触发器或取消已经在运行的工作时，可以使用此功能。

> **Info:** workflow 暂停与 worker 暂停不同。暂停 worker 是阻止该 worker 拾取新 task；
>   而暂停 workflow 是对所有 worker 上的某一个 workflow 生效。

## workflow 暂停期间会发生什么

- **进行中的运行继续执行。** 暂停不会取消或中断已经启动的 task。
- **新的运行不会启动。** 事件触发和手动触发仍会创建运行，但这些运行会保持在队列中，直到你取消暂停，或[队列 TTL](#queue-ttl) 到期。cron 和计划触发则可以选择完全跳过创建运行（见下文）。
- **其他 workflow 不受影响。** worker 会照常运行其他 workflow。

## Cron 与计划运行

暂停时，你可以选择 [cron](<../03. triggers（触发）/02. cron-runs.md>) 和[计划](<../03. triggers（触发）/01. scheduled-runs.md>)触发器在 workflow 暂停期间的行为：

行为, 效果

**QUEUE**, 触发器仍会创建运行。该运行保持在队列中，在你取消暂停后启动，除非队列 TTL 先到期。
**DROP**, 跳过该触发。workflow 暂停期间，该 cron tick 或计划不会创建任何运行。

cron 和计划行为可独立设置。事件触发和手动触发的运行在 workflow 暂停期间始终进入队列，不受这些设置控制。

## 队列 TTL

等待暂停中 workflow 的排队运行有 TTL。如果某个运行排队时间超过 TTL 仍未启动，Hatchet 会将其取消。仪表板中默认值为 `24h`。时长字符串使用与[超时](<02. timeouts.md>)相同的格式（例如 `30m` 或 `24h`）。

## 取消暂停

取消暂停会清除暂停设置，并重新排队仍在等待的运行。已因 TTL 到期而被取消的运行保持取消状态。

## 通过仪表板操作

1. 打开该 workflow。
2. 进入 **Settings** 标签页。
3. 在 **Workflow status** 下选择 **Paused**。

## 通过 Python SDK 操作

```python
from datetime import timedelta

my_workflow.pause(
    queue_ttl=timedelta(hours=24),
    paused_workflow_cron_run_queue_behavior="QUEUE",
    paused_workflow_scheduled_run_queue_behavior="QUEUE",
)

my_workflow.unpause()
```

异步版本为 `aio_pause` 和 `aio_unpause`。
