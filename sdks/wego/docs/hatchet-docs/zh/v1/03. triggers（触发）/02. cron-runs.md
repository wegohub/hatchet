# 使用 Cron 的周期性运行

[Cron](https://en.wikipedia.org/wiki/Cron) 是一种基于时间的作业调度器，允许你定义 task 在预定的调度计划上自动执行的时间。

cron 式 task 的一些典型使用场景包括：

1. 在特定时间运行每日报告。
2. 每周向用户发送关于其过去一周活动的摘要邮件。
3. 运行月度账单流程，为客户生成发票。

Hatchet 支持以几种不同的方式定义 cron 触发调度计划：

- [Task 定义](<02. cron-runs.md#defining-a-cron-in-your-task-definition>)：在 task 定义中定义 cron 表达式，按预定的调度计划触发 task。
- [以编程方式动态创建](<02. cron-runs.md#programmatically-creating-cron-triggers>)：使用 Hatchet SDK 动态设置 task 的 cron 调度计划。
- [Hatchet 控制台](<02. cron-runs.md#managing-cron-jobs-in-the-hatchet-dashboard>)：在 Hatchet 控制台中手动创建 cron 触发器。

> **Warning:** 表达式定义的是 Hatchet **入队** task 的时间，而不是 run 开始的时间。
>   并发限制、速率限制和重试策略等调度约束都可能影响 run 的开始时间。

### Cron 表达式语法

Hatchet 中的 cron 表达式遵循标准的 cron 语法。Hatchet 同时支持 5 字段和 6 字段表达式。cron 表达式由 5 到 6 个以空格分隔的字段组成。如果有 6 个字段，第一个字段是秒；如果有 5 个字段，第一个字段是分钟。

```
┌───────────── second (0 - 59) (optional)
│ ┌───────────── minute (0 - 59)
│ │ ┌───────────── hour (0 - 23)
│ │ │ ┌───────────── day of the month (1 - 31)
│ │ │ │ ┌───────────── month (1 - 12)
│ │ │ │ │ ┌───────────── day of the week (0 - 6) (Sunday to Saturday)
* * * * * *
```

每个字段可以包含一个具体的值、表示所有可能值的星号（`*`），或一个值范围。下面是一些 cron 表达式的示例：

- `0 0 * * *`：每天午夜运行
- `*/15 * * * *`：每 15 分钟运行
- `0 9 * * 1`：每周一上午 9 点运行
- `0 0 1 * *`：每月第一天午夜运行
- `30 * * * * *`：每分钟的第 30 秒运行（6 字段）

> **Info:** 请注意，Hatchet Cloud 按 Task run 计量计费，请合理使用秒级调度。
>   对定价有疑问？请[联系我们](https://cal.com/team/hatchet/talk-to-us)

## 在 Task 定义中定义 Cron

你可以在 task 定义中配置 cron 表达式，为 task 定义 cron 调度计划：

#### Python-Sync

```python
# Adding a cron trigger to a workflow is as simple
# as adding a `cron expression` to the `on_cron`
# prop of the workflow definition

cron_workflow = hatchet.workflow(name="CronWorkflow", on_crons=["* * * * *"])


@cron_workflow.task()
def step1(input: EmptyModel, ctx: Context) -> dict[str, str]:
    return {
        "time": "step1",
    }
```

#### Python-Async

```python
# Adding a cron trigger to a workflow is as simple
# as adding a `cron expression` to the `on_cron`
# prop of the workflow definition

cron_workflow = hatchet.workflow(name="CronWorkflow", on_crons=["* * * * *"])


@cron_workflow.task()
def step1(input: EmptyModel, ctx: Context) -> dict[str, str]:
    return {
        "time": "step1",
    }
```

#### Typescript

```typescript
export const onCron = hatchet.workflow({
  name: 'on-cron-workflow',
  on: {
    // 👀 add a cron expression to run the workflow every 15 minutes
    cron: '*/15 * * * *',
  },
});
```

#### Go

```go
dailyCleanup := client.NewStandaloneTask("cleanup-temp-files", func(ctx hatchet.Context, input CronInput) (CronOutput, error) {
	log.Printf("Running daily cleanup at %s", input.Timestamp)

	time.Sleep(2 * time.Second)

	return CronOutput{
		JobName:    "daily-cleanup",
		ExecutedAt: time.Now().Format(time.RFC3339),
		NextRun:    "Next run: tomorrow at 2 AM",
	}, nil
},
	hatchet.WithWorkflowCron("0 2 * * *"),
	hatchet.WithWorkflowCronInput(CronInput{
		Timestamp: time.Now().Format(time.RFC3339),
	}),
	hatchet.WithWorkflowDescription("Daily cleanup and maintenance tasks"),
)
```

#### Ruby

```ruby
CRON_WORKFLOW = HATCHET.workflow(
  name: "CronWorkflow",
  on_crons: ["*/5 * * * *"]
)

CRON_WORKFLOW.task(:cron_task) do |input, ctx|
  puts "Cron task executed at #{Time.now}"
  { "status" => "success" }
end
```

在上面的示例中，我们设置了 task 的 `on cron` 属性。该属性指定了决定 task 何时触发的 cron 表达式。


  注意：修改 task 定义中的 cron 时，它会覆盖之前 task 定义中已定义的 cron 调度
  计划，但通过 API 或控制台创建的 cron 仍然会被保留。


## 以编程方式创建 Cron 触发器

### 创建 Cron 触发器

你可以通过 API 以编程方式创建动态的 cron 触发器。如果你想在 task 定义时还无法确定 cron 触发器的情况下创建触发器，这会很有用。

下面是一个创建 cron 的示例，为特定客户每天中午触发一份报告：

#### Python-Sync

```python
cron_trigger = dynamic_cron_workflow.create_cron(
    cron_name="customer-a-daily-report",
    expression="0 12 * * *",
    input=DynamicCronInput(name="John Doe"),
    additional_metadata={
        "customer_id": "customer-a",
    },
)


id = cron_trigger.metadata.id  # the id of the cron trigger
```

#### Python-Async

```python
cron_trigger = await dynamic_cron_workflow.aio_create_cron(
    cron_name="customer-a-daily-report",
    expression="0 12 * * *",
    input=DynamicCronInput(name="John Doe"),
    additional_metadata={
        "customer_id": "customer-a",
    },
)

cron_trigger.metadata.id  # the id of the cron trigger
```

#### Typescript

```typescript
const cron = await simple.cron('simple-daily', '0 0 * * *', {
  Message: 'hello',
});

// it may be useful to save the cron id for later
const cronId = cron.metadata.id;
```

#### Go

```go
createdCron, err := client.Crons().Create(context.Background(), "cleanup-temp-files", features.CreateCronTrigger{
	Name:       "daily-cleanup",
	Expression: "0 0 * * *",
	Input: map[string]interface{}{
		"timestamp": time.Now().Format(time.RFC3339),
	},
	AdditionalMetadata: map[string]interface{}{
		"description": "Daily cleanup and maintenance tasks",
	},
})
if err != nil {
	return err
}
```

#### Ruby

```ruby
cron_trigger = dynamic_cron_workflow.create_cron(
  "customer-a-daily-report",
  "0 12 * * *",
  input: { "name" => "John Doe" }
)

id = cron_trigger.metadata.id
```

在这个示例中，你可以为不同的客户使用不同的表达式，或者根据其他业务逻辑动态设置表达式。

通过 API 创建 cron 时，你会收到一个 cron 触发器对象，其 metadata 属性包含该 cron 触发器的 id。这个 id 可用于在删除 cron 触发器时引用它，通常会被存储在数据库或其他持久层中。


  注意：创建 cron 触发器时，Cron Name 和 Expression 是必填字段，
  我们对这两者强制执行唯一约束。


### 删除 Cron 触发器

你可以通过向 delete 方法传入 cron 对象或 cron 触发器 id 来删除 cron 触发器。

#### Python-Sync

```python
hatchet.cron.delete(cron_id=cron_trigger.metadata.id)
```

#### Python-Async

```python
await hatchet.cron.aio_delete(cron_id=cron_trigger.metadata.id)
```

#### Typescript

```typescript
await hatchet.crons.delete(cronId);
```

#### Go

```go
err = client.Crons().Delete(context.Background(), createdCron.Metadata.Id)
if err != nil {
	return err
}
```

#### Ruby

```ruby
hatchet.cron.delete(cron_trigger.metadata.id)
```


  注意：删除 cron 触发器不会取消该 task 当前正在运行的任何实例。
  它只是让 cron 触发器不再触发该 task。


### 列出 Cron 触发器

检索匹配条件的所有 task cron 触发器列表。

#### Python-Sync

```python
cron_triggers = hatchet.cron.list()
```

#### Python-Async

```python
await hatchet.cron.aio_list()
```

#### Typescript

```typescript
const crons = await hatchet.crons.list({
  workflow: simple,
});
```

#### Go

```go
cronList, err := client.Crons().List(context.Background(), rest.CronWorkflowListParams{
	AdditionalMetadata: &[]string{"description:Daily cleanup and maintenance tasks"},
})
if err != nil {
	return err
}
```

#### Ruby

```ruby
cron_triggers = hatchet.cron.list
```

## 在 Hatchet 控制台中管理 Cron 触发器

在 Hatchet 控制台中，你可以查看和管理 task 的 cron 触发器。

在左侧边栏导航到"Triggers" > "Cron Jobs"，并点击右上角的"Create Cron Job"。

你可以指定运行参数，如 Input、Additional Metadata 和 Expression。

## Cron 使用注意事项

使用 cron 触发器时，需要注意以下几点：

1. **时区**：cron 调度计划使用 UTC。定义 cron 表达式时务必考虑时区。

2. **执行时间**：cron 触发的 task 的实际执行时间可能与计划时间略有偏差。Hatchet 会尽最大努力在尽可能接近计划时间的时刻将 task 入队，但由于系统负载等因素，可能会有轻微延迟。

3. **错过的调度**：如果错过了计划的 task（例如由于系统停机），Hatchet **不会**自动运行错过的实例，而是会等待下一个计划时间再触发 task。

4. **重叠调度**：如果下一个计划时间到达时 task 仍在运行，Hatchet 会启动该 task 的新实例，或遵循[并发](<../05. flow-control（流控）/01. concurrency.md>)策略。
