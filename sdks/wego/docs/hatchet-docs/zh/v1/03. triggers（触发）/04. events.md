# 通过 Event 触发运行

事件触发（run-on-event）允许你在特定 event 发生时触发一个或多个 task。当你需要针对一个结果并不重要的临时性 event 执行 task 时，这非常有用。事件触发 task run 的几个常见使用场景：

1. 在收到临时性 event 时运行 task，例如 webhook 或来自队列的消息。
2. 希望响应单个 event 运行多个相互独立的 task。例如，你想运行一个 `send_welcome_email` task，同时还想运行 `grant_new_user_credits` task 和 `reward_referral` task，都由注册事件触发。这种情况下，你可以为这三个 task 都声明 `user:signup` 的 event 触发器，让它们在该 event 发生时全部启动。


> **Info:** 事件触发器在 event 到达时评估要运行的 task。如果 event 在 task 注册
>   之前就已到达，该 task 将不会运行。

## 声明事件触发器

要让 task 在某个 event 上运行，你需要声明将触发该 task 的 event。这通过在 task 声明中声明 `on_events` 属性来完成。

#### Python

```python
EVENT_KEY = "user:create"
SECONDARY_KEY = "foobarbaz"
WILDCARD_KEY = "subscription:*"


class EventWorkflowInput(BaseModel):
    should_skip: bool


event_workflow = hatchet.workflow(
    name="EventWorkflow",
    on_events=[EVENT_KEY, SECONDARY_KEY, WILDCARD_KEY],
    input_validator=EventWorkflowInput,
)
```

#### Typescript

```typescript
export const lower = hatchet.workflow({
  name: 'lower',
  // 👀 Declare the event that will trigger the workflow
  onEvents: ['simple-event:create'],
});
```

#### Go

```go
const SimpleEvent = "simple-event:create"

func Lower(client *hatchet.Client) *hatchet.StandaloneTask {
	return client.NewStandaloneTask(
		"lower", func(ctx hatchet.Context, input EventInput) (*LowerTaskOutput, error) {
			return &LowerTaskOutput{
				TransformedMessage: strings.ToLower(input.Message),
			}, nil
		},
		hatchet.WithWorkflowEvents(SimpleEvent),
	)
}
```

#### Ruby

```ruby
EVENT_KEY = "user:create"
SECONDARY_KEY = "foobarbaz"
WILDCARD_KEY = "subscription:*"

EVENT_WORKFLOW = HATCHET.workflow(
  name: "EventWorkflow",
  on_events: [EVENT_KEY, SECONDARY_KEY, WILDCARD_KEY]
)
```

> **Info:** 注意：同一个 event 可以触发多个 task。

> **Info:** 自 engine 版本 0.65.0 起，Hatchet 支持使用 `*` 通配符模式的事件
>   触发器。例如，你可以注册 `subscription:*` 作为 event key，它会匹配
>   `subscription:create`、`subscription:renew`、`subscription:cancel` 等
>   传入 event。

## 向 Hatchet 推送 Event

你可以通过调用 Hatchet event 客户端的 `push` 方法并传入 event 名称和 payload 来向 Hatchet 推送 event。所有注册了与该 event key 匹配的事件触发器的 task 都会运行。

#### Python

```python
hatchet.event.push("user:create", {"should_skip": False})
```

#### Typescript

```typescript
const res = await hatchet.events.push('simple-event:create', {
  Message: 'hello',
  ShouldSkip: false,
});
```

#### Go

```go
err := client.Events().Push(
	context.Background(),
	"simple-event:create",
	EventInput{
		Message: "Hello, World!",
	},
)
if err != nil {
	return err
}
```

#### Ruby

```ruby
HATCHET.event.push("user:create", { "should_skip" => false })
```

> **Info:** 事件触发器在 event 到达时评估要运行的 task。如果 event 在 task 注册
>   之前就已到达，该 task 将不会运行。

## Event 过滤器

Hatchet 中的 event 可以被_过滤_，这允许你向 Hatchet 推送 event，但仅在特定情况下才从中触发 task run。**如果你在 workflow 上启用了过滤器，那么对于任何 scope 匹配的传入 event，workflow 会针对每个匹配的过滤器各触发一次**（参见下文的[理解 scope](#understanding-scopes)）。

### 理解 scope

每个过滤器都有一个必填的 `scope`，它是一个任意字符串，充当过滤器的分组键。它的作用是缩小 event 所要评估的候选过滤器集合：当你推送带 `scope` 的 event 时，Hatchet 只考虑 scope 与 event 的 scope 完全匹配的过滤器，然后针对其中每个表达式求值为 `true` 的过滤器各触发一次 workflow。

具体来说，对于一个带事件触发器的 workflow：

- 如果 workflow **没有过滤器**，匹配的 event 会照常触发它，scope 没有任何影响。
- 如果 workflow **有一个或多个过滤器**，传入 event 只有在其 scope 与至少一个过滤器的 scope 完全匹配，_并且_该过滤器的表达式对该 event 求值为 `true` 时才会触发 workflow。不带 scope 推送的 event，或 scope 与 workflow 任何过滤器都不匹配的 event，完全不会触发该 workflow。

Scope 在需要按实体过滤时最有用，例如在多租户应用中，每个客户都应有自己的过滤规则。例如，你可以为每个客户创建一个 scope 为 `customer:1234` 的过滤器，各自拥有独立的表达式和 payload。当该客户的 event 到达时，你带上 `scope="customer:1234"` 推送它，它只会针对该客户的过滤器进行评估——而不会针对该 workflow 注册的每一个过滤器。

### 基本用法

在 Hatchet 中有两种创建过滤器的方式。

### workflow 上的默认过滤器

创建过滤器最简单的方式是在创建 workflow 时以声明式方式注册。例如：

#### Python

```python
event_workflow_with_filter = hatchet.workflow(
    name="EventWorkflow",
    on_events=[EVENT_KEY, SECONDARY_KEY, WILDCARD_KEY],
    input_validator=EventWorkflowInput,
    default_filters=[
        DefaultFilter(
            expression="true",
            scope="example-scope",
            payload={
                "main_character": "Anna",
                "supporting_character": "Stiva",
                "location": "Moscow",
            },
        )
    ],
)
```

#### Typescript

```typescript
export const lowerWithFilter = hatchet.workflow({
  name: 'lower',
  // 👀 Declare the event that will trigger the workflow
  onEvents: ['simple-event:create'],
  defaultFilters: [
    {
      expression: 'true',
      scope: 'example-scope',
      payload: {
        mainCharacter: 'Anna',
        supportingCharacter: 'Stiva',
        location: 'Moscow',
      },
    },
  ],
});
```

#### Go

```go
func LowerWithFilter(client *hatchet.Client) *hatchet.StandaloneTask {
	return client.NewStandaloneTask(
		"lower", accessFilterPayload,
		hatchet.WithWorkflowEvents(SimpleEvent),
		hatchet.WithDefaultFilters(hatchet.DefaultFilter{
			Expression: "true",
			Scope:      "example-scope",
			Payload: map[string]interface{}{
				"main_character":       "Anna",
				"supporting_character": "Stiva",
				"location":             "Moscow"},
		}),
	)
}
```

#### Ruby

```ruby
EVENT_WORKFLOW_WITH_FILTER = HATCHET.workflow(
  name: "EventWorkflow",
  on_events: [EVENT_KEY, SECONDARY_KEY, WILDCARD_KEY],
  default_filters: [
    Hatchet::DefaultFilter.new(
      expression: "true",
      scope: "example-scope",
      payload: {
        "main_character" => "Anna",
        "supporting_character" => "Stiva",
        "location" => "Moscow"
      }
    )
  ]
)

EVENT_WORKFLOW.task(:task) do |input, ctx|
  puts "event received"
  ctx.filter_payload
end
```

在以上每种情况中，我们都在 workflow 上注册了一个过滤器。注意这些"声明式"过滤器在每次更新 workflow 时都会被覆盖，因此与之关联的 id 不会随时间保持稳定。这使你可以就地修改过滤器或移除过滤器，而无需通过 API 手动删除。

### Filters feature client

你还可以使用各 SDK 中的 `filters` 客户端创建 event 过滤器：

#### Python

```python
hatchet.filters.create(
    workflow_id=event_workflow.id,
    expression="input.should_skip == false",
    # the scope groups filters: only events pushed with a matching
    # scope are evaluated against this filter. in a real app, this is
    # often an id, e.g. a customer, user, or organization id
    scope="foobarbaz",
    payload={
        "main_character": "Anna",
        "supporting_character": "Stiva",
        "location": "Moscow",
    },
)
```

#### Typescript

```typescript
hatchet.filters.create({
  workflowId: lower.id,
  expression: 'input.ShouldSkip == false',
  scope: 'foobarbaz',
  payload: {
    main_character: 'Anna',
    supporting_character: 'Stiva',
    location: 'Moscow',
  },
});
```

#### Go

```go
_, err = client.Filters().Create(
	context.Background(),
	rest.V1CreateFilterRequest{
		WorkflowId: uuid.MustParse("bb866b59-5a86-451b-8023-10d451db11d3"),
		Expression: "true",
		Scope:      "example-scope",
	},
)
if err != nil {
	return err
}
```

#### Ruby

```ruby
HATCHET_CLIENT.filters.create(
  workflow_id: EVENT_WORKFLOW.id,
  expression: "input.should_skip == false",
  scope: "foobarbaz",
  payload: {
    "main_character" => "Anna",
    "supporting_character" => "Stiva",
    "location" => "Moscow"
  }
)
```

> **Warning:** 注意，过滤器的 [`scope`](#understanding-scopes) 参数在**创建过滤器
>   和推送 event 时**都必须提供。如果创建过滤器时的 scope 与推送 event 时的
>   scope 不匹配，该过滤器将不会生效。

然后，推送一个由过滤器决定是否运行的 event。例如，下面这个 run 会被跳过，因为 payload 与表达式不匹配：

#### Python

```python
hatchet.event.push(
    event_key=EVENT_KEY,
    payload={
        "should_skip": True,
    },
    scope="foobarbaz",
)
```

#### Typescript

```typescript
hatchet.events.push(
  SIMPLE_EVENT,
  {
    Message: 'hello',
    ShouldSkip: true,
  },
  {
    scope: 'foobarbaz',
  }
);
```

#### Go

```go
skipPayload := map[string]interface{}{
	"shouldSkip": true,
}
skipScope := "foobarbaz"
err = client.Events().Push(
	context.Background(),
	"simple-event:create",
	skipPayload,
	hatchet.WithFilterScope(&skipScope),
)
if err != nil {
	return err
}
```

#### Ruby

```ruby
HATCHET_CLIENT.event.push(
  EVENT_KEY,
  { "should_skip" => true },
  scope: "foobarbaz"
)
```

而下面这个会被触发，因为 payload 与表达式_匹配_：

#### Python

```python
hatchet.event.push(
    event_key=EVENT_KEY,
    payload={
        "should_skip": False,
    },
    scope="foobarbaz",
)
```

#### Typescript

```typescript
hatchet.events.push(
  SIMPLE_EVENT,
  {
    Message: 'hello',
    ShouldSkip: false,
  },
  {
    scope: 'foobarbaz',
  }
);
```

#### Go

```go
triggerPayload := map[string]interface{}{
	"shouldSkip": false,
}
triggerScope := "foobarbaz"
err = client.Events().Push(
	context.Background(),
	"simple-event:create",
	triggerPayload,
	hatchet.WithFilterScope(&triggerScope),
)
if err != nil {
	return err
}
```

#### Ruby

```ruby
HATCHET_CLIENT.event.push(
  EVENT_KEY,
  { "should_skip" => false },
  scope: "foobarbaz"
)
```

> **Info:** 在 Hatchet 中，过滤器是"正向"的，也就是说我们通过查找与过滤器_匹配_的
>   内容来决定触发哪些 task。

### 访问过滤器 payload

你可以在由 event 触发的 task 中使用 `Context` 访问过滤器 payload：

#### Python

```python
@event_workflow_with_filter.task()
def filtered_task(input: EventWorkflowInput, ctx: Context) -> None:
    print(ctx.filter_payload)
```

#### Typescript

```typescript
lowerWithFilter.task({
  name: 'lowerWithFilter',
  fn: (input, ctx) => {
    ctx.logger.info('filterPayload', { filterPayload: ctx.filterPayload() });
  },
});
```

#### Go

```go
func accessFilterPayload(ctx hatchet.Context, input EventInput) (*LowerTaskOutput, error) {
	fmt.Println(ctx.FilterPayload())
	return &LowerTaskOutput{
		TransformedMessage: strings.ToLower(input.Message),
	}, nil
}
```

#### Ruby

```ruby
EVENT_WORKFLOW_WITH_FILTER.task(:filtered_task) do |input, ctx|
  puts ctx.filter_payload.inspect
end
```

### 高级用法

除了在表达式中引用 `input`（对应_event_的 payload）之外，你还可以引用以下字段：

1. `payload` 对应_过滤器_的 payload（创建过滤器时请求中携带的部分）。
2. `additional_metadata` 允许基于随 event 发送的 `additional_metadata` 进行过滤。
3. `event_key` 允许基于 event 的 key（如 `user:created`）进行过滤。

过滤表达式中可用的完整变量和函数集合，请参阅 [CEL 表达式](<../05. flow-control（流控）/06. cel-expressions.md#event-filter-expressions>)。
