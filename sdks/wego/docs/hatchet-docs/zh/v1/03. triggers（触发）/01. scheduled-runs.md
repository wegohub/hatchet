# 计划运行（Scheduled Runs）

计划运行允许你在未来的特定时间触发 task。一些典型的使用场景包括：

- 在用户执行某项操作后的特定时间发送提醒邮件。
- 在应用程序确定的预定时间运行一次性维护任务。例如，每当某个 task 满足特定条件时，你可能想在维护窗口期间运行数据库 vacuum。
- 让客户决定何时让你的应用程序执行特定任务。例如，如果你的应用是一个简单的闹钟应用，在客户指定的时间向其发送通知，你可以为每个客户设置的闹钟创建一个计划运行。

Hatchet 支持以几种不同的方式定义计划来运行计划任务：

- [编程方式](#编程方式创建计划运行)：使用 Hatchet SDK 动态设置 task 的计划。
- [Hatchet 仪表板](#在-hatchet-仪表板中管理计划运行)：在 Hatchet 仪表板中手动创建计划运行。

> **Warning:** 计划时间是 Hatchet **入队**该 task 的时间，而不是运行开始的时间。
>   并发限制、速率限制和重试策略等调度约束可能会影响运行开始时间。

## 编程方式创建计划运行

### 创建计划运行

你可以通过 API 以编程方式创建动态计划运行，使 task 在未来的特定时间运行。

下面是一个创建计划运行的示例，在明天中午触发一个 task：

#### Python

```python
from datetime import datetime

from examples.simple.worker import simple

schedule = simple.schedule(datetime(2025, 3, 14, 15, 9, 26))

## 👀 do something with the id
print(schedule.scheduled_workflows[0].id)
```

#### Typescript

```typescript
const runAt = new Date(new Date().setHours(12, 0, 0, 0) + 24 * 60 * 60 * 1000);

const scheduled = await simple.schedule(runAt, {
  Message: 'hello',
});

// 👀 Get the scheduled run ID of the workflow
// it may be helpful to store the scheduled run ID of the workflow
// in a database or other persistent storage for later use
const scheduledRunId = scheduled.metadata.id;
console.log(scheduledRunId);
```

#### Go

```go
scheduledRun, err := client.Schedules().Create(
	context.Background(),
	"scheduled",
	features.CreateScheduledRunTrigger{
		TriggerAt: time.Now().Add(1 * time.Minute),
		Input:     map[string]interface{}{"message": "Hello, World!"},
	},
)
if err != nil {
	log.Fatalf("failed to create scheduled run: %v", err)
}
```

#### Ruby

```ruby
schedule = SIMPLE.schedule(Time.now + 86_400, input: { "message" => "Hello, World!" })

## do something with the id
puts schedule.scheduled_workflows.first.id
```

在这个示例中，你可以为不同客户设置不同的计划时间，或根据其他业务逻辑动态设置计划时间。

通过 API 创建计划运行时，你会收到一个计划运行对象，其 metadata 属性包含该计划运行的 id。这个 id 可用于在删除计划运行时引用它，通常会被存储到数据库或其他持久层中。

> **Info:** 注意：请留意计划运行的时区。计划运行**始终**以 UTC 存储和返回。

### 删除计划运行

你可以在 scheduled 客户端上调用 `delete` 方法来删除计划运行。

#### Python

```python
hatchet.scheduled.delete(scheduled_id=scheduled_run.metadata.id)
```

#### Typescript

```typescript
await hatchet.scheduled.delete(scheduled);
```

#### Go

```go
err = client.Schedules().Delete(
	context.Background(),
	scheduledRun.Metadata.Id,
)
if err != nil {
	log.Fatalf("failed to delete scheduled run: %v", err)
}
```

#### Ruby

```ruby
hatchet.scheduled.delete(scheduled_run.metadata.id)
```

### 列出计划运行

你可以在 scheduled 客户端上调用 `list` 方法列出某个 task 的所有计划运行。

#### Python

```python
scheduled_runs = hatchet.scheduled.list()
```

#### Typescript

```typescript
const scheduledRuns = await hatchet.scheduled.list({
  workflow: simple,
});
console.log(scheduledRuns);
```

#### Go

```go
scheduledRuns, err := client.Schedules().List(
	context.Background(),
	rest.WorkflowScheduledListParams{},
)
if err != nil {
	log.Fatalf("failed to list scheduled runs: %v", err)
}
```

#### Ruby

```ruby
scheduled_runs = hatchet.scheduled.list
```

### 重新调度计划运行

如果需要更改现有计划运行的触发时间，可以通过更新其 `triggerAt` 来重新调度。

#### Python

```python
hatchet.scheduled.update(
    scheduled_id=scheduled_run.metadata.id,
    trigger_at=datetime.now(tz=timezone.utc) + timedelta(hours=1),
)
```

#### Typescript

```typescript
await hatchet.scheduled.update(scheduledRunId, {
  triggerAt: new Date(Date.now() + 60 * 60 * 1000),
});
```

#### Ruby

```ruby
hatchet.scheduled.update(
  scheduled_run.metadata.id,
  trigger_at: Time.now + 3600
)
```

> **Warning:** 只能重新调度通过 API 创建的计划运行（不能是通过代码定义的调度创建的运行），
>   而且如果运行已经触发，Hatchet 可能会拒绝重新调度。

### 批量操作（删除 / 重新调度）

Hatchet 支持计划运行的批量操作。你可以批量删除计划运行，也可以通过提供更新列表来批量重新调度计划运行。

#### Python

```python
hatchet.scheduled.bulk_delete(scheduled_ids=[id])

hatchet.scheduled.bulk_delete(
    workflow_id="workflow_id",
    statuses=[ScheduledRunStatus.SCHEDULED],
    additional_metadata={"customer_id": "customer-a"},
)
```
```python
hatchet.scheduled.bulk_update(
    [
        (id, datetime.now(tz=timezone.utc) + timedelta(hours=2)),
    ]
)
```

#### Typescript

```typescript
await hatchet.scheduled.bulkDelete({
  scheduledRuns: [scheduledRunId],
});
```
```typescript
await hatchet.scheduled.bulkUpdate([
  { scheduledRun: scheduledRunId, triggerAt: new Date(Date.now() + 2 * 60 * 60 * 1000) },
]);
```

#### Ruby

```ruby
hatchet.scheduled.bulk_delete(scheduled_ids: [id])
```
```ruby
hatchet.scheduled.bulk_update(
  [[id, Time.now + 7200]]
)
```

## 在 Hatchet 仪表板中管理计划运行

在 Hatchet 仪表板中，你可以查看和管理 task 的计划运行。

在左侧边栏导航到 "Triggers" > "Scheduled Runs"，然后点击右上角的 "Create Scheduled Run"。

你可以指定运行参数，例如输入（Input）、附加元数据（Additional Metadata）和计划时间（Scheduled Time）。

![Create Scheduled Run](/schedule-dash.gif)

你还可以管理现有的计划运行：

- **单个运行操作**：使用每行的操作菜单对单个计划运行进行**重新调度**（Reschedule）或**删除**（Delete）。
- **批量操作**：使用 **Actions** 菜单对以下范围批量**删除**或**重新调度**：
  - 选中的行，或
  - 与当前筛选条件匹配的所有行（如果未设置筛选条件，则包括"所有"行）。

> **Info:** 在仪表板中，对于通过代码定义的调度创建的运行，重新调度/删除操作可能被禁用；
>   对于已经触发的运行，重新调度可能被禁用。

## 计划运行的注意事项

使用计划运行时，需要注意以下几点：

1. **时区**：计划运行以 UTC 存储和返回。定义计划时间时请务必考虑时区。

2. **执行时间**：计划运行的实际执行时间可能与计划时间略有偏差。Hatchet 会尽最大努力在尽可能接近计划时间时将 task 入队，但由于系统负载等因素，可能会有轻微延迟。

3. **错过的计划**：如果计划 task 被错过（例如由于系统停机），Hatchet 不会在服务恢复后自动运行错过的实例。

4. **计划重叠**：如果在上一个计划运行仍在执行时，第二个计划运行已到启动时间，Hatchet 将启动该 task 的新实例，或遵循[并发](<../05. flow-control（流控）/01. concurrency.md>)策略。
