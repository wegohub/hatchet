# 用户角色（User Roles）

租户中的每个用户都有一个角色，控制其在仪表板和 REST API 中可以执行的操作。角色是分层的：每个角色都可以执行其下层角色能做的一切。

## 租户角色

| 角色 | 说明 |
| --- | --- |
| **OWNER** | 对租户拥有完全控制权，包括向其他成员分配 OWNER 角色。只有 owner 才能更改其他 owner 的角色或移除成员。 |
| **ADMIN** | 可以做 MEMBER 能做的一切，此外还可以管理租户成员、邀请和 API token。 |
| **MEMBER** | 可以做 VIEWER 能做的一切，此外还可以执行变更操作：触发、重放和取消运行，管理 workflow、cron、计划、webhook 和告警。 |
| **VIEWER** | 只读访问。可以查看运行、workflow、worker、事件、日志和指标，但不能触发或修改任何内容。 |

角色在成员被邀请时指定，之后可以在 **Settings > Members** 中更改。成员不能更改自己的角色。

## 组织角色

组织（Hatchet Cloud）有两种角色：

角色, 说明

**OWNER**, 管理组织：成员、邀请、租户、SSO 和[用户组](<03. user-groups.md>)。会被作为租户 OWNER 加入每个租户。
**MEMBER**, 通过显式授权或[用户组](<03. user-groups.md>)获得租户访问权限，并拥有各授权所指定的租户角色。

## 载荷可见性

具有 MEMBER 或 VIEWER 租户角色的成员还可以被限制查看载荷。当某个成员的 **Can view payloads** 开关被关闭后，他们仍然可以看到运行、状态和错误，但 task 的输入与输出、事件载荷和日志载荷在仪表板和 REST API 中都会被隐藏。

有几条规则：

- **OWNER 和 ADMIN 始终可以看到载荷**，不受该开关影响。
- **API token 不受限制。** worker 运行 task 需要载荷，因此通过 API token 进行的编程访问始终包含载荷。
- 该开关在所有可设置的地方**默认为 true**。

该开关可以在以下位置设置：

- 租户成员级别，在 **Settings > Members** 中。
- 租户或组织邀请级别，使限制在邀请被接受时立即生效。
- [用户组](<03. user-groups.md>)级别，应用于该组同步的每个成员。如果一个用户匹配多个组，则以限制最严格的组为准。

成员角色和载荷可见性的变更会被记录到[审计日志](<../11. evaluating-hatchet（评估）/04. audit-logs.md>)中。
