# 单点登录（Single Sign-On）

> **Info:** 单点登录仅在我们的 Cloud Scale 计划中提供。详情请参阅
>   [定价](https://hatchet.run/pricing)。

除了 Google 和 Github OAuth 之外，我们还为希望使用自己身份提供程序（IdP）的企业提供自定义 SSO 方案。

## 支持的 IdP

- Okta
- Microsoft Entra
- OneLogin
- JumpCloud
- Google
- 通用 OIDC 提供程序

## 设置 SSO

### IdP 配置

第一步是设置 SSO 配置。方法是：在 Settings > Organization > SSO 中点击 "Set up SSO"，并填写提供的字段。各平台的字段有所不同，但所有平台都需要你复制 "Redirect / Callback" URL，并将其设置为你 IdP 中的回调 URL。

### 域名验证

要允许用户通过 SSO 登录，你还必须将组织的邮箱域名关联到你的 SSO 配置。这通过 DNS 验证完成 —— 你需要在域名的 DNS TXT 记录中添加 `hatchet-sso-verify` 和一个验证 token 来关联域名。域名验证通过后，所有使用该邮箱域名通过 SSO 登录的用户都将使用你的 SSO 配置进行身份认证。由于 DNS 记录需要传播，更新 TXT 记录与验证完成之间可能会有短暂延迟。以下是一条示例验证记录：

类型, 域名, 记录

TXT, hatchet.run, "hatchet-sso-verify=b2b92da1-4314-11f1-a43b-5eff43bccba3"

### 强制 SSO

启用 Force SSO 开关后，所有用户都将被强制通过 SSO 登录，其他所有登录方式将被禁用。

> **Warning:** 只有在确认 SSO 正常工作之后再启用强制 SSO，否则你可能会被锁定在组织之外。
>   如果遇到这种情况，请<a href="mailto:support@hatchet.run">联系支持团队</a>。
