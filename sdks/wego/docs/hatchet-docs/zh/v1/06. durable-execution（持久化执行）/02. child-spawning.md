# 子任务派生（Child Spawning）

一个 task 可以在运行时派生（spawn）子 task——包括其他持久化 task 或完整的 DAG workflow。子 task 在任意可用的 worker 上独立运行，父 task 可以在继续之前等待它们的结果。你可以从任何 task（无论是否持久化）派生子 task。

> **Info:** 虽然子任务派生并非持久化 task 独有的能力，但当派生子任务是某个
>   task 的主要职责（或主要职责之一）时，我们通常建议使用持久化 task。
>   例如，一个 agent 的主要职责可能是派生大量子任务（即工具调用），
>   这种情况下持久化 task 是很好的选择。

### 派生一个子 task

派生子 task 的方式与正常运行 task 类似，但实现细节因语言而略有差异。任何 task 都可以派生子 task。

#### Python

```python
from examples.fanout.worker import ChildInput, child_wf

# 👀 example: run this inside of a parent task to spawn a child
child_wf.run(
    ChildInput(a="b"),
)
```

#### Typescript

```typescript
export const parentSingleChild = hatchet.task({
  name: 'parent-single-child',
  fn: async () => {
    const childRes = await child.run({ N: 1 });

    return {
      Result: childRes.Value,
    };
  },
});
```

#### Go

```go
// Inside a parent task
childResult, err := childWorkflow.Run(hCtx, ChildInput{
	Value: 1,
})
if err != nil {
	return err
}
```

#### Ruby

```ruby
FANOUT_CHILD_WF.run({ "a" => "b" })
```

### 一次派生多个子 task

你也可以批量派生子 task，与批量运行其他任何 task 的方式完全相同。

#### Python

```python
async def run_child_workflows(n: int) -> list[dict[str, Any]]:
    return await child_wf.aio_run_many(
        [
            child_wf.create_bulk_run_item(
                input=ChildInput(a=str(i)),
            )
            for i in range(n)
        ]
    )
```

#### Typescript

```typescript
type ParentInput = {
  N: number;
};

export const parent = hatchet.task({
  name: 'parent',
  fn: async (input: ParentInput, ctx) => {
    const n = input.N;
    const promises = [];

    for (let i = 0; i < n; i++) {
      promises.push(child.run({ N: i }));
    }

    const childRes = await Promise.all(promises);
    const sum = childRes.reduce((acc, curr) => acc + curr.Value, 0);

    return {
      Result: sum,
    };
  },
});
```

#### Go

```go
// Run multiple child tasks in parallel using goroutines
var wg sync.WaitGroup
var mu sync.Mutex
results := make([]*ChildOutput, 0, n)

wg.Add(n)
for i := 0; i < n; i++ {
	go func(index int) {
		defer wg.Done()
		result, err := childWorkflow.Run(hCtx, ChildInput{Value: index})
		if err != nil {
			return
		}

		var childOutput ChildOutput
		err = result.Into(&childOutput)
		if err != nil {
			return
		}

		mu.Lock()
		results = append(results, &childOutput)
		mu.Unlock()
	}(i)
}
wg.Wait()
```

#### Ruby

```ruby
def run_child_workflows(n)
  FANOUT_CHILD_WF.run_many(
    n.times.map do |i|
      FANOUT_CHILD_WF.create_bulk_run_item(
        input: { "a" => i.to_s }
      )
    end
  )
end
```

### 可以派生什么

一个持久化 task 可以派生任何可运行对象：

| 子任务类型 | 示例 |
| --- | --- |
| **普通 task** | 派生一个无状态的 task，用于快速计算或 API 调用。 |
| **持久化 task** | 派生另一个持久化 task，它拥有自己的检查点、sleep 和 event 等待。 |
| **DAG workflow** | 派生一个完整的多 task workflow 并等待其最终输出。 |

### 错误处理

#### Python

```python
try:
    child_wf.run(
        ChildInput(a="b"),
    )
except Exception as e:
    print(f"Child workflow failed: {e}")
```

#### Typescript

```typescript
export const withErrorHandling = hatchet.task({
  name: 'parent-error-handling',
  fn: async () => {
    try {
      const childRes = await child.run({ N: 1 });

      return {
        Result: childRes.Value,
      };
    } catch (error) {
      // decide how to proceed here
      return {
        Result: -1,
      };
    }
  },
});
```

#### Go

```go
result, err := childWorkflow.Run(hCtx, ChildInput{Value: 1})
if err != nil {
	// Handle error from child workflow
	fmt.Printf("Child workflow failed: %v\n", err)
	// Decide how to proceed - retry, skip, or fail the parent
}
```

#### Ruby

```ruby
begin
  FANOUT_CHILD_WF.run({ "a" => "b" })
rescue StandardError => e
  puts "Child workflow failed: #{e.message}"
end
```

## 子任务派生的使用方式

### 扇出（Fan-out）：并行派生大量子任务

处理一个长度只有运行时才知道的列表。为每一项派生一个子 task，收集所有结果后继续。文档处理和批处理是典型示例：当一批文件到达时，父 task 为每份文档扇出一个子 task；每个子 task 在你的 worker 集群中并行地解析、提取和校验各自的文档。

[并发控制](<../05. flow-control（流控）/01. concurrency.md>)决定同时运行多少个子 task。Hatchet 会把子 task 分发到可用的 worker 上，因此增加 worker 就能提升吞吐量而无需修改代码。对于有速率限制的外部服务（OCR、LLM API），可以配合[速率限制](<../05. flow-control（流控）/02. rate-limits.md>)对所有 worker 上的子 task 执行进行限流。

### Agent 推理循环

agent 循环的运行方式是：由一个持久化 task 用更新后的输入派生自己的新子 run，直到满足终止条件。每次迭代都是一个独立的子 task，因此你可以在控制台中获得完整的可观测性。AI agent 在思考下一步做什么时就会用到这一点：派生一个子任务（或子 workflow），检查结果，然后决定继续、分支还是停止。

### 派生工作树

一个持久化 task 可以派生子持久化 task，而后者又可以派生自己的子 task。这样就形成了一棵完全由运行时逻辑驱动的工作树——非常适合爬虫、递归搜索和树形计算等场景。
