# 在 Hatchet 中对 step 运行进行速率限制

Hatchet 允许你对 task 运行实施速率限制（rate limit），从而控制服务运行消耗资源的速率，例如外部 API 调用、数据库查询或其他服务。通过定义速率限制，你可以防止 task 运行在每个时间窗口（例如每秒、每分钟或每小时）内超过一定的请求次数，确保资源被高效利用，并避免外部服务过载。

活跃速率限制的状态可以在仪表板的 `Rate Limit` 资源标签页中查看。

## 动态与静态速率限制

Hatchet 提供两种对 task 运行进行速率限制的模式：

1. [动态速率限制](#动态速率限制)：通过 `input` 或 `additional_metadata` 键在运行时 upsert 限制，适用于按用户限制等复杂场景。
2. [静态速率限制](#静态速率限制)：适用于运行前已知的资源（例如外部 API）的简单限速。

## 动态速率限制

动态速率限制非常适合需要按只在运行时才知道的资源进行分区的复杂限速场景。

这种模式特别适用于：

1. 对单个用户或租户进行限速
2. 根据订阅等级或用户角色实现可变的速率限制
3. 根据实时系统负载或其他因素动态调整限制

### 工作原理

1. 在 key 上使用 [CEL（Common Expression Language）表达式](<06. cel-expressions.md>)定义动态速率限制键，引用 `input` 或 `additional_metadata`。
2. 在运行时，通过 workflow 触发或事件的 `input` 或 `additional_metadata` 提供该键。
3. Hatchet 会根据提供的键创建或更新速率限制，并对该 step 运行实施限制。

> **Info:** 注意：动态键是共享资源，这意味着在多个 step 上渲染出相同 CEL 表达式时，
>   会被视为一个全局速率限制。

### 声明和消费动态速率限制

#### Ruby

> 注意：`dynamic_key` 必须是 CEL 表达式。`units` 和 `limits` 可以是整数，也可以是 CEL 表达式。

我们可以在 task 定义中添加 `rate_limits` 配置，从而为一个 task 添加一个或多个速率限制。

```python
@rate_limit_workflow.task(
    rate_limits=[
        RateLimit(
            dynamic_key="input.user_id",
            units=1,
            limit=10,
            duration=RateLimitDuration.MINUTE,
        )
    ]
)
def step_2(input: RateLimitInput, ctx: Context) -> None:
    print("executed step_2")
```

#### Tab 2

> 注意：`dynamicKey` 必须是 CEL 表达式。`units` 和 `limit` 可以是整数，也可以是 CEL 表达式。

我们可以在 task 定义中添加 `rate_limits` 配置，从而为一个 task 添加一个或多个速率限制。

```typescript
const task2 = hatchet.task({
  name: 'task2',
  fn: (input: { userId: string }, ctx) => {
    ctx.logger.info(`executed task2 for user: ${input.userId}`);
  },
  rateLimits: [
    {
      dynamicKey: 'input.userId',
      units: 1,
      limit: 10,
      duration: RateLimitDuration.MINUTE,
    },
  ],
});
```

#### Tab 3

> 注意：Go 要求同时设置 key 和 KeyExpr，且 LimitValueExpr 必须是 CEL。

```go
userUnits := 1
userLimit := "10"
duration := hatchet.Minute
dynamicTask := client.NewStandaloneTask("task2",
	func(ctx hatchet.Context, input APIRequest) (string, error) {
		log.Printf("executed task2 for user: %s", input.UserID)

		return "completed", nil
	},
	hatchet.WithRateLimits(&hatchet.RateLimit{
		Key:            "input.userId",
		Units:          &userUnits,
		LimitValueExpr: &userLimit,
		Duration:       &duration,
	}),
)
```

#### Tab 4

```ruby
RATE_LIMIT_WORKFLOW.task(
  :step_2,
  rate_limits: [
    Hatchet::RateLimit.new(
      dynamic_key: "input.user_id",
      units: 1,
      limit: 10,
      duration: :minute
    )
  ]
) do |input, ctx|
  puts "executed step_2"
end
```

## 静态速率限制

静态速率限制（以前称为全局速率限制）在运行之前、作为 worker 启动生命周期的一部分定义。这种模型为预定义资源提供了单一的"事实来源"，例如：

1. 对所有用户或租户有整体速率限制的外部 API 资源
2. 有最大并发连接数的数据库连接池
3. 容量有限的共享计算资源

### 工作原理

1. 在启动 worker 之前，使用 `Admin` 客户端的 `put_rate_limit` 方法声明静态速率限制。
2. 在每个 step 定义中，使用 `rate_limits` 配置指定消耗特定速率限制键的 units 数量。
3. Hatchet 通过跟踪所有 workflow 运行中每个 step 运行消耗的 units 来实施定义的速率限制。

如果某个 step 运行超过了速率限制，Hatchet 会将其重新入队，直到不再超限。

### 声明静态限制

在代码中使用 `Admin` 客户端的 `put_rate_limit` 方法定义静态速率限制，供所有 workflow 运行中的任何 step 运行消费。

#### Ruby

```python
RATE_LIMIT_KEY = "test-limit"

hatchet.rate_limits.put(RATE_LIMIT_KEY, 2, RateLimitDuration.SECOND)
```

### 消费静态速率限制

定义好速率限制键后，在 workflow 的 step 定义中添加 `rate_limits` 配置，为特定键指定消耗的 units 数量。

#### Ruby

```python
RATE_LIMIT_KEY = "test-limit"


@rate_limit_workflow.task(rate_limits=[RateLimit(static_key=RATE_LIMIT_KEY, units=1)])
def step_1(input: RateLimitInput, ctx: Context) -> None:
    print("executed step_1")
```

#### Tab 2

```typescript
const RATE_LIMIT_KEY = 'api-service-rate-limit';

const task1 = hatchet.task({
  name: 'task1',
  rateLimits: [
    {
      staticKey: RATE_LIMIT_KEY,
      units: 1,
    },
  ],
  fn: (_input, ctx) => {
    ctx.logger.info('executed task1');
  },
});
```

#### Tab 3

```go
units := 1
staticTask := client.NewStandaloneTask("task1",
	func(ctx hatchet.Context, input APIRequest) (string, error) {
		log.Println("executed task1")

		return "completed", nil
	},
	hatchet.WithRateLimits(&hatchet.RateLimit{
		Key:   RATE_LIMIT_KEY,
		Units: &units,
	}),
)
```

#### Tab 4

```ruby
RATE_LIMIT_KEY = "test-limit"

RATE_LIMIT_WORKFLOW.task(
  :step_1,
  rate_limits: [Hatchet::RateLimit.new(static_key: RATE_LIMIT_KEY, units: 1)]

```

### 限制整个 workflow 运行

要对整个 workflow 运行限速，建议在入口 step（即 workflow 的第一个 step）上指定速率限制配置。这将控制 workflow 中所有下游 step 的执行。
