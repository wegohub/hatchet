# 在 Hatchet 中为 task 分配优先级

Hatchet 允许你根据希望 task 多快被执行，为其分配不同的 `priority` 值。`priority` 可设为 `1`、`2` 或 `3`（分别对应 `low`、`medium`、`high`），值越高，该 task 越优先于同类型的其他 task 被拾取。**默认情况下，除非另行指定，Hatchet 中的运行优先级为 1（low）。**


优先级只影响*单个* workflow 的多次运行。假设你有两个不同的 workflow（A 和 B），将 A 全局设为优先级 3，B 全局设为优先级 1，这并*不能*保证队列中同时存在 A 的一个 task 和 B 的一个 task 时，A 的 task 会先运行。

但是，在 A *内部*，如果你入队一个优先级为 3 的 task 和一个优先级为 1 的 task，优先级为 3 的 task 会先运行。


分配优先级的常见用例包括：

1. 让高优先级客户（如付费客户、新客户等）优先于低优先级客户，使其 task 获得更快的周转时间。
2. 让通过 API 触发的 task 以比 cron 触发的相同 task 更高的优先级运行。

## 为 task 或 workflow 设置优先级

在 Hatchet 中有多种方式可以为 task 或 workflow 设置优先级。

### workflow 级别的默认优先级

首先，你可以在 workflow 级别设置默认优先级：

#### Ruby

```python
DEFAULT_PRIORITY = Priority.LOW
SLEEP_TIME = 0.25

priority_workflow = hatchet.workflow(
    name="PriorityWorkflow",
    default_priority=DEFAULT_PRIORITY,
)
```

#### Tab 2

```typescript
export const priorityWf = hatchet.workflow({
  name: 'priority-wf',
  defaultPriority: Priority.LOW,
});
```

#### Tab 3

```go
workflow := client.NewWorkflow(
	"priority",
	hatchet.WithWorkflowDefaultPriority(features.RunPriorityLow),
)
```

#### Tab 4

```ruby
DEFAULT_PRIORITY = 1
SLEEP_TIME = 0.25

PRIORITY_WORKFLOW = HATCHET.workflow(
  name: "PriorityWorkflow",
  default_priority: DEFAULT_PRIORITY
)

PRIORITY_WORKFLOW.task(:priority_task) do |input, ctx|
  puts "Priority: #{ctx.priority}"
  sleep SLEEP_TIME
end
```

这会为该 workflow 的所有运行（及 workflow 对应的所有 task）分配相同的默认优先级，但如果不同时设置运行级优先级则没有实际效果，因为每次运行都会使用相同的默认值。

### 触发时设置优先级

触发运行时，你可以为被触发的运行设置优先级，以覆盖其默认优先级。

#### Ruby

```python
low_prio = priority_workflow.run(
    ## 👀 Adding priority and key to metadata to show them in the dashboard
    priority=Priority.LOW,
    additional_metadata={"priority": "low", "key": 1},
    wait_for_result=False,
)

high_prio = priority_workflow.run(
    ## 👀 Adding priority and key to metadata to show them in the dashboard
    priority=Priority.HIGH,
    additional_metadata={"priority": "high", "key": 1},
    wait_for_result=False,
)
```

#### Tab 2

```typescript
const run = priority.run(new Date(Date.now() + 60 * 60 * 1000), { priority: Priority.HIGH });
```

#### Tab 3

```go
ref, err := client.RunNoWait(
	context.Background(),
	workflow.GetName(),
	PriorityInput{},
	hatchet.WithRunPriority(features.RunPriorityLow),
)
if err != nil {
	return err
}
```

#### Tab 4

```ruby
low_prio = PRIORITY_WORKFLOW.run_no_wait(
  {},
  options: Hatchet::TriggerWorkflowOptions.new(
    priority: 1,
    additional_metadata: { "priority" => "low", "key" => 1 }
  )
)

high_prio = PRIORITY_WORKFLOW.run_no_wait(
  {},
  options: Hatchet::TriggerWorkflowOptions.new(
    priority: 3,
    additional_metadata: { "priority" => "high", "key" => 1 }
  )
)
```

类似地，你也可以为计划（scheduled）和 cron workflow 分配优先级。

#### Ruby

```python
schedule = priority_workflow.schedule(
    run_at=datetime.now(tz=timezone.utc) + timedelta(minutes=1),
    priority=Priority.HIGH,
)

cron = priority_workflow.create_cron(
    cron_name="my-scheduled-cron",
    expression="0 * * * *",
    priority=Priority.HIGH,
)
```

#### Tab 2

```typescript
const scheduled = priority.schedule(
  new Date(Date.now() + 60 * 60 * 1000),
  {},
  { priority: Priority.HIGH }
);
const delayed = priority.delay(60 * 60 * 1000, {}, { priority: Priority.HIGH });
const cron = priority.cron(
  `daily-cron-${Math.random()}`,
  '0 0 * * *',
  {},
  { priority: Priority.HIGH }
);
```

#### Tab 3

```go
priority := features.RunPriorityHigh

schedule, err := client.Schedules().Create(
	context.Background(),
	workflow.GetName(),
	features.CreateScheduledRunTrigger{
		Priority: &priority,
	},
)
if err != nil {
	return err
}

cron, err := client.Crons().Create(
	context.Background(),
	workflow.GetName(),
	features.CreateCronTrigger{
		Priority: &priority,
	},
)
if err != nil {
	return err
}
```

#### Tab 4

```ruby
schedule = PRIORITY_WORKFLOW.schedule(
  Time.now + 60,
  options: Hatchet::TriggerWorkflowOptions.new(priority: 3)
)

cron = PRIORITY_WORKFLOW.create_cron(
  "my-scheduled-cron",
  "0 * * * *",
  input: {},
)
```

在这些情况下，触发器上设置的优先级会覆盖默认优先级，因此这些运行会先于较低优先级的运行被处理。
