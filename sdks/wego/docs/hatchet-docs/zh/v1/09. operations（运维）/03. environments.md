# 使用 Hatchet 管理环境

## 多个开发者，一个编排器

当多个开发者共享同一个 Hatchet 编排器时，workflow run 和 event 相互混杂可能引发冲突。如果没有适当的隔离，一个开发者的 workflow 可能干扰另一个开发者的测试或开发工作。

Hatchet 为应对这一挑战提供了三种关键方案：命名空间、多租户（multi-tenancy）以及本地 Hatchet 实例。

### 方案一：多租户

为不同开发者或团队隔离环境的最简单方法是使用 Hatchet 的多租户功能。每个 tenant 代表一个独立的环境，拥有自己的一组 workflow 和 worker。要为每个开发者添加一个新 tenant，请创建一个组织并按以下步骤操作：

1. 在控制台中访问组织下拉菜单（右上角）
2. 点击组织名称旁边的 `+` 图标
3. 为该 tenant 生成一个新 token
4. 每个开发者使用分配给他们的 tenant token 配置自己的环境

### 方案二：本地 Hatchet 实例

如果你在本地使用 Hatchet，可以创建一个本地 Hatchet 实例来管理隔离的本地开发环境。

可选方案请参阅[在本地运行 Hatchet](<../01. get-started（入门）/04. running-locally.md>)，从嵌入式模式（无需账户、token 或 Docker）到贴近生产的本地技术栈均有覆盖。
