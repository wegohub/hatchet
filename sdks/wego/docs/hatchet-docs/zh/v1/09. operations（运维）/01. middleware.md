# 中间件与依赖注入（Middleware & Dependency Injection）

中间件让你可以在客户端上于每个 task **之前**和**之后**运行逻辑，而无需修改各个 task 的定义。常见用途包括注入请求 ID、用共享数据丰富输入、加密/解密载荷，以及对输出进行标准化或增强。


  此功能为实验性功能，中间件钩子的签名在未来版本中可能会发生变化。


#### Python

Hatchet 的 Python SDK 使用 FastAPI 风格的依赖注入：在 task 执行前运行逻辑，
并将结果作为参数注入。依赖以函数的形式声明，并通过 `Depends` 接入 task。

#### Typescript

中间件钩子通过 `withMiddleware` 注册在客户端上，并且是完全类型安全的 ——
TypeScript 能看到 task 输入类型与 `before` 钩子返回值的字段联合类型，
task 输出与 `after` 钩子同理。

#### Ruby

在 Ruby 中，这种模式使用可调用对象（lambda/proc），在定义 task 时作为 `deps`
传入。依赖在每次 task 运行前求值，并可通过 `ctx.deps` 获取。

## 定义中间件

#### Python

定义你的依赖函数 —— 它们接收 workflow 输入和上下文，其返回值会作为参数注入到 task 中。

```python
async def async_dep(input: EmptyModel, ctx: Context) -> str:
    return ASYNC_DEPENDENCY_VALUE


def sync_dep(input: EmptyModel, ctx: Context) -> str:
    return SYNC_DEPENDENCY_VALUE


@asynccontextmanager
async def async_cm_dep(
    input: EmptyModel, ctx: Context, async_dep: Annotated[str, Depends(async_dep)]
) -> AsyncGenerator[str, None]:
    try:
        yield ASYNC_CM_DEPENDENCY_VALUE + "_" + async_dep
    finally:
        pass


@contextmanager
def sync_cm_dep(
    input: EmptyModel, ctx: Context, sync_dep: Annotated[str, Depends(sync_dep)]
) -> Generator[str, None, None]:
    try:
        yield SYNC_CM_DEPENDENCY_VALUE + "_" + sync_dep
    finally:
        pass


@contextmanager
def base_cm_dep(input: EmptyModel, ctx: Context) -> Generator[str, None, None]:
    try:
        yield CHAINED_CM_VALUE
    finally:
        pass


def chained_dep(
    input: EmptyModel, ctx: Context, base_cm: Annotated[str, Depends(base_cm_dep)]
) -> str:
    return "chained_" + base_cm


@asynccontextmanager
async def base_async_cm_dep(
    input: EmptyModel, ctx: Context
) -> AsyncGenerator[str, None]:
    try:
        yield CHAINED_ASYNC_CM_VALUE
    finally:
        pass


async def chained_async_dep(
    input: EmptyModel,
    ctx: Context,
    base_async_cm: Annotated[str, Depends(base_async_cm_dep)],
) -> str:
    return "chained_" + base_async_cm
```

#### Typescript

创建客户端并通过 `before` 和 `after` 钩子附加中间件。

- **`before(input, ctx)`** 在 task 之前运行。其返回值会**替换** task 输入。
- **`after(output, ctx, input)`** 在 task 之后运行。其返回值会**替换** task 输出。

```typescript
import { HatchetClient, HatchetMiddleware } from '@hatchet/v1';

export type GlobalInputType = {
  first: number;
  second: number;
};

export type GlobalOutputType = {
  extra: number;
};

const myMiddleware = {
  before: (input, ctx) => {
    ctx.logger.info('before', { first: input.first });
    return { ...input, dependency: 'abc-123' };
  },
  after: (output, ctx, input) => {
    return { ...output, additionalData: 2 };
  },
} satisfies HatchetMiddleware;

export const hatchetWithMiddleware = HatchetClient.init<
  GlobalInputType,
  GlobalOutputType
>().withMiddleware(myMiddleware);
```


  **如果想保留原始值，请展开原值。** 每个钩子的返回值会**完全替换**输入（或输出）——
  并非浅合并。如果 `before` 钩子中省略了 `...input`，原始字段将丢失。`after` 钩子中的
  `...output` 同理。

  ```typescript
      // ✅ 保留原始字段并添加 `requestId`
      before: (input) => ({ ...input, requestId: crypto.randomUUID() })

      // ❌ 完全替换输入 —— task 只会收到 { requestId }
      before: (input) => ({ requestId: crypto.randomUUID() })
  ```


### 链式中间件

你可以链式调用多个 `.withMiddleware()`，让钩子按顺序执行。每个 `before` 钩子接收上一个 `before` 钩子的返回值（第一个钩子则接收原始输入），每个 `after` 钩子接收上一个 `after` 钩子的返回值。

```typescript
const firstMiddleware = {
  before: (input, ctx) => {
    ctx.logger.info('before', { first: input.first });
    return { ...input, dependency: 'abc-123' };
  },
  after: (output, ctx, input) => {
    return { ...output, firstExtra: 3 };
  },
} satisfies HatchetMiddleware;

const secondMiddleware = {
  before: (input, ctx) => {
    ctx.logger.info('before', { dependency: input.dependency }); // available from previous middleware
    return { ...input, anotherDep: true };
  },
  after: (output, ctx, input) => {
    return { ...output, secondExtra: 4 };
  },
} satisfies HatchetMiddleware;

export const hatchetWithMiddlewareChaining = HatchetClient.init()
  .withMiddleware(firstMiddleware)
  .withMiddleware(secondMiddleware);
```

将依赖定义为可调用对象（lambda）。它们接收输入、上下文，以及可选的先前已解析依赖的哈希，用于链式调用。


## 中间件的执行方式

#### Python

依赖在每次 task 执行之前解析。每个依赖函数接收原始的 workflow 输入和 task 上下文，其返回值以命名参数的形式注入到 task 函数中。

#### Typescript

当 task 运行时，worker 按以下顺序应用中间件钩子：


### before 钩子按注册顺序运行

每个 `before` 钩子接收当前输入和 task 的 `Context`。其返回值会**替换**传给下一个钩子（或 task 本身）的输入。返回 `undefined`（或 `void`）则跳过替换，原样传递输入。

### task 函数执行

task 接收所有 `before` 钩子运行完毕后的最终输入。

### after 钩子按注册顺序运行

每个 `after` 钩子接收当前输出、task 的 `Context` 以及最终输入。其返回值会**替换**传给下一个钩子（或最终结果）的输出。返回 `undefined` 则跳过替换。


`before` 和 `after` 钩子都可以是 **async** 的 —— 返回一个 `Promise`，它会在继续执行之前被 await。

> **Info:** 如果中间件钩子抛出错误，该 task 运行将以此错误失败。中间件本身没有内置的错误恢复机制 —— 如需优雅降级，请在钩子内部使用 try/catch。

### `ctx` 参数

`before` 和 `after` 钩子的第二个参数是 task 的 `Context` 对象。它让中间件可以访问：
- `ctx.workflowRunId` —— 当前 workflow 运行的 ID
- `ctx.stepRunId` —— 当前 step 运行的 ID
- `ctx.log()` —— 输出可在 Hatchet 仪表板中查看的结构化日志
- `ctx.cancel()` —— 在中间件内取消当前运行

### 全局类型与中间件类型

task 的输入上出现额外字段有两种途径：

机制， 设置方式， 调用方是否必须提供？， 运行时是否可用？

**全局输入类型**， `HatchetClient.init()`， 是 —— 调用方必须提供这些字段， 是
**中间件 before 钩子**， `.withMiddleware({ before })`， 否 —— 由 worker 自动注入， 是

全局输入类型（`init()` 中的 `T`）表示调用方在触发 task 时**必须提供**的字段。当你知道每个 task 都必须始终接收某些参数时（例如用于身份认证的 `userId`，或用于多租户路由的 `tenantId`），这非常有用。将它们声明为全局类型后，TypeScript 会强制每个调用方都提供。

而中间件 `before` 钩子注入的是**在运行时计算**出来的字段（例如请求 ID、解密后的密钥、拉取的配置），**不**要求调用方提供。

```typescript
    type RequiredContext = { userId: string; orgId: string };

    const client = HatchetClient.init()
      .withMiddleware({
        before: (input) => ({
          ...input,
          resolvedAt: Date.now(),        // injected, not required from caller
          permissions: lookupPerms(input.userId), // derived from global type
        }),
      });

    // Callers MUST provide userId and orgId — TypeScript enforces this
    await myTask.run({ userId: 'usr_123', orgId: 'org_456', /* ...task fields */ });
```

## 在 task 中使用中间件

#### Python

使用 `Depends` 和类型注解将依赖注入到 task 中。依赖结果会直接作为函数参数传入。

```python
@hatchet.task()
async def async_task_with_dependencies(
    _i: EmptyModel,
    ctx: Context,
    async_dep: Annotated[str, Depends(async_dep)],
    sync_dep: Annotated[str, Depends(sync_dep)],
    async_cm_dep: Annotated[str, Depends(async_cm_dep)],
    sync_cm_dep: Annotated[str, Depends(sync_cm_dep)],
    chained_dep: Annotated[str, Depends(chained_dep)],
    chained_async_dep: Annotated[str, Depends(chained_async_dep)],
) -> Output:
    return Output(
        sync_dep=sync_dep,
        async_dep=async_dep,
        async_cm_dep=async_cm_dep,
        sync_cm_dep=sync_cm_dep,
        chained_dep=chained_dep,
        chained_async_dep=chained_async_dep,
    )
```


  你的依赖函数必须接收两个位置参数：workflow 输入和 `Context`（与其他任何 task 相同）。


#### Typescript

从启用了中间件的客户端创建的 task 会自动获得合并后的输入和输出类型。task 本身无需任何额外配置。

```typescript
import { hatchetWithMiddleware } from './client';

type TaskInput = {
  message: string;
};

type TaskOutput = {
  message: string;
};

export const taskWithMiddleware = hatchetWithMiddleware.task({
  name: 'task-with-middleware',
  fn: (input, ctx) => {
    ctx.logger.info('task', { message: input.message }); // string  (from TaskInput)
    ctx.logger.info('task', { first: input.first }); // number  (from GlobalInputType)
    ctx.logger.info('task', { second: input.second }); // number  (from GlobalInputType)
    ctx.logger.info('task', { dependency: input.dependency }); // string  (from Pre Middleware)
    return {
      message: input.message,
      extra: 1,
    };
  },
});
// !!
```

task 的 `input` 类型是 `TaskInput`、`GlobalInputType` 与 `before` 中间件钩子返回类型的交集。task 的返回类型必须满足 `TaskOutput` 和 `GlobalOutputType`，而调用方收到的是它们与 `after` 中间件返回类型的交集。

## 实战示例

下面的示例展示了常见生产模式下的 TypeScript 中间件。每个示例都可以通过将相同逻辑提取到依赖函数中，适配到 Python 依赖注入模型。

### 端到端加密

在敏感输入字段到达 Hatchet 服务器之前对其进行加密，并在返回时对输出进行解密。这确保明文数据永远不会离开你的 worker 进程。

```typescript
import { HatchetClient, HatchetMiddleware } from '@hatchet/v1';
import { randomUUID, createCipheriv, createDecipheriv, randomBytes } from 'crypto';
```

> **Info:** `before` 钩子对传入的数据解密，使你的 task 函数处理的是明文。
>   `after` 钩子在输出被存储之前对其进行加密。加密密钥永远不会离开 worker 环境。

### 将大载荷转存到 S3

当 task 的输入或输出超过 Hatchet 的载荷大小限制时（或者你只是不想让大块数据进入控制平面），可以将它们上传到 S3 并传递签名 URL。

```typescript
import { S3Client, PutObjectCommand, GetObjectCommand } from '@aws-sdk/client-s3';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';

const ALGORITHM = 'aes-256-gcm';
const KEY = Buffer.from(process.env.ENCRYPTION_KEY!, 'hex');

type EncryptedEnvelope = { ciphertext: string; iv: string; tag: string };

function encrypt(plaintext: string): EncryptedEnvelope {
  const iv = randomBytes(16);
  const cipher = createCipheriv(ALGORITHM, KEY, iv);
  const encrypted = Buffer.concat([cipher.update(plaintext, 'utf8'), cipher.final()]);
  return {
    ciphertext: encrypted.toString('base64'),
    iv: iv.toString('base64'),
    tag: cipher.getAuthTag().toString('base64'),
  };
}

function decrypt(ciphertext: string, iv: string, tag: string): string {
  const decipher = createDecipheriv(ALGORITHM, KEY, Buffer.from(iv, 'base64'));
  decipher.setAuthTag(Buffer.from(tag, 'base64'));
  return decipher.update(ciphertext, 'base64', 'utf8') + decipher.final('utf8');
}

type EncryptedInput = { encrypted?: EncryptedEnvelope };

const e2eEncryption: HatchetMiddleware = {
  before: (input) => {
    if (!input.encrypted) {
      return input;
    }
    const { ciphertext, iv, tag } = input.encrypted;
    const decrypted = JSON.parse(decrypt(ciphertext, iv, tag));
    return { ...input, ...decrypted, encrypted: undefined };
  },
  after: (output) => {
    const payload = JSON.stringify(output);
    return { encrypted: encrypt(payload) };
  },
};

const encryptionClient = HatchetClient.init().withMiddleware(e2eEncryption);

const s3 = new S3Client({ region: process.env.AWS_REGION });
const BUCKET = process.env.S3_BUCKET!;
const PAYLOAD_THRESHOLD = 256 * 1024; // 256 KB

async function uploadToS3(data: unknown): Promise<string> {
  const key = `hatchet-payloads/${randomUUID()}.json`;
  await s3.send(
    new PutObjectCommand({
      Bucket: BUCKET,
      Key: key,
      Body: JSON.stringify(data),
      ContentType: 'application/json',
    })
  );
  return getSignedUrl(s3, new GetObjectCommand({ Bucket: BUCKET, Key: key }), {
    expiresIn: 3600,
  });
}

async function downloadFromS3(url: string): Promise<unknown> {
  const res = await fetch(url);
  return res.json();
}

type S3Input = { s3Url?: string };

const s3Offload: HatchetMiddleware = {
  before: async (input) => {
    if (input.s3Url) {
      const restored = (await downloadFromS3(input.s3Url)) as Record<string, any>;
      return { ...restored, s3Url: undefined };
    }
    return input;
  },
  after: async (output) => {
    const serialized = JSON.stringify(output);
    if (serialized.length > PAYLOAD_THRESHOLD) {
      const url = await uploadToS3(output);
      return { s3Url: url };
    }
    return output;
  },
};

const s3Client = HatchetClient.init().withMiddleware(s3Offload);
```


  调用方负责在触发 task 之前将超大的输入上传到 S3。`before` 钩子只负责下载这一侧。
  你可以在调用方使用相同的 `uploadToS3` 辅助函数上传输入，并将 `{ __s3Url: url }` 作为 task 输入传入。


## FAQ

### 什么是 Hatchet 中间件？它与 Express 中间件有何不同？

Hatchet 中间件在 **worker 进程内部**围绕每次 task 调用运行 —— 而非 HTTP 请求路径上。`before` 钩子在 task 运行前转换输入，`after` 钩子在运行后转换输出。与 Express 中间件不同，这里没有 `next()` 函数；钩子直接返回结果，由运行器自动完成链式调用。

### 中间件可以同时用于 task 和 workflow 吗？

可以。中间件注册在 `HatchetClient` 实例上，因此适用于从该客户端创建的每个 task —— 无论该 task 是独立的 `client.task()`，还是多步骤 `client.workflow()` 的一部分。workflow 中的每个 step 都会独立地应用中间件。

### 中间件在服务器上运行还是在 worker 上运行？

中间件完全在 **worker 上**运行。Hatchet 服务器永远不会看到或执行你的中间件代码。这正是端到端加密等模式得以实现的原因 —— 明文数据始终留在你的基础设施内。

### 如果我的中间件抛出错误会怎样？

如果 `before` 或 `after` 钩子抛出异常（或返回一个 rejected 的 `Promise`），该 task 运行将以此错误失败。中间件本身不会自动重试，但 task 配置的重试策略仍然生效，会从头重新运行该 task（及其中间件）。

### 中间件钩子中可以使用 async/await 吗？

可以。`before` 和 `after` 钩子既可以是同步的也可以是异步的。如果钩子返回一个 `Promise`，worker 会在进入下一个钩子或 task 函数之前对其进行 `await`。

### 如何在 `before` 和 `after` 钩子之间共享状态？

`after` 钩子的第三个参数是 task 输入（`before` 钩子运行之后）。在 `before` 中添加字段（如 `startedAt`、`traceId`），然后在 `after` 中从 `input` 读取。没有单独的共享上下文对象 —— 输入本身就是载体。

### 中间件适用于通过 fanout 派生的子 task 吗？

中间件的作用域是**客户端实例**。如果子 task 定义在同一个启用了中间件的客户端上，该子 task 执行时会运行其中间件。如果子 task 使用不同的客户端实例，则只应用那个客户端的中间件（如果有）。

### 我可以为某些 task 选择性地跳过中间件吗？

中间件适用于给定客户端上的**所有** task。要为特定 task 跳过中间件，请创建一个不带中间件的第二个客户端，并在其上定义这些 task。这是有意为之的设计 —— 中间件是一种横切关注点，选择性退出在客户端边界处处理。

### 使用中间件有性能开销吗？

中间件钩子是在 worker 上进程内运行的普通 JavaScript 函数。开销即你的钩子代码的执行时间。对于轻量操作（添加字段、记录日志），开销可以忽略不计。对于较重的操作（如 S3 上传或解密等网络调用），task 的总时长会包含这部分时间，因此请尽量保持钩子高效。

### TypeScript 中全局类型和中间件类型有什么区别？

全局类型（`HatchetClient.init()`）定义调用方在触发 task 时**必须提供**的字段。中间件类型（从 `withMiddleware` 返回值推断）定义由 worker 在**运行时注入**的字段。两者都会出现在 task 的 `input` 类型上，但只有全局类型会出现在面向调用方的 `run()` 签名中。

### 中间件可以用于限流或身份认证吗？

可以。`before` 钩子可以在 task 运行前检查限流、验证 API 密钥或校验 JWT。如果检查失败，抛出错误以中止 task。不过，就限流而言，建议使用 Hatchet 内置的[速率限制](/home/rate-limits)功能，它在调度层运作，比 worker 内检查更高效。

### 如何单独测试中间件？

中间件钩子是普通函数 —— 你可以用模拟输入和模拟上下文对象直接调用它们进行单元测试。对于集成测试，e2e 测试模式效果很好：创建客户端、附加中间件、定义 task、启动 worker，然后对结果进行断言。完整测试配置请参见 [GitHub 上的中间件示例](https://github.com/hatchet-dev/hatchet/tree/main/examples/typescript/middleware)。
