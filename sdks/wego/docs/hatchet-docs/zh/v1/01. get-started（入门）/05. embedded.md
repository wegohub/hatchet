# 嵌入式模式（Embedded Mode）


Hatchet 可以在你的 worker 内部以[嵌入式模式](https://github.com/hatchet-dev/hatchet-embedded)运行。其目标是让本地测试尽可能简单，并能够在临时（ephemeral）CI 环境中端到端地测试 worker。无需预先创建 tenant、用户或 API token 即可开始。

使用嵌入式模式时，你会在本地得到一个完整的 Hatchet 引擎，没有任何外部依赖（包括 Postgres）。默认情况下，它使用 [embedded-postgres](https://github.com/fergusstrange/embedded-postgres) 来提供一个 Postgres 数据库。


## 工作原理

- **Go** 在进程内运行引擎：`hatchet-embedded` 包通过空导入（blank import）向 Go SDK 注册自身，SDK 在 `NewClient` 时启动引擎。
- **TypeScript 和 Python** 将引擎作为 sidecar 进程运行。首次使用时，SDK 会从 hatchet-embedded 的 [releases](https://github.com/hatchet-dev/hatchet-embedded/releases) 下载适合你平台的 `hatchet-embedded-sidecar` 二进制文件（在 macOS 上经过签名和公证），缓存在 `~/.hatchet/embedded/<version>` 下并启动它。每次启动时都会根据 release 的校验和验证该二进制文件，并且 sidecar 会随你的进程一起关闭。

## 用法

#### Python

```python
hatchet = Hatchet.from_embedded()
```

通过 `ClientConfig.embedded` 配置嵌入式引擎（参见[选项](#options)）。

使用完毕后，停止引擎并等待其退出：

```python
hatchet.stop_embedded()
```

> **Warning:** Python worker 在子进程中运行 task，子进程会重新导入你的主模块。
>   `Hatchet.from_embedded()` 会自动处理这一点，子进程会连接到父进程的引擎，
>   而不是自己再启动一个。与任何使用 multiprocessing 的 Python 程序一样，
>   请把 worker 启动和 task 触发放在 `if __name__ == "__main__":` 保护之下。

#### Typescript

嵌入式模式是一个独立的入口，因此不会进入生产构建产物：

```typescript
const hatchet = await HatchetEmbeddedClient.init();
```

选项作为第一个参数传入（参见[选项](#options)）。

使用完毕后，停止引擎并等待其退出：

```typescript
await hatchet.stopEmbedded();
```

#### Go

```sh
go get github.com/hatchet-dev/hatchet-embedded
```

将该包与 SDK 一起以副作用方式导入；SDK 会检测嵌入式配置并在 `NewClient` 时启动引擎：

```go
import (
	hatchet "github.com/hatchet-dev/hatchet/sdks/go"

	_ "github.com/hatchet-dev/hatchet-embedded"
)
```

选项通过 `WithEmbedded` 传入（参见[选项](#options)）。

使用完毕后，`client.Close(ctx)` 会停止嵌入式引擎并等待其退出：

```go
return client.Close(ctx)
```

## 选项

#### Python

所有选项都在 `EmbeddedHatchetConfig` 上。每个字段也可以通过 `HATCHET_CLIENT_EMBEDDED_*` 环境变量设置（例如 `HATCHET_CLIENT_EMBEDDED_BINARY_PATH`）：

```python
hatchet = Hatchet.from_embedded(
    ClientConfig(
        embedded=EmbeddedHatchetConfig(
            # use your own Postgres instead of the bundled one
            database_url="postgres://...",
            # store the bundled Postgres runtime and data under this directory
            postgres_data_dir="~/my-project/.hatchet-pg",
            # use RabbitMQ instead of the Postgres message queue
            rabbitmq_url="amqp://...",
            # bind the API / gRPC servers to specific ports
            api_port=28243,
            grpc_port=7070,
            # start only the engine + gRPC, no REST API
            start_api=False,
            # skip running migrations on startup
            run_migrations=False,
            # engine log level (default "warn")
            log_level="info",
            # hatchet-embedded release tag to download
            version="v0.105.0",
            # use an existing sidecar binary, skips the download
            binary_path="/path/to/hatchet-embedded-sidecar",
            # pinned sha256 of the sidecar binary, replaces
            # checksums.txt as the trust anchor
            checksum="4f2a...",
        )
    )
)
```

#### Typescript

```typescript
const hatchet = await HatchetEmbeddedClient.init({
  // use your own Postgres instead of the bundled one
  databaseUrl: 'postgres://...',
  // store the bundled Postgres runtime and data under this directory
  postgresDataDir: '~/my-project/.hatchet-pg',
  // use RabbitMQ instead of the Postgres message queue
  rabbitmqUrl: 'amqp://...',
  // bind the API / gRPC servers to specific ports
  apiPort: 28243,
  grpcPort: 7070,
  // start only the engine + gRPC, no REST API
  startApi: false,
  // skip running migrations on startup
  runMigrations: false,
  // engine log level (default "warn")
  logLevel: 'info',
  // hatchet-embedded release tag to download
  version: 'v0.105.0',
  // use an existing sidecar binary, skips the download
  binaryPath: '/path/to/hatchet-embedded-sidecar',
  // pinned sha256 of the sidecar binary, replaces checksums.txt as the trust anchor
  checksum: '4f2a...',
});
```

#### Go

```go
client, err := hatchet.NewClient(hatchet.WithEmbedded(
	// use your own Postgres instead of the bundled one
	hatchet.WithEmbeddedDatabaseURL("postgres://..."),
	// use RabbitMQ instead of the Postgres message queue
	hatchet.WithEmbeddedRabbitMQ("amqp://..."),
	// bind the API / gRPC servers to specific ports
	hatchet.WithEmbeddedAPIPort(28243),
	hatchet.WithEmbeddedGRPCPort(7070),
	// start only the engine + gRPC, no REST API
	hatchet.WithoutEmbeddedAPI(),
	// skip running migrations on startup
	hatchet.WithoutEmbeddedMigrations(),
	// engine log level (default "warn")
	hatchet.WithEmbeddedLogLevel("info"),
))
```

`version`、`binaryPath` 和 `checksum` 不适用于 Go：引擎在进程内运行，因此没有需要下载的 sidecar。当你通过 `embed.StartServer` 自行驱动引擎时，`embed` 包还提供 `WithPostgresDataDir(dir)`、`WithAdminUser(email, password)`、`WithKeysets(...)` 和 `WithLogger(...)`。

## 提供控制台服务

嵌入式实例不带前端。`hatchet embedded-ui` CLI 命令会在你的机器上提供打包在 CLI 二进制文件中的控制台，并将 API 请求代理到实例的 API server。不带任何参数时，它默认指向嵌入式 API 的默认端口（`http://localhost:28243`）：

```sh
hatchet embedded-ui
```

这会在浏览器中打开本地提供的控制台。URL 中包含一次性的 `ui_token`，会被交换为本地会话 cookie；没有该 cookie 的请求会被拒绝，因此其他进程或机器无法使用这个代理端口。除非你通过 `--host` 覆盖，服务器默认绑定到 `localhost`。

如果你的实例不在默认端口上（例如同一台机器上的第二个实例），请通过 `--api-url` 显式传入其 API server 地址（取自引擎 ready 日志行中的地址）。目标必须（通过 `/api/v1/meta`）表明自己是嵌入式实例；对于其他任何部署，该命令都会报错。

| 标志 | 描述 |
| --- | --- |
| `--api-url` | 要代理到的 API server URL（默认为 `http://localhost:28243`）。 |
| `--profile` | UI 所指向的 API server 所属的 profile。 |
| `--port` | 提供 UI 服务的端口（默认从 `8080` 起自动检测）。 |
| `--host` | UI 服务器绑定的主机接口（默认为 `localhost`）。 |
| `--no-open` | 不自动打开浏览器。 |

## 版本管理

hatchet-embedded 的 release 标签与公开发布的 [Hatchet 引擎](https://github.com/hatchet-dev/hatchet/releases)版本一一对应。

TypeScript 和 Python SDK 按以下顺序解析版本：

1. `version` 选项
2. `HATCHET_CLIENT_EMBEDDED_VERSION` 环境变量
3. 最新的 hatchet-embedded release

## 运行多个实例

同一台机器上的多个嵌入式实例可以开箱即用：第一个实例的 API 绑定默认端口 `28243`，其余实例获得随机空闲端口（在每个引擎的 ready 日志行中打印），gRPC 和 Postgres 端口自动分配，内置的 Postgres 把数据保存在按项目划分的目录中（`~/.hatchet-embedded/<工作目录哈希>`），该目录在重启后也会保留。

从_同一个_工作目录启动的两个实例不能并发共享内置 Postgres 的数据目录。请通过 Postgres 数据目录选项为每个实例单独指定，或让它们指向一个外部 Postgres。

## 用共享数据库运行集群

你可以将多个嵌入式引擎作为一个集群运行。让每个引擎指向同一个外部 Postgres 数据库。这些引擎随后会在同一个 tenant 上运行，并共享任务队列。这在 Go、TypeScript 和 Python 中的工作方式相同，并且可以混合使用。

在创建每个客户端时设置数据库 URL：

#### Python

```python
hatchet = Hatchet.from_embedded(
    ClientConfig(
        embedded=EmbeddedHatchetConfig(
            database_url="postgres://user:pass@db.internal:5432/hatchet"
        )
    )
)
```

#### Typescript

```typescript
const hatchet = await HatchetEmbeddedClient.init({
  databaseUrl: 'postgres://user:pass@db.internal:5432/hatchet',
});
```

#### Go

```go
client, err := hatchet.NewClient(hatchet.WithEmbedded(
	hatchet.WithEmbeddedDatabaseURL("postgres://user:pass@db.internal:5432/hatchet"),
))
```

#### Ruby

> **Info:** Ruby SDK 的嵌入式模式即将推出。加入我们的
>       <a href="https://hatchet.run/discord">Discord</a> 了解最新动态。

用相同的数据库 URL 启动更多进程即可扩大集群；停止一个进程即可缩小集群。其余引擎会继续处理工作。

每个引擎在启动时都会执行数据库迁移。不要让两个引擎同时执行迁移。请先完整启动第一个引擎再启动其他引擎，或者只在其中一个引擎上开启迁移（`WithoutEmbeddedMigrations()`、`runMigrations: false`、`run_migrations=False`）。

## 加密密钥集

如果没有显式的密钥集（keyset），嵌入式模式会在同一个数据库内的某个 schema 中自动管理它们。这对开发很方便，但当密钥与它们所加密的数据存放在一起时，静态加密（at-rest encryption）无法提供额外的保护。可以通过 `WithKeysets`（Go，通过 `embed.StartServer`）在外部管理密钥。
