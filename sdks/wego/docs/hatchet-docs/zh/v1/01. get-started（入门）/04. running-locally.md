# 在本地运行 Hatchet

在你自己的机器上运行 Hatchet 有多种选择：

选项, 最适合, 需要

| [嵌入式模式](<05. embedded.md>) | 本地开发和 CI | 无（无需账号或 Docker） |
| --- | --- | --- |
| [Hatchet CLI](<../../reference/05. running-hatchet-locally.md>) | 带仪表板的完整本地栈 | Docker |
| [Hatchet Lite](<../../self-hosting/02. hatchet-lite.md>) | 单个自管理容器 | Docker |
| [Docker Compose](<../../self-hosting/03. docker-compose.md>) | 服务分离的本地栈 | Docker |
| [Kubernetes](<../../self-hosting/04. kubernetes-quickstart.md>) | 类生产的自托管部署 | 一个集群 |

## 嵌入式模式

[嵌入式模式](<05. embedded.md>) 在你的 worker 进程内部运行一个完整的 Hatchet 引擎和 Postgres 实例。它不需要账号、API token 或 Docker，因而是本地开发和 CI 中端到端测试的最快途径。

## CLI

使用 CLI 命令 [`hatchet server start`](<../../reference/05. running-hatchet-locally.md>)，你可以在本地运行一个完整的实例（包括仪表板），底层使用 Docker。添加 `--disable-auth` 可启用面向本地开发的无认证模式：一切都以预置的管理员用户身份在默认租户下运行，因此没有注册步骤。

## Hatchet Lite

[Hatchet Lite](<../../self-hosting/02. hatchet-lite.md>) 将 Hatchet 打包为单个容器。当你想自己管理容器时可直接使用它（上面的 CLI 命令就是对它的封装）。

## Docker Compose 与 Kubernetes

[Docker Compose](<../../self-hosting/03. docker-compose.md>) 以相互独立的服务形式运行整套栈，适合类生产的本地环境；而 [Kubernetes](<../../self-hosting/04. kubernetes-quickstart.md>) 让你可以模拟真实的自托管部署。
