# 使用编码 Agent（Coding Agents）

Hatchet 在设计上可以与 AI 编码 agent 良好配合。本页介绍如何让你的 agent 访问 Hatchet 文档，以及常用 CLI 操作的分步技能（skills）。

> **Info:** **前提条件：** `hatchet skills install` 和 `hatchet docs install` 命令需要
>   Hatchet CLI。安装说明请参阅 [CLI 参考](/cli)。

## Agent Skills

Agent skills 是教 AI 编码 agent 如何使用 Hatchet CLI 的参考文档 —— 触发 workflow、启动 worker、调试运行等。

在项目根目录下运行以下命令安装 skill 包：

```bash copy
hatchet skills install
```

这会创建一个 `skills/hatchet-cli/` 目录（包含分步参考文件），并在项目的 `AGENTS.md`（和 `CLAUDE.md`）中追加一节，引导 agent 为每个任务找到正确的文件。

**安装到自定义目录：**

```bash copy
hatchet skills install --dir ./my-project
```

安装完成后，将 `skills/` 目录和 `AGENTS.md` 提交到版本控制，这样仓库中所有 agent 都能自动受益。

### 可用的参考文档

| 参考文档 | 使用时机 |
| --- | --- |
| `references/setup-cli.md` | 安装 CLI、创建或列出 profile |
| `references/local-dev-embedded.md` | 无需 token、服务器或 Docker 在本地运行 Hatchet |
| `references/start-worker.md` | 为本地开发启动 dev worker |
| `references/trigger-and-watch.md` | 触发 workflow 并轮询完成状态 |
| `references/debug-run.md` | 诊断失败、卡住或异常的运行 |
| `references/replay-run.md` | 使用相同或新的输入重新运行之前的 workflow |

## 使用嵌入式模式进行本地开发

本地开发时，agent 不需要 API token 或 Docker。[嵌入式模式](<05. embedded.md>)会在本地运行一个完整的 Hatchet 引擎，因此 agent 可以启动 worker、触发 task 并查看结果，而无需任何账号设置。

每个 SDK 都有嵌入式入口：Python 使用 `Hatchet.from_embedded()`，TypeScript 使用来自 `@hatchet-dev/typescript-sdk/v1/embedded` 的 `HatchetEmbeddedClient.init()`，Go 则使用 `hatchet.WithEmbedded()` 并 blank import `github.com/hatchet-dev/hatchet-embedded`：

#### Python

```python
hatchet = Hatchet.from_embedded()
```

#### Typescript

```typescript
const hatchet = await HatchetEmbeddedClient.init();
```

#### Go

```go
import (
	hatchet "github.com/hatchet-dev/hatchet/sdks/go"

	_ "github.com/hatchet-dev/hatchet-embedded"
)
```

配置选项、停止引擎以及托管仪表板，请参阅[嵌入式模式](<05. embedded.md>)。

## MCP 服务器

Hatchet 文档以 **MCP（Model Context Protocol）服务器**的形式提供，因此 Cursor 和 Claude Code 等 AI 编码助手可以直接搜索和引用 Hatchet 文档。

MCP 端点： 


  
  
  
    #### Hatchet CLI

```bash copy
        hatchet docs install claude-code
```

如果 `claude` 在你的 PATH 中，这会自动运行该命令；否则它会打印出命令供你复制。
