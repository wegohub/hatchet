# OpenTelemetry

Hatchet 支持将 task 产生的 trace 导出到 [OpenTelemetry Collector](https://opentelemetry.io/docs/collector/)，以提升对 Hatchet task 的可观测性。

> **Info:** 本页介绍的是对应用程序、task 和 workflow 代码进行追踪。如需导出自托管实例上
>   Hatchet 自身服务产生的 trace，请参阅
>   [内部 OpenTelemetry trace](<02. opentelemetry.md>)。

## 设置

#### Python

安装 `otel` 扩展：

```bash
pip install hatchet-sdk[otel]
```

然后创建 instrumentor 并调用 `instrument()`：

```python
from hatchet_sdk.opentelemetry.instrumentor import HatchetInstrumentor

HatchetInstrumentor().instrument()
```

默认情况下，`HatchetInstrumentor` 会创建一个 `TracerProvider`，将 span 发送到 Hatchet 引擎的 OTLP collector。你也可以传入自己的 `TracerProvider`：

```python
HatchetInstrumentor(
    tracer_provider=your_tracer_provider,
).instrument()
```

### 选项

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `tracer_provider` | `TracerProvider` | — | 自定义 TracerProvider。若未设置，会自动创建一个。 |
| `enable_hatchet_otel_collector` | `bool` | `True` | 将 trace 发送到 Hatchet 引擎的 OTLP collector。 |
| `schedule_delay_millis` | `int` | — | BatchSpanProcessor 两次连续导出之间的延迟。 |
| `max_export_batch_size` | `int` | — | BatchSpanProcessor 的最大批量大小。 |
| `max_queue_size` | `int` | — | BatchSpanProcessor 的最大队列大小。 |

#### TypeScript

安装所需的 OpenTelemetry 包：

```bash
npm install @opentelemetry/api @opentelemetry/instrumentation @opentelemetry/sdk-trace-base @opentelemetry/exporter-trace-otlp-grpc
```

在创建任何 Hatchet 客户端或 worker 之前注册 instrumentor：

```typescript
const { registerInstrumentations } = require("@opentelemetry/instrumentation");
import { HatchetInstrumentor } from "@hatchet-dev/typescript-sdk/opentelemetry";

registerInstrumentations({
  instrumentations: [new HatchetInstrumentor()],
});
```

默认情况下，`HatchetInstrumentor` 会将 span 发送到 Hatchet 引擎的 OTLP collector。可以通过 `enableHatchetCollector: false` 禁用此行为。

### 选项

| 选项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `enableHatchetCollector` | `boolean` | `true` | 将 trace 发送到 Hatchet 引擎的 OTLP collector。 |
| `clientConfig` | `object` | — | 覆盖用于 collector 连接的 Hatchet 客户端配置。 |
| `includeTaskNameInSpanName` | `boolean` | `false` | 将 task 的 action ID 追加到 `hatchet.start_step_run` span 名称中。 |
| `excludedAttributes` | `array` | `[]` | 要从 span 中排除的 `hatchet.*` 属性键列表。 |

#### Go

导入 `opentelemetry` 包（通常别名为 `hatchetotel`）：

```go
import hatchetotel "github.com/hatchet-dev/hatchet/sdks/go/opentelemetry"
```

创建 instrumentor，然后在 worker 上注册其中间件：

```go
instrumentor, err := hatchetotel.NewInstrumentor()
if err != nil {
    log.Fatalf("failed to create instrumentor: %v", err)
}

worker.Use(instrumentor.Middleware())
```

默认情况下，`NewInstrumentor` 会创建一个 `TracerProvider`，将 span 发送到 Hatchet 引擎的 OTLP collector。

记得在退出时关闭 instrumentor，以刷出剩余的 span：

```go
defer instrumentor.Shutdown(context.Background())
```

### 选项

| 选项 | 说明 |
| --- | --- |
| `hatchetotel.WithTracerProvider(tp)` | 使用自定义的 `*sdktrace.TracerProvider`，而不是新建一个。 |
| `hatchetotel.DisableHatchetCollector()` | 禁用向 Hatchet 引擎的 OTLP collector 发送 trace。 |
| `hatchetotel.WithBatchSpanProcessorOptions(...)` | 为 Hatchet collector 配置 `BatchSpanProcessor`。 |

## Span

默认情况下，Hatchet 会在 task 运行生命周期的以下时点创建 span：

1. **Producer span** —— 在客户端调用触发方法时（例如 `run()`、`runNoWait()`、`push()`、`schedule()`）。
2. **Consumer span** —— 在 worker 处理 task 运行时，例如开始运行 task（`hatchet.start_step_run`）或取消 task（`hatchet.cancel_step_run`）。

### Span 名称

| Span 名称 | 类型 | 说明 |
| --- | --- | --- |
| `hatchet.start_step_run` | `CONSUMER` | worker 开始执行 task。 |
| `hatchet.cancel_step_run` | `CONSUMER` | worker 取消正在运行的 task。 |
| `hatchet.run_workflow` | `PRODUCER` | 客户端触发 workflow 运行。 |
| `hatchet.run_workflows` | `PRODUCER` | 客户端触发多个 workflow 运行。 |
| `hatchet.schedule_workflow` | `PRODUCER` | 客户端创建计划的 workflow 运行。 |
| `hatchet.push_event` | `PRODUCER` | 客户端推送事件。 |
| `hatchet.bulk_push_event` | `PRODUCER` | 客户端批量推送事件。 |
| `hatchet.durable.wait_for` | `INTERNAL` | durable task 等待信号/条件。 |

### Span 属性

所有 span 都包含一个值为 `"hatchet"` 的 `instrumentor` 属性。Consumer span（`hatchet.start_step_run`）包含以下 `hatchet.*` 属性：

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `hatchet.tenant_id` | `string` | task 运行所属的租户 ID。 |
| `hatchet.worker_id` | `string` | 处理该 task 的 worker。 |
| `hatchet.workflow_run_id` | `string` | workflow 运行 ID。 |
| `hatchet.step_run_id` | `string` | task 运行 ID。 |
| `hatchet.step_id` | `string` | task ID。 |
| `hatchet.workflow_name` | `string` | workflow 名称。 |
| `hatchet.action_name` | `string` | action ID（格式：`workflowName:taskName`）。 |
| `hatchet.step_name` | `string` | 人类可读的 task 名称。 |
| `hatchet.retry_count` | `int` | 当前重试次数（从 0 开始计数）。 |
| `hatchet.workflow_id` | `string` | workflow 定义 ID（如果可用）。 |
| `hatchet.workflow_version_id` | `string` | workflow 版本 ID（如果可用）。 |
| `hatchet.parent_workflow_run_id` | `string` | 父 workflow 运行 ID（针对子 workflow）。 |
| `hatchet.child_workflow_index` | `int` | 子 workflow 索引（针对子 workflow）。 |
| `hatchet.child_workflow_key` | `string` | 子 workflow 键（针对子 workflow）。 |

Producer span（`hatchet.run_workflow`）包含 `hatchet.step_name`（被触发的 workflow），成功时还包含 `hatchet.child_workflow_run_id`。

### 上下文传播

所有 SDK 都会：

1. 自动将 W3C `traceparent` 注入到 producer span 的 `additionalMetadata` 中，使 worker 上的 consumer span 成为触发 span 的子 span。
2. 提供 `HatchetAttributeSpanProcessor`，将 `hatchet.*` 属性从父 task 运行 span 传播到该 task 内创建的所有子 span。也就是说，你在 task 函数内创建的任何自定义 span 都会自动携带相同的 `hatchet.*` 属性。
