# 附加元数据（Additional Metadata）

Hatchet 允许你向 event 和 task run 附加任意的键值字符串对，用于过滤、搜索或其他查找目的。这些附加元数据不属于 event 的 payload 或 task 的输入数据，而是提供补充信息，以便更好地组织和检索。

> **Info:** 附加元数据可以添加到 `Runs`、`Scheduled Runs`、`Cron Runs` 和
>   `Events` 上。数据会从父级传播到子级，或从 event 传播到 run。

你可以在推送 event 或触发 task run 时，使用 Hatchet 客户端库附加元数据：

#### Event Push

#### Ruby

```python
hatchet.event.push(
    "user:create",
    {"userId": "1234", "should_skip": False},
    additional_metadata={"source": "api"},  # Arbitrary key-value pair
)
```

#### Tab 2

```typescript
const withMetadata = await hatchet.events.push(
  'user:create',
  {
    test: 'test',
  },
  {
    additionalMetadata: {
      source: 'api', // Arbitrary key-value pair
    },
  }
);
```

#### Tab 3

```go
err = client.Events().Push(
	context.Background(),
	"user:create",
	Input{Message: "hello"},
	hatchet.WithEventMetadata(
		map[string]string{"version": "1.0.0"},
	),
)
if err != nil {
	log.Fatalf("failed to push event: %v", err)
}
```

#### Tab 4

```ruby
HATCHET.event.push(
  "user:create",
  { "userId" => "1234", "should_skip" => false },
  additional_metadata: { "source" => "api" }
)
```

#### Task Run Trigger

#### Ruby

```python
simple.run(
    additional_metadata={"source": "api"},  # Arbitrary key-value pair
)
```

#### Tab 2

```typescript
const withMetadata = simple.run(
  {
    Message: 'HeLlO WoRlD',
  },
  {
    additionalMetadata: {
      source: 'api', // Arbitrary key-value pair
    },
  }
);
```

#### Tab 3

```go
_, err = client.Run(
	context.Background(),
	"my-workflow",
	Input{Message: "hello"},
	hatchet.WithRunMetadata(
		map[string]string{"version": "1.0.0"},
	),
)
if err != nil {
	log.Fatalf("failed to run workflow: %v", err)
}
```

#### Tab 4

```ruby
SIMPLE.run(
  {},
  options: Hatchet::TriggerWorkflowOptions.new(
    additional_metadata: { "source" => "api" }
  )
)
```

## 在控制台中过滤

为 event 或 task run 附加元数据后，这些数据会出现在 Hatchet 控制台的 Event 和 Task Run 列表视图中。你可以使用过滤输入框，根据所附加的元数据键值对来搜索 event 或 task run。

例如，你可以按 `source` 元数据键过滤 event，快速找到来自特定来源或环境的 event。

## 过滤语义

使用 `additional_metadata` 过滤 **run** 时，Hatchet 返回匹配**任意一个**所给键值对（逻辑 `OR`）的 run，而不是全部匹配。

> **Info:** 例如，使用 `{ first_name: "john", last_name: "doe" }` 过滤 run
>   时，返回的 run 其元数据匹配 *`first_name: "john"` 或* `last_name: "doe"`
>   任意一项即可，而不要求两者都匹配。

event 过滤的行为则不同：使用多个 `additional_metadata` 键值对过滤 **event** 时，要求所有键值对都匹配（逻辑 `AND`），因为 event 在底层使用 `JSONB` 包含（containment）查询。

> **Info:** 例如，使用 `{ first_name: "john", last_name: "doe" }` 过滤 event
>   时，只返回元数据*同时*匹配 `first_name: "john"` *和* `last_name: "doe"`
>   的 event。

## 使用场景

附加元数据的一些常见使用场景包括：

- 为 event 或 task run 打上环境信息标签（如 `production`、`staging`、`development`）
- 标明 event 的来源或出处（如 `api`、`webhook`、`manual`）
- 基于业务特定标准对 event 或 task run 进行分类（如 `priority`、`region`、`product`）

利用附加元数据，你可以提升 Hatchet 中 event 和 task run 的组织性、可搜索性和可发现性。
