# Worker 健康检查

Python 和 TypeScript SDK 都允许你启用并 ping 一个健康检查端点，以查看 worker 的状态。

## Python SDK

### 用法

首先，将 `HATCHET_CLIENT_WORKER_HEALTHCHECK_ENABLED` 环境变量设为 `True`。设置后，将提供两个健康检查端点（默认在端口 `8001` 上）：

1. `/health` —— worker 监听器健康时返回 **200**，否则返回 **503**，body 为 `{"status":"HEALTHY"}` 或 `{"status":"UNHEALTHY"}`。
2. `/metrics` —— 指标端点，供 Prometheus 等监控系统使用。

### 自定义端口

你可以通过 `HATCHET_CLIENT_WORKER_HEALTHCHECK_PORT` 环境变量设置自定义端口，例如 `HATCHET_CLIENT_WORKER_HEALTHCHECK_PORT=8002`。

### 事件循环阻塞阈值

如果 worker 监听器进程的事件循环阻塞时间超过某个阈值，`/health` 将返回 **503**。

你可以通过以下变量配置该阈值（单位为秒）：

- `HATCHET_CLIENT_WORKER_HEALTHCHECK_EVENT_LOOP_BLOCK_THRESHOLD_SECONDS`（默认：`5.0`）

#### `/health` 请求示例：

```bash
curl localhost:8001/health

{"status":"HEALTHY"}
```


## TypeScript SDK

设置 `HATCHET_CLIENT_WORKER_HEALTHCHECK_ENABLED=true`（以及可选的 `HATCHET_CLIENT_WORKER_HEALTHCHECK_PORT`，默认 `8001`）以启用 worker 的健康检查服务器。它暴露以下端点：

1. `/health` —— 始终返回 **200**，JSON body 中包含 worker 的状态（`INITIALIZED`、`STARTING`、`HEALTHY` 或 `UNHEALTHY`），例如 `{"status":"HEALTHY"}`。保持无条件返回是为了向后兼容直接检查 body 的消费者 —— 由于状态码本身不反映健康状况，此端点**不适合**用作 Kubernetes 的 `httpGet` 探针。请改用 `/readyz`。
2. `/readyz` —— Kubernetes 风格的就绪探针。仅当 worker 处于 `HEALTHY` 状态（已注册并持有 action listener）时返回 **200**，否则返回 **503**。
3. `/livez` —— Kubernetes 风格的存活探针。只要进程还能响应就始终返回 **200**，与 Hatchet 的连接状况无关 —— 临时处于 `UNHEALTHY` 状态的 worker 应通过 `/readyz` 移出轮转，而不是杀死并重启，因为重启无法解决上游 Hatchet 故障，还会丢失进行中的工作。
4. `/metrics` —— 指标端点，供 Prometheus 等监控系统使用（需要可选的 `prom-client` 依赖）。

#### Kubernetes 探针配置示例

```yaml
readinessProbe:
  httpGet:
    path: /readyz
    port: 8001
livenessProbe:
  httpGet:
    path: /livez
    port: 8001
```
