# 手动释放 Slot

Hatchet 的执行模型为运行 workflow 中的 task 设定了一定数量的可用 slot。当一个 task 运行时，它会占用一个 slot；如果 worker 没有可用 slot，就无法再并发运行更多 task。

在某些情况下，你的 workflow 中可能有一个资源密集型 task，需要独占访问某个共享资源，例如数据库连接或 GPU 计算实例。为了让 workflow 中的其他 task 能够并发运行，你可以在资源密集型 task 完成后、但该 task 还有非资源密集型工作要做（即上传或清理）时，手动释放其 slot。

> **Warning:** 这是一项高级功能，应谨慎使用。手动释放 slot 可能对系统性能和并发
>   产生意外副作用。例如，如果运行该 task 的 worker 挂掉，该 task 不会被重新分配，
>   而是会一直保持运行状态，直到被手动终止。

## 使用手动释放 Slot

你可以在 workflow 中运行中的 task 内，使用 Hatchet 上下文方法 `release_slot` 手动释放 slot：

#### Go

```python
slot_release_workflow = hatchet.workflow(name="SlotReleaseWorkflow")


@slot_release_workflow.task()
def step1(input: EmptyModel, ctx: Context) -> dict[str, str]:
    print("RESOURCE INTENSIVE PROCESS")
    time.sleep(10)

    # 👀 Release the slot after the resource-intensive process, so that other steps can run
    ctx.release_slot()

    print("NON RESOURCE INTENSIVE PROCESS")
    return {"status": "success"}
```

#### Ruby

```go
_ = workflow.NewTask("step1", func(ctx hatchet.Context, _ any) (*StepOutput, error) {
	fmt.Println("RESOURCE INTENSIVE PROCESS")
	time.Sleep(10 * time.Second)

	// Release the slot after the resource-intensive process,
	// so that other steps can run on this worker.
	if releaseErr := ctx.ReleaseSlot(); releaseErr != nil {
		return nil, fmt.Errorf("failed to release slot: %w", releaseErr)
	}

	fmt.Println("NON RESOURCE INTENSIVE PROCESS")

	return &StepOutput{Status: "success"}, nil
})
```

#### Tab 3

```ruby
SLOT_RELEASE_WORKFLOW = HATCHET.workflow(name: "SlotReleaseWorkflow")

SLOT_RELEASE_WORKFLOW.task(:step1) do |input, ctx|
  puts "RESOURCE INTENSIVE PROCESS"
  sleep 10

  # Release the slot after the resource-intensive process, so that other steps can run
  ctx.release_slot

  puts "NON RESOURCE INTENSIVE PROCESS"
  { "status" => "success" }
end
```

在上述示例中，`release_slot()` 方法在资源密集型流程完成后被调用。这样，workflow 中的其他 task 就可以开始执行，而当前 task 继续处理非资源密集型的工作。

> **Info:** 手动释放 slot 并不会终止当前 task。该 task 会继续执行，直到完成或遇到错误。

## 使用场景

手动释放 Slot 的一些常见使用场景包括：

- 执行需要大量 CPU、GPU 或内存资源的数据处理或分析
- 获取锁或信号量以访问共享资源
- 执行在完成部分初始工作后无需阻塞其他 task 的长时间运行任务

通过使用手动释放 Slot，你可以优化 workflow 的并发和资源利用率，让多个 task 在可能的情况下并行运行。
