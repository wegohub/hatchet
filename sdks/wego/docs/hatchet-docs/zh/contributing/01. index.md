# 参与贡献

> **注意：** 本指南

### 环境搭建

1. 启动数据库和队列服务：

```sh
task start-db
```

2. 安装依赖、执行迁移、生成加密密钥并初始化数据库：

```sh
task setup
```

### 启动开发服务器

启动 Hatchet engine、API server、dashboard 和 Prisma studio：

```sh
task start-dev # 如果你想用 tmux 分屏，可用 task start-dev-tmux
```

### 创建并测试 workflow

要创建和测试 workflow，运行 `./examples` 目录下的示例。

你需要将 tenant（`task seed-dev` 命令的输出）添加到每个示例目录的 `.env` 文件中。`./examples/simple` 目录的 `.env` 示例可通过以下方式生成：

```sh
alias get_token='go run ./cmd/hatchet-admin token create --name local --tenant-id 707d0855-80ab-4e1f-a156-f1c4546cbf52'

cat > ./examples/simple/.env <

# 可选
OTEL_EXPORTER_OTLP_HEADERS=<optional-headers>

# 可选
OTEL_EXPORTER_OTLP_ENDPOINT=<collector-url>
```

### CloudKMS

可以用 CloudKMS 生成主加密密钥：

```
gcloud kms keyrings create "development" --location "global"
gcloud kms keys create "development" --location "global" --keyring "development" --purpose "encryption"
gcloud kms keys list --location "global" --keyring "development"
```

从最后一步复制 Key URI，并设置以下环境变量：

```
SERVER_ENCRYPTION_CLOUDKMS_KEY_URI=gcp-kms://projects//locations/global/keyRings/development/cryptoKeys/development
```

在 GCP 中生成一个可对 CloudKMS 执行加密/解密的服务账号，下载服务账号 JSON 文件并通过以下方式设置：

```
SERVER_ENCRYPTION_CLOUDKMS_CREDENTIALS_JSON='{...}'
```

## 已知问题

### Query engine 泄漏

有时热重载后 Prisma 派生的 query engine 不会被杀死。在 OSX 上可以运行 `task kill-query-engines` 来终止 query engine。

编写与数据库交互的 CLI 命令时，务必在数据库配置对象上调用 `.Disconnect`。否则，当你尝试把这些 CLI 命令包装进新命令时，它永远不会退出，例如：

```
export HATCHET_CLIENT_TOKEN="$(go run ./cmd/hatchet-admin token create --tenant-id <tenant>)"
```
