# Events Client

用于与 Hatchet 事件管理 API 交互的 events 客户端。

此类为在 Hatchet 系统中创建和管理事件提供了高层接口。事件创建（push/bulk_push）使用 gRPC，读取操作（list、get 等）使用 REST API。

```ruby
response = hatchet.events.push(
  "user-login",
  { user_id: 123, action: "login" },
  additional_metadata: { ip_address: "192.168.1.1" }
)
```

它在主客户端上以 `hatchet.events` 的形式提供。

方法：

| Name | Description |
| --- | --- |
| `create` | 在 Hatchet 系统中创建一个新事件。 |
| `push` | 向 Hatchet 推送单个事件。 |
| `bulk_push` | 批量创建事件。 |
| `list` | 列出事件并支持过滤选项。 |
| `get` | 按 ID 获取特定事件。 |
| `get_data` | 获取特定事件的事件数据。 |
| `list_keys` | 列出租户可用的事件键。 |
| `cancel` | 取消符合给定条件的事件。 |
| `replay` | 重放符合给定条件的事件。 |

### Functions

#### `create`

在 Hatchet 系统中创建一个新事件。

此方法通过 gRPC 发送事件创建请求。事件会被处理，并可用于工作流触发器和事件驱动自动化。

```ruby
response = hatchet.events.create(
  key: "user-login",
  data: { user_id: 123, action: "login" },
  additional_metadata: { ip_address: "192.168.1.1" }
)
```

参数：

| Name | Type | Description | Default |
| --- | --- | --- | --- |
| `key` | `String` | 事件键/名称。 | _required_ |
| `data` | `Hash` | 事件的负载数据。 | _required_ |
| `additional_metadata` | `Hash \| nil` | 事件的额外元数据。 | `nil` |
| `priority` | `Integer \| nil` | 事件优先级。 | `nil` |
| `scope` | `String \| nil` | 用于事件过滤的范围。 | `nil` |
| `namespace` | `String \| nil` | 覆盖此事件的命名空间。 | `nil` |

返回：

Type, Description

`Object`, 包含所创建事件详细信息的 gRPC 响应。

抛出：

Type, Description

`ArgumentError`, 如果缺少必需参数。
`Hatchet::Error`, 如果 API 请求失败或返回错误。

#### `push`

向 Hatchet 推送单个事件。

```ruby
response = hatchet.events.push(
  "user-signup",
  { user_id: 456, email: "user@example.com" },
  additional_metadata: { source: "web" }
)
```

参数：

| Name | Type | Description | Default |
| --- | --- | --- | --- |
| `event_key` | `String` | 事件键/名称。 | _required_ |
| `payload` | `Hash` | 事件的负载数据。 | _required_ |
| `additional_metadata` | `Hash \| nil` | 事件的额外元数据。 | `nil` |
| `namespace` | `String \| nil` | 覆盖此事件的命名空间。 | `nil` |
| `priority` | `Integer \| nil` | 事件优先级。 | `nil` |

返回：

Type, Description

`Object`, 包含所创建事件详细信息的 gRPC 响应。

抛出：

Type, Description

`Hatchet::Error`, 如果 API 请求失败或返回错误。

#### `bulk_push`

批量创建事件。

```ruby
events_data = [
  { key: "user-signup", data: { user_id: 1 } },
  { key: "user-login", data: { user_id: 1 }, priority: 1 }
]
response = hatchet.events.bulk_push(events_data)
```

参数：

Name, Type, Description, Default

`events`, `Array`, 事件哈希的数组，每个包含 :key、:data，以及可选的 :additional_metadata 和 :priority。, _required_
`namespace`, `String \, nil`, 覆盖所有事件的命名空间。, `nil`

返回：

Type, Description

`Object`, 包含所创建事件的 gRPC 响应。

抛出：

Type, Description

`Hatchet::Error`, 如果 API 请求失败或返回错误。

#### `list`

列出事件并支持过滤选项。

```ruby
events = hatchet.events.list(
  limit: 10,
  since: Time.now - 24 * 60 * 60,
  keys: ["user-signup", "user-login"]
)
```

参数：

| Name | Type | Description | Default |
| --- | --- | --- | --- |
| `offset` | `Integer \| nil` | 分页偏移量。 | `nil` |
| `limit` | `Integer \| nil` | 返回的最大事件数。 | `nil` |
| `keys` | `Array \| nil` | 按事件键过滤。 | `nil` |
| `since` | `Time \| nil` | 过滤此时间之后的事件。 | `nil` |
| `until_time` | `Time \| nil` | 过滤此时间之前的事件。 | `nil` |
| `workflow_ids` | `Array \| nil` | 按工作流 ID 过滤。 | `nil` |
| `workflow_run_statuses` | `Array \| nil` | 按工作流运行状态过滤。 | `nil` |
| `event_ids` | `Array \| nil` | 按特定事件 ID 过滤。 | `nil` |
| `additional_metadata` | `Hash \| nil` | 按额外元数据过滤。 | `nil` |
| `scopes` | `Array \| nil` | 按事件范围过滤。 | `nil` |

返回：

Type, Description

`HatchetSdkRest::V1EventList`, 符合过滤条件的事件列表。

抛出：

Type, Description

`Hatchet::Error`, 如果 API 请求失败或返回错误。
