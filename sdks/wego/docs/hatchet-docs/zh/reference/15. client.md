# Hatchet Python SDK 参考文档

这是 Python SDK 参考文档，记录了与 Hatchet 资源交互时可用的方法。请查看[用户指南](<../v1/01. get-started（入门）/01. index.md>)以了解如何运行你的第一批任务。

## Hatchet Python 客户端

与 Hatchet SDK 交互的主客户端。

该类提供对各种客户端接口和实用工具方法的访问，
用于操作 Hatchet 的 worker、workflow、task 以及我们的各类功能客户端。

方法：

| 名称 | 描述 |
| --- | --- |
| `worker` | 创建一个用于运行 workflow 的 Hatchet worker。 |
| `workflow` | 定义一个 Hatchet workflow，随后可以在其上声明 `task`，并对其进行 `run`、`schedule` 等操作。 |
| `task` | 一个装饰器，将函数转换为作为 workflow 一部分运行的独立 Hatchet task。 |
| `durable_task` | 一个装饰器，将函数转换为作为 workflow 一部分运行的独立 Hatchet _durable_（持久）task。 |
| `from_embedded` | 在本地运行完整的 Hatchet 引擎，并返回连接到该引擎的客户端。 |
| `stop_embedded` | 优雅地停止由 `Hatchet.from_embedded()` 启动的嵌入式引擎。 |
| `aio_stop_embedded` | `stop_embedded` 的异步版本。 |

### 属性

#### `cron`

cron 客户端用于管理 Hatchet 中的 cron workflow。

#### `event`

事件客户端，可用于向 Hatchet 推送事件。

#### `logs`

日志客户端，用于与 Hatchet 的日志 API 交互。

#### `metrics`

指标客户端，用于从 Hatchet 的指标 API 读取指标。

#### `rate_limits`

速率限制客户端，是 Hatchet gRPC API 的封装，让你更方便地在 Hatchet 中操作速率限制。

#### `runs`

运行客户端，用于与 Hatchet 中的 task 运行和 workflow 运行交互。

#### `scheduled`

计划客户端，用于管理 Hatchet 中的计划（scheduled）workflow。

#### `workers`

worker 客户端，用于以编程方式管理 Hatchet 中的 worker。

#### `workflows`

workflow 客户端，用于以编程方式管理 Hatchet 中的 workflow。

请注意，workflow 是声明本身，而_不是_单个运行。如果你要查找的是运行，请改用 `RunsClient`。

#### `tenant_id`

你当前操作的租户 ID。

#### `namespace`

你当前交互的命名空间。

### 函数

#### `worker`

创建一个用于运行 workflow 的 Hatchet worker。

参数：

| 名称 | 类型 | 描述 | 默认值 |
| --- | --- | --- | --- |
| `name` | `str` | worker 的名称。 | _必填_ |
| `slots` | `int \| None` | 标准 task 的 slot 数量。 | `None` |
| `durable_slots` | `int \| None` | durable task 的 slot 数量。 | `None` |
| `labels` | `dict[str, str \| int] \| None` | 分配给该 worker 的标签字典。更多细节请查看 affinity 与 worker 标签的相关示例。 | `None` |
| `workflows` | `list[BaseWorkflow[Any]] \| None` | 要注册到该 worker 上的 workflow 列表，相当于对每个调用 `register_workflow` 或对所有调用 `register_workflows` 的简写形式。 | `None` |
| `lifespan` | `LifespanFn \| None` | 在 worker 上运行的 lifespan 函数。该函数会在 worker 启动时被调用，可用于执行任何初始化或清理任务。 | `None` |

返回：

类型, 描述

`Worker`, 创建的 `Worker` 对象，它暴露一个 `start` 实例方法，可调用该方法来启动 worker。

异常：

类型, 描述

`TypeError`, 如果 `workflows` 中的任一项不是 `Workflow` 或 `Standalone` 的实例——这两者是可传给 worker 的 workflow 对象类型。这是为了捕获一个常见错误：用户传入了像 `Workflow.task` 这样的 task 声明方法的返回结果，而不是 workflow 对象本身。

#### `workflow`

定义一个 Hatchet workflow，随后可以在其上声明 `task`，并对其进行 `run`、`schedule` 等操作。

参数：

| 名称 | 类型 | 描述 | 默认值 |
| --- | --- | --- | --- |
| `name` | `str` | workflow 的名称。 | _必填_ |
| `description` | `str \| None` | workflow 的描述。 | `None` |
| `input_validator` | `type[TWorkflowInput] \| None` | 一个 Pydantic 模型，用作 workflow 中各 task `input` 的校验器。如果未提供校验器，默认在底层使用 `EmptyModel`。`EmptyModel` 是一个未指定任何字段、且 `extra` 配置项设为 `"allow"` 的 Pydantic 模型。 | `None` |
| `on_events` | `list[str] \| None` | workflow 的事件触发器列表——即会导致 workflow 运行的事件。 | `None` |
| `on_crons` | `list[str] \| None` | workflow 的 cron 触发器列表。 | `None` |
| `cron_input` | `TWorkflowInput \| None` | 可选的输入，提供给由 workflow 的 `on_crons` 计划触发的运行。应为该 workflow 输入模型的实例。 | `None` |
| `version` | `str \| None` | workflow 的版本。 | `None` |
| `sticky` | `StickyStrategy \| None` | workflow 的 sticky 策略。 | `None` |
| `default_priority` | `int \| Priority` | workflow 的优先级。值越高，该 workflow 在调度时越优先于其他低优先级的 workflow。 | `LOW` |
| `concurrency` | `int \| ConcurrencyExpression \| Sequence[ConcurrencyExpression] \| None` | 控制该 workflow 并发设置的并发对象。如果传入整数，它会被视为使用 `GROUP_ROUND_ROBIN` 策略的常量并发限制，即任意时刻该 task 最多只有 `N` 个运行可以执行。 | `None` |
| `task_defaults` | `TaskDefaults` | 一个 `TaskDefaults` 对象，控制该 workflow 的默认 task 设置。 | `TaskDefaults()` |
| `default_filters` | `list[DefaultFilter] \| None` | 创建 workflow 时一并创建的过滤器列表。注意，这是一个辅助功能，让你可以"声明式"地创建过滤器，而无需在 workflow 创建之后再发起单独的 API 调用来创建它们。 | `None` |
| `default_additional_metadata` | `JSONSerializableMapping \| None` | 默认附加到该 workflow 每次运行上的额外元数据字典。 | `None` |
| `idempotency` | `TTLBasedIdempotencyConfig \| StatusBasedIdempotencyConfig \| None` | 可选的幂等配置，控制 Hatchet 如何判断该 workflow 的两次运行在去重和幂等执行意义上是否"相同"。 | `None` |

返回：

类型, 描述

`Workflow[EmptyModel] \, Workflow[TWorkflowInput]`, 创建的 `Workflow` 对象，可用于声明 task、运行 workflow 等。

#### `task`

一个装饰器，将函数转换为作为 workflow 一部分运行的独立 Hatchet task。

参数：

| 名称 | 类型 | 描述 | 默认值 |
| --- | --- | --- | --- |
| `name` | `str \| None` | task 的名称。如果未指定，默认为被 `task` 装饰器包装的函数的名称。 | `None` |
| `description` | `str \| None` | task 的可选描述。 | `None` |
| `input_validator` | `type[TWorkflowInput] \| None` | 一个 Pydantic 模型，用作该 task 输入的校验器。如果未提供校验器，默认使用 `EmptyModel`。 | `None` |
| `on_events` | `list[str] \| None` | task 的事件触发器列表——即会导致 task 运行的事件。 | `None` |
| `on_crons` | `list[str] \| None` | task 的 cron 触发器列表。 | `None` |
| `cron_input` | `TWorkflowInput \| None` | 可选的输入，提供给由该 task 的 `on_crons` 计划触发的运行。应为该 task 输入模型的实例。 | `None` |
| `version` | `str \| None` | task 的版本。 | `None` |
| `sticky` | `StickyStrategy \| None` | task 的 sticky 策略。 | `None` |
| `default_priority` | `int \| Priority` | task 的优先级。值越高，该 task 在调度时越优先。 | `LOW` |
| `concurrency` | `int \| ConcurrencyExpression \| Sequence[ConcurrencyExpression] \| None` | 控制该 task 并发设置的并发对象。如果传入整数，它会被视为使用 `GROUP_ROUND_ROBIN` 策略的常量并发限制，即任意时刻该 task 最多只有 `N` 个运行可以执行。 | `None` |
| `schedule_timeout` | `Duration` | 调度该 task 所允许的最长时间。 | `timedelta(minutes=5)` |
| `execution_timeout` | `Duration` | 执行该 task 所允许的最长时间。 | `timedelta(seconds=60)` |
| `retries` | `int` | task 失败前重试的次数。 | `0` |
| `rate_limits` | `list[RateLimit] \| None` | 该 task 的速率限制配置列表。 | `None` |
| `desired_worker_labels` | `dict[str, DesiredWorkerLabel] \| list[DesiredWorkerLabel] \| None` | 期望 worker 标签字典，决定该 task 应被分配给哪个 worker。 | `None` |
| `backoff_factor` | `float \| None` | 控制重试中指数退避的退避系数。 | `None` |
| `backoff_max_seconds` | `int \| None` | 允许指数退避重试持续的最长秒数。 | `None` |
| `default_filters` | `list[DefaultFilter] \| None` | 创建 task 时一并创建的过滤器列表。注意，这是一个辅助功能，让你可以"声明式"地创建过滤器，而无需在 task 创建之后再发起单独的 API 调用来创建它们。 | `None` |
| `default_additional_metadata` | `JSONSerializableMapping \| None` | 默认附加到该 task 每次运行上的额外元数据字典。 | `None` |
| `slot_cost` | `int \| None` | 该 task 消耗的默认 worker slot 数。普通 task 消耗一个。对于需要更多内存或 CPU 的 task，可以设得更高，这样 worker 同时运行的该 task 数就会更少。单个 worker 必须有这么多空闲 slot 才能运行它。 | `None` |
| `idempotency` | `TTLBasedIdempotencyConfig \| StatusBasedIdempotencyConfig \| None` | 可选的幂等配置，控制 Hatchet 如何判断该 task 的两次运行在去重和幂等执行意义上是否"相同"。 | `None` |

返回：

类型, 描述

`Callable[[Callable[Concatenate[EmptyModel, Context, P], R \, CoroutineLike[R]]], Standalone[EmptyModel, R]] \, Callable[[Callable[Concatenate[TWorkflowInput, Context, P], R \, CoroutineLike[R]]], Standalone[TWorkflowInput, R]]`, 一个创建 `Standalone` task 对象的装饰器。

#### `from_embedded` `classmethod`

在本地运行完整的 Hatchet 引擎，并返回连接到该引擎的客户端。
无需 API token，也无需 Docker，因此这是本地开发环境下运行 Hatchet 的最快方式。
引擎以 hatchet-embedded 边车（sidecar）进程运行（首次使用时下载），
默认启动自带的 Postgres；在 `config.embedded` 上设置 `database_url`
即可改用你自己的 Postgres。你可以在[文档](<../v1/01. get-started（入门）/05. embedded.md>)中了解更多关于嵌入式引擎的内容。

参数：

名称, 类型, 描述, 默认值

`config`, `ClientConfig \, None`, 要使用的基础客户端配置；连接字段（token、tenant、地址、TLS）会被覆盖为指向嵌入式引擎。设置 `config.embedded`（一个 `EmbeddedHatchetConfig`）可配置嵌入式引擎本身（例如数据库 URL、端口）。, `None`

返回：

类型, 描述

`Hatchet`, 连接到嵌入式引擎的 Hatchet 客户端实例。

#### `stop_embedded`

优雅地停止由 `Hatchet.from_embedded()` 启动的嵌入式引擎。

阻塞直至引擎（包括其自带的 Postgres）完全退出。嵌入式引擎是进程级唯一的：
本进程中通过 `Hatchet.from_embedded()` 创建的每个客户端都共享同一个引擎。
请在进程退出前调用此方法，以免引擎的关闭输出打印在你的程序返回之后。
如果本进程中没有正在运行的嵌入式引擎，则此方法为空操作（no-op）。

#### `aio_stop_embedded`

`stop_embedded` 的异步版本。

在不阻塞事件循环的情况下优雅地停止嵌入式引擎，并在引擎完全退出后返回。
如果本进程中没有正在运行的嵌入式引擎，则此方法为空操作（no-op）。

## 嵌入式引擎配置

基类：`BaseSettings`

由 `Hatchet.from_embedded()` 启动的嵌入式 Hatchet 引擎的配置。
请在 `ClientConfig.embedded` 上设置。每个字段也可以通过以
`HATCHET_CLIENT_EMBEDDED_` 为前缀的环境变量来设置，
例如 `HATCHET_CLIENT_EMBEDDED_DATABASE_URL`。
你可以在[文档](<../v1/01. get-started（入门）/05. embedded.md>)中了解更多关于嵌入式引擎的内容。

字段：

| 名称 | 类型 | 描述 |
| --- | --- | --- |
| `version` | `str \| None` | 要下载的 hatchet-embedded 发行版标签。默认为最新发行版。标签对应于边车内置的 Hatchet 引擎版本，因此固定该值即固定了引擎版本。 |
| `binary_path` | `str \| None` | 已存在的边车二进制文件的路径。设置后将跳过下载。 |
| `checksum` | `str \| None` | 边车二进制文件预期的 sha256 十六进制摘要。设置后，它会取代发行版的 checksums.txt 作为信任锚，这样即使发行渠道被攻破也无法替换二进制文件。请与 `version` 一起固定。 |
| `database_url` | `str \| None` | 要使用的已有 Postgres 的连接字符串，替代自带的 Postgres。 |
| `postgres_data_dir` | `str \| None` | 存放自带 Postgres 运行时和数据的目录。默认为根据工作目录派生的按项目划分的目录。 |
| `grpc_port` | `int \| None` | 覆盖嵌入式引擎 gRPC 服务器监听的端口。 |
| `api_port` | `int \| None` | 覆盖嵌入式 REST API 监听的端口。 |
| `start_api` | `bool` | 设为 `False` 时只启动引擎和 gRPC 服务器，不启动 REST API。 |
| `run_migrations` | `bool` | 设为 `False` 时跳过启动时运行数据库迁移。 |
| `rabbitmq_url` | `str \| None` | 用作消息队列的 RabbitMQ 实例的连接字符串，替代 Postgres。 |
| `log_level` | `str \| None` | 嵌入式引擎的日志级别。 |
| `ready_timeout_seconds` | `float` | 等待嵌入式引擎就绪的秒数，超时则抛出错误。默认为 300 秒。 |
