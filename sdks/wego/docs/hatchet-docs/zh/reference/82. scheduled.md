# Scheduled Client

用于管理 Hatchet 中计划工作流的 scheduled 客户端。

此类为创建、删除、更新、批量操作、列出和获取计划工作流运行提供了高层接口。

```ruby
scheduled = hatchet.scheduled.create(
  workflow_name: "my-workflow",
  trigger_at: Time.now + 3600,
  input: { key: "value" },
  additional_metadata: { source: "api" }
)
```

它在主客户端上以 `hatchet.scheduled` 的形式提供。

方法：

| Name | Description |
| --- | --- |
| `create` | 创建一个新的计划工作流运行。 |
| `delete` | 按 ID 删除计划工作流运行。 |
| `update` | 按 ID 重新安排计划工作流运行。 |
| `bulk_delete` | 批量删除计划工作流运行。 |
| `bulk_update` | 批量重新安排计划工作流运行。 |
| `list` | 根据提供的过滤条件列出计划工作流。 |
| `get` | 按 ID 获取特定的计划工作流。 |

### Functions

#### `create`

创建一个新的计划工作流运行。

重要：如果可能，优先使用 Workflow.run 来触发工作流。此方法仅作为兜底手段。

```ruby
scheduled = hatchet.scheduled.create(
  workflow_name: "my-workflow",
  trigger_at: Time.now + 3600,
  input: { key: "value" },
  additional_metadata: { source: "api" }
)
```

参数：

| Name | Type | Description | Default |
| --- | --- | --- | --- |
| `workflow_name` | `String` | 要调度的工作流的名称（会应用命名空间） | _required_ |
| `trigger_at` | `Time` | 运行应被触发的日期时间。 | _required_ |
| `input` | `Hash` | 计划工作流的输入数据。 | `{}` |
| `additional_metadata` | `Hash` | 与未来运行关联的额外元数据。 | `{}` |

返回：

Type, Description

`Object`, 创建的计划工作流实例。

抛出：

Type, Description

`HatchetSdkRest::ApiError`, 如果 API 请求失败。

#### `delete`

按 ID 删除计划工作流运行。

```ruby
hatchet.scheduled.delete("scheduled-123")
```

参数：

Name, Type, Description, Default

`scheduled_id`, `String`, 要删除的计划工作流运行的 ID。, _required_

抛出：

Type, Description

`HatchetSdkRest::ApiError`, 如果 API 请求失败。

#### `update`

按 ID 重新安排计划工作流运行。

注意：如果计划运行已经触发，或者它是通过代码定义（而非通过 API）创建的，服务器可能会拒绝重新安排。

```ruby
hatchet.scheduled.update("scheduled-123", trigger_at: Time.now + 7200)
```

参数：

Name, Type, Description, Default

`scheduled_id`, `String`, 要重新安排的计划工作流运行的 ID。, _required_
`trigger_at`, `Time`, 运行应被触发的新日期时间。, _required_

返回：

Type, Description

`Object`, 更新后的计划工作流实例。

抛出：

Type, Description

`HatchetSdkRest::ApiError`, 如果 API 请求失败。

#### `bulk_delete`

批量删除计划工作流运行。

请提供 scheduled_ids（显式列表）或一个或多个过滤字段。

参数：

| Name | Type | Description | Default |
| --- | --- | --- | --- |
| `scheduled_ids` | `Array \| nil` | 要删除的计划工作流运行 ID 的显式列表。 | `nil` |
| `workflow_id` | `String \| nil` | 按工作流 ID 过滤。 | `nil` |
| `parent_workflow_run_id` | `String \| nil` | 按父工作流运行 ID 过滤。 | `nil` |
| `parent_step_run_id` | `String \| nil` | 按父步骤运行 ID 过滤。 | `nil` |
| `statuses` | `Array \| nil` | 按计划运行状态过滤（警告：可能不被支持） | `nil` |
| `additional_metadata` | `Hash \| nil` | 按额外元数据键值对过滤。 | `nil` |

返回：

Type, Description

`Object`, 批量删除响应，包含已删除的 ID 和逐条目的错误。

抛出：

Type, Description

`ArgumentError`, 如果既未提供 scheduled_ids 也未提供任何过滤字段。
`HatchetSdkRest::ApiError`, 如果 API 请求失败。

#### `bulk_update`

批量重新安排计划工作流运行。

```ruby
hatchet.scheduled.bulk_update([
  { id: "scheduled-1", trigger_at: Time.now + 3600 },
  { id: "scheduled-2", trigger_at: Time.now + 7200 }
])
```

参数：

Name, Type, Description, Default

`updates`, `Array`, 包含 :id 和 :trigger_at 键的哈希数组。, _required_

返回：

Type, Description

`Object`, 批量更新响应，包含已更新的 ID 和逐条目的错误。

抛出：

Type, Description

`HatchetSdkRest::ApiError`, 如果 API 请求失败。

#### `list`

根据提供的过滤条件列出计划工作流。

```ruby
scheduled = hatchet.scheduled.list(limit: 10, workflow_id: "wf-1")
```

参数：

| Name | Type | Description | Default |
| --- | --- | --- | --- |
| `offset` | `Integer \| nil` | 分页使用的偏移量。 | `nil` |
| `limit` | `Integer \| nil` | 返回的最大计划工作流数量。 | `nil` |
| `workflow_id` | `String \| nil` | 用于过滤的工作流 ID。 | `nil` |
| `parent_workflow_run_id` | `String \| nil` | 用于过滤的父工作流运行 ID。 | `nil` |
| `statuses` | `Array \| nil` | 用于过滤的状态列表。 | `nil` |
| `additional_metadata` | `Hash \| nil` | 用于过滤的额外元数据。 | `nil` |
| `order_by_field` | `String \| nil` | 结果排序所依据的字段。 | `nil` |
| `order_by_direction` | `String \| nil` | 结果排序的方向。 | `nil` |

返回：

Type, Description

`Object`, 符合所提供过滤条件的计划工作流列表。

抛出：

Type, Description

`HatchetSdkRest::ApiError`, 如果 API 请求失败。
