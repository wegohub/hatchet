# Runnables（可运行对象）

Hatchet SDK 中的 `Runnables` 是可以被运行的东西，即 task 和 workflow。你会遇到的两种主要 runnable 类型是：

- `Workflow`，允许你定义 task 并调用所有 run、schedule 等方法
- `Standalone`，由 `hatchet.task` 返回的单个 task，可被运行、调度等

## Workflow

基类：`BaseWorkflow[TWorkflowInput]`

一个 Hatchet workflow，允许你定义要运行的 task 并对该 workflow 执行操作。

Hatchet 中的 workflow 表示可被触发、调度或按 cron 计划运行的协调式工作单元。
每个 workflow 可以包含多个 task，这些 task 可以组成依赖关系（DAG），
并具有自定义的重试行为、超时、并发控制等。

示例：

```python
from pydantic import BaseModel
from hatchet_sdk import Hatchet

class MyInput(BaseModel):
    name: str

hatchet = Hatchet()
workflow = hatchet.workflow("my-workflow", input_type=MyInput)

@workflow.task()
def greet(input, ctx):
    return f"Hello, {input.name}!"

# Run the workflow
result = workflow.run(MyInput(name="World"))
```

Workflow 支持多种执行模式，包括：

- 使用 `run()` 或 `aio_run()` 的一次性执行
- 使用 `schedule()` 的计划执行
- 使用 `create_cron()` 的基于 cron 的周期性执行
- 使用 `run_many()` 的批量操作

workflow 中的 task 可以通过 `@workflow.task()` 或 `@workflow.durable_task()` 装饰器定义，
并可以组成复杂的依赖模式。

### 函数

#### `task`

一个装饰器，将函数转换为作为 workflow 一部分运行的 Hatchet task。

参数：

| 名称 | 类型 | 描述 | 默认值 |
| --- | --- | --- | --- |

| `retries` | `int` | task 失败前重试的次数。 | `0` |
| `rate_limits` | `list[RateLimit] \| None` | 该 task 的速率限制配置列表。 | `None` |
| `desired_worker_labels` | `dict[str, DesiredWorkerLabel] \| list[DesiredWorkerLabel] \| None` | 期望 worker 标签字典，决定该 task 应被分配给哪个 worker。更多细节请查看 affinity 与 worker 标签的相关文档和示例。 | `None` |

| `backoff_max_seconds` | `int \| None` | 允许指数退避重试持续的最长秒数。 | `None` |
| `concurrency` | `int \| Sequence[ConcurrencyExpression] \| None` | 该 task 的并发表达式列表。如果传入整数，它会被视为使用 `GROUP_ROUND_ROBIN` 策略的常量并发限制，即任意时刻该 task 最多只有 `N` 个运行可以执行。 | `None` |
| `wait_for` | `list[Condition \| OrGroup] \| None` | task 运行前必须满足的条件列表。 | `None` |
| `skip_if` | `list[Condition \| OrGroup] \| None` | 条件列表，如果满足，将导致该 task 被跳过。 | `None` |

类型, 描述

`Callable[[Callable[Concatenate[TWorkflowInput, Context, P], R \, CoroutineLike[R]]], Task[TWorkflowInput, R]]`, 一个创建 `Task` 对象的装饰器。

异常：

类型, 描述

`ValueError`, 如果 `slot_cost` 不是正数。

#### `batch_task`

.. note::
**Preview:** 此功能处于 beta 阶段，在未来的版本中可能会发生变化。

一个装饰器，将函数转换为作为 workflow 一部分运行的 Hatchet _batch_（批处理）task。

batch task 会缓冲单次执行，直到 Hatchet 刷新批次（达到批次大小或刷新间隔到达），
然后以 step run ID 为键，将所有缓冲的输入一次性传给处理函数调用。

处理函数必须返回一个将每个 step run ID 映射到其输出的字典，或者使用 `broadcast_output` 向所有调用点返回相同的结果。

#### `run`

同步运行 workflow 并等待其完成。

该方法触发一次 workflow 运行，阻塞直至完成，并返回最终结果。

参数：

| 名称 | 类型 | 描述 | 默认值 |
| --- | --- | --- | --- |
| `input` | `TWorkflowInput` | workflow 的输入数据，必须与 workflow 的输入类型匹配。 | `cast(TWorkflowInput, EmptyModel())` |
| `options` | `TriggerWorkflowOptions \| None` | 已弃用。workflow 执行的额外选项。请改用其他关键字参数。 | `None` |
| `wait_for_result` | `bool` | 如果为 True，阻塞直至完成并返回结果。如果为 False，立即返回 WorkflowRunRef。 | `True` |
| `child_key` | `str \| None` | 用于对子 workflow 运行去重的可选键。 | `None` |
| `additional_metadata` | `JSONSerializableMapping \| None` | 附加到该 workflow 运行上的额外元数据。 | `None` |
| `priority` | `int \| None` | workflow 运行的优先级。 | `None` |
| `sticky` | `bool` | 该 workflow 运行是否使用 sticky 调度。 | `False` |

| `desired_worker_labels` | `list[DesiredWorkerLabel] \| None` | 用于 worker affinity 的期望 worker 标签列表。 | `None` |
