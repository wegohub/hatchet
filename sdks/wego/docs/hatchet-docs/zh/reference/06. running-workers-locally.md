# 在本地运行 Worker

Hatchet CLI 提供 `hatchet worker` 系列命令，用于为开发和测试目的在本地运行 Hatchet worker。

## 设置 hatchet.yaml 文件

> **提示：** 如果你已经使用 `hatchet quickstart` 创建了项目，项目目录中已经为你
>   生成了 `hatchet.yaml` 文件。

`hatchet worker` 命令依赖 `hatchet.yaml` 配置文件来定义 worker 设置。你可以在项目目录中创建一个如下所示的 `hatchet.yaml` 文件（你需要根据自己项目的配置调整 `preCmds` 和 `runCmd` 字段）：

#### Python

```yaml
dev:
  preCmds: ["poetry install"]
  runCmd: "poetry run python src/worker.py"
  files:
    - "**/*.py"
    - "!**/__pycache__/**"
    - "!**/.venv/**"
  reload: true
```

#### Typescript

```yaml
dev:
  preCmds: ["pnpm install"]
  runCmd: "pnpm start"
  files:
    - "**/*.ts"
    - "!**/node_modules/**"
  reload: true
```

#### Go

```yaml
dev:
  preCmds: ["go mod download"]
  runCmd: "go run ./cmd/worker"
  files:
    - "**/*.go"
  reload: true
```

## 运行 worker

设置好 `hatchet.yaml` 文件后，你可以使用以下命令在本地运行 worker：

```sh
hatchet worker dev
```

要使用特定 profile 运行 worker，可以运行：

```sh
hatchet worker dev --profile <profile-name>
```

### 禁用自动重载

如果你希望 worker 在文件变更时不自动重载，可以将 `hatchet.yaml` 文件中的 `dev.reload` 字段设为 `false`：

```yaml
dev:
  reload: false
```

或者在运行 worker 时传递 `--no-reload` 参数：

```sh
hatchet worker dev --no-reload
```

### 覆盖运行命令

你可以使用 `--run-cmd` 参数覆盖 `hatchet.yaml` 文件中指定的 `runCmd`：

```sh
hatchet worker dev --run-cmd "npm run dev"
```
