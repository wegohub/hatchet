# Runnables

Hatchet Ruby SDK 中的 Runnables 指可以被运行的对象，即任务和工作流。你会遇到的两种主要 runnable 类型是：

- `Hatchet::Workflow`，让你可以定义任务并调用所有运行、调度等方法
- `Hatchet::Task`，由 `hatchet.task`（独立任务）或 `workflow.task` 返回的单个任务，可以被运行、调度等

不等待结果的触发方法会返回运行引用——`WorkflowRunRef` 和 `TaskRunRef`——它们也在下文中记录。

## Workflow

表示由一个或多个按 DAG 排列的任务组成的工作流定义。

```ruby
wf = hatchet.workflow(name: "MyWorkflow")
step1 = wf.task(:step1) { |input, ctx| { "value" => 42 } }
wf.task(:step2, parents: [step1]) { |input, ctx|
  { "result" => ctx.task_output(step1)["value"] + 1 }
}
```

#### `batch_task`

在此工作流中定义一个批量任务。

批量任务会缓冲并发运行，直到 Hatchet 刷新该批次（达到大小上限或到达刷新间隔），然后以所有缓冲输入（按每次运行的任务运行外部 ID 作为键）调用一次代码块。代码块必须返回一个将每个 ID 映射到其输出的 Hash，或者在批量配置上使用 `broadcast_output` 将相同结果返回给所有调用方。批量任务的 retries 始终强制为 0。

预览：批量任务目前处于 beta 阶段，在未来的版本中可能会发生变化。

参数：

| Name | Type | Description | Default |
| --- | --- | --- | --- |
| `name` | `Symbol \| String` | 任务名称。 | _required_ |
| `batch` | `Hatchet::BatchTaskConfig` | 批量配置。 | _required_ |
| `**opts` | `Hash` | 转发给 `task` 的其他任务选项。 | `{}` |

返回：

Type, Description

`Task`, 创建的批量任务。

## Task

表示工作流中的一个任务（或一个独立任务）。

任务是 Hatchet 中工作的基本单元。它们可以作为工作流的一部分定义，也可以作为独立任务定义。每个任务都有一个执行任务逻辑的代码块，接收工作流输入和一个上下文对象。

```ruby
step1 = workflow.task(:step1) { |input, ctx| { "result" => "done" } }
```

```ruby
task = hatchet.task(name: "my_task") { |input, ctx| { "result" => "done" } }
```

### Methods

| Name | Description |
| --- | --- |
| `run` | 同步运行此任务（或其所属工作流）。 |
| `run_no_wait` | 运行此任务，不等待结果。 |
| `run_many` | 批量运行此任务的多个实例。 |
| `run_many_no_wait` | 批量运行多个实例，不等待结果。 |
| `create_bulk_run_item` | 创建供 run_many 使用的批量运行条目。 |
| `mock_run` | 在单元测试模式下以模拟上下文执行任务。 |
`id`

## WorkflowRunRef

正在运行的工作流的引用，由 `Workflow#run_no_wait` 返回。

结果是完整的、以任务 readable_id 为键的工作流级输出，例如 `{"step1" => {...}, "step2" => {...}}`。

```ruby
ref = workflow.run_no_wait(input)
result = ref.result  # blocks until complete
```

### Methods

Name, Description

`result`, 阻塞直至工作流运行完成并返回结果。

### Attributes

#### `workflow_run_id`

工作流运行 ID。

返回：

Type, Description

`String`, 工作流运行 ID。

### Functions

#### `result`

阻塞直至工作流运行完成并返回结果。

可用时使用池化的 gRPC `SubscribeToWorkflowRuns` 监听器，否则回退到 gRPC `GetRunDetails` 轮询。

返回：

Type, Description

`Hash`, 以任务 readable_id 为键的工作流运行输出。

抛出：

Type, Description

`Hatchet::FailedRunError`, 如果工作流运行失败。

## TaskRunRef

正在运行的独立任务的引用，由 `Task#run_no_wait` 返回。

包装一个 `WorkflowRunRef`，并自动从工作流级结果中提取该任务特定的输出。对于名为 "my_task" 的任务，调用 `result` 直接返回任务输出（例如 `{"value" => 42}`），而不是完整的按键输出（`{"my_task" => {"value" => 42}}`）。

```ruby
ref = my_task.run_no_wait(input)
output = ref.result  # => {"value" => 42}
```

### Methods

Type, Description

抛出：

Type, Description
