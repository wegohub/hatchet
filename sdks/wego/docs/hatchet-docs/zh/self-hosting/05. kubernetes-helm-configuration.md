# 配置 Helm Chart

## 共享配置

对于 `hatchet-stack` 和 `hatchet-ha` Helm chart，`values.yaml` 文件中的 `sharedConfig` 对象允许你为所有后端服务配置共享设置。默认值如下：

```yaml
sharedConfig:
  # you can disable shared config by setting this to false
  enabled: true

  # these are the most commonly configured values
  serverUrl: "http://localhost:8080"
  serverAuthCookieDomain: "localhost:8080" # the domain for the auth cookie
  serverAuthCookieInsecure: "t" # allows cookies to be set over http
  serverAuthSetEmailVerified: "t" # automatically sets email_verified to true for all users
  serverAuthBasicAuthEnabled: "t" # allows login via basic auth (email/password)
  grpcBroadcastAddress: "localhost:7070" # the endpoint for the gRPC server, exposed via the `grpc` service
  grpcInsecure: "true" # allows gRPC to be served over http
  defaultAdminEmail: "admin@example.com" # in exposed/production environments, change this to a valid email
  defaultAdminPassword: "Admin123!!" # in exposed/production environments, change this to a secure password

  # you can set additional environment variables here, which will override any defaults
  env: {}
```

### 网络

- **`sharedConfig.serverUrl`**（默认：`"http://localhost:8080"`）：指定服务器的基础 URL。该 URL 应为 Hatchet API 服务器的对外公开 URL（通常与 Hatchet 前端一起捆绑在反向代理之后）。

- **`sharedConfig.grpcBroadcastAddress`**（默认：`"localhost:7070"`）：定义 gRPC 服务器端点的地址，该端点通过 `grpc` 服务对外暴露。

- **`sharedConfig.grpcInsecure`**（默认：`"true"`）：设为 `true` 时，允许 gRPC 服务器通过 HTTP 而非 HTTPS 提供服务。仅限非生产环境使用。

### 认证

- **`sharedConfig.serverAuthCookieDomain`**（默认：`"localhost:8080"`）：指定认证 cookie 的域。部署到生产环境时应设置为相应的域。

- **`sharedConfig.serverAuthCookieInsecure`**（默认：`"t"`）：如果设为 `"t"`，允许通过 HTTP 设置认证 cookie，适用于本地开发。生产环境请使用安全设置。

- **`sharedConfig.serverAuthSetEmailVerified`**（默认：`"t"`）：自动将所有用户的 `email_verified` 设为 `true`。适用于无需邮箱验证的测试环境。

- **`sharedConfig.serverAuthBasicAuthEnabled`**（默认：`"t"`）：为用户启用基本认证（使用邮箱和密码）。如果系统需要支持用户通过邮箱/密码登录，应启用此项。

- **`sharedConfig.defaultAdminEmail`**（默认：`"admin@example.com"`）：指定默认管理员账户的邮箱。部署到生产环境时请改为有效的邮箱。

- **`sharedConfig.defaultAdminPassword`**（默认：`"Admin123!!"`）：定义默认管理员账户的密码。生产部署时应改为强密码。

### 其他环境变量

你可以使用 `env` 对象为后端服务设置其他环境变量。例如：

```yaml
sharedConfig:
  env:
    MY_ENV_VAR: "my-value"
```

这会为所有后端服务设置环境变量 `MY_ENV_VAR` 为 `"my-value"`。这些值将覆盖服务的任何默认环境设置。

## 凭据与密钥生成

### Setup Job

quickstart job 会将 Hatchet 的加密密钥和认证密钥引导写入一个 Kubernetes Secret（`hatchet-config`）。它位于 `hatchet-api` 子 chart 中，因此在 `hatchet-stack` 和 `hatchet-ha` chart 中通过 `api` 别名进行配置，并且默认启用：

```yaml
api:
  quickstartJob:
    enabled: true
```

### Worker Token Job

worker token job 会在 engine 运行后生成一个客户端 token。与 quickstart job 一样，它位于 `hatchet-api` 子 chart 中：

```yaml
api:
  workerTokenJob:
    enabled: true
```

该 token 以 `HATCHET_CLIENT_TOKEN` 的形式存储在 `hatchet-client-config` secret 中。或者，你也可以在 Hatchet 前端导航到 `Settings` 标签页并点击 `API Tokens` 标签页手动生成 token。

### 手动生成密钥

对于 GitOps 或预配置部署，可使用 `hatchet-admin` 镜像生成密钥：

```sh
docker run --rm ghcr.io/hatchet-dev/hatchet/hatchet-admin:latest \
  /hatchet/hatchet-admin keyset create-local-keys
```

通过 `openssl` 生成 cookie 密钥——必须是两个以空格分隔的随机字符串：

```sh
echo "$(openssl rand -hex 16) $(openssl rand -hex 16)"
```

在你的 `values.yaml` 中提供所有值：

```yaml
sharedConfig:
  env:
    SERVER_ENCRYPTION_MASTER_KEYSET: "<master-keyset>"
    SERVER_ENCRYPTION_JWT_PRIVATE_KEYSET: "<private-keyset>"
    SERVER_ENCRYPTION_JWT_PUBLIC_KEYSET: "<public-keyset>"
    SERVER_AUTH_COOKIE_SECRETS: "<secret1> <secret2>"
```

所有可用选项请参阅[加密配置](<07. configuration-options.md#encryption-configuration>)和[认证配置](<07. configuration-options.md#authentication-configuration>)。

### 种子数据

`sharedConfig` 对象还允许你为数据库播种默认租户和用户。默认的管理员凭据直接在 `sharedConfig` 上设置，其余种子值通过 `sharedConfig.env` 以环境变量的形式传入：

```yaml
sharedConfig:
  defaultAdminEmail: "admin@example.com" # in exposed/production environments, change this to a valid email
  defaultAdminPassword: "Admin123!!" # in exposed/production environments, change this to a secure password
  env:
    ADMIN_NAME: "Admin User"
    DEFAULT_TENANT_NAME: "Default"
    DEFAULT_TENANT_SLUG: "default"
    DEFAULT_TENANT_ID: "707d0855-80ab-4e1f-a156-f1c4546cbf52"
```
