# Hatchet 基准测试

本页面提供了 Hatchet 在 8 CPU 数据库（Amazon RDS，`m7g.2xlarge` 实例类型）上的吞吐量和延迟基准测试示例。这些基准测试均针对运行 `v0.55.26` 版本的 v1 Hatchet engine 进行。有关测试环境的更多信息，请参阅 [测试环境](#setup) 一节。请注意，在更好的硬件上会有显著更好的性能：我们曾在 `m7g.8xlarge` 实例上测试到 10k/s。

对 Hatchet 进行基准测试的最佳方式是在你自己的环境中运行你自己的基准测试。下面提供的基准数据仅作为参考点，说明在典型环境下你可能看到的结果。要运行你自己的基准测试，请参阅 [运行你自己的基准测试](#running-your-own-benchmarks) 一节。

## 吞吐量

下面是在不同事件流入速率下运行的吞吐量基准测试汇总。对于每次运行，我们都记录了数据库 CPU 利用率和估算的 IOPS，这是追踪数据库性能最相关的指标。

吞吐量（runs/s），数据库 CPU，数据库 IOPs

100，15%，400
500，60%，600
2000，83%，800

## 延迟

基准测试使用基于事件的触发方式运行：这大约会使 workflow 的排队时间翻倍。Hatchet 中事件的平均延迟可以通过 Hatchet 上报的两个测量值来近似衡量：

- **每个已执行事件的平均执行时间**：从事件开始执行到完成的时间。
- **每个事件的平均写入时间**：Hatchet 写入事件的确认时间。

下表汇总了这些延迟数据：

吞吐量（runs/s），平均执行时间（ms），平均写入时间（ms）

100，~40，~2.5
500，~48，~2.6
2000，~220，~5.7

对于每秒大约 100-500 个事件的工作负载，延迟保持在相对较低的水平。当吞吐量扩展到每秒 2000 个事件时，整体平均执行时间会上升（不过在整个测试过程中 Hatchet engine 保持稳定）。

## 运行你自己的基准测试

Hatchet 发布了一个公开的负载测试容器，可用于基准测试。该容器位于 `ghcr.io/hatchet-dev/hatchet/hatchet-loadtest`。它同时充当 Hatchet worker 和事件发射器，因此只需在环境中设置 `HATCHET_CLIENT_TOKEN` 即可。

例如，要以每秒 100 个事件运行 60 秒，可以使用以下命令：

```bash
docker run -e HATCHET_CLIENT_TOKEN=your-token ghcr.io/hatchet-dev/hatchet/hatchet-loadtest -e "100" -d "60s" --level "warn" --slots "100"
```

容器内置的事件发射器难以发出超过 2k 事件/秒。因此，要测试更高的吞吐量，建议并行运行多个容器。由于每个容器管理自己的 workflow 和 worker，建议使用 `HATCHET_CLIENT_NAMESPACE` 环境变量来确保 workflow 不会在容器之间重复。例如：

```bash
# first container
docker run -e HATCHET_CLIENT_TOKEN=your-token -e HATCHET_CLIENT_NAMESPACE=loadtest1 ghcr.io/hatchet-dev/hatchet/hatchet-loadtest -e "2000" -d "60s" --level "warn" --slots "100"

# second container
docker run -e HATCHET_CLIENT_TOKEN=your-token -e HATCHET_CLIENT_NAMESPACE=loadtest2 ghcr.io/hatchet-dev/hatchet/hatchet-loadtest -e "2000" -d "60s" --level "warn" --slots "100"
```

### 参考

该容器接受以下参数：

```sh
Usage:
  loadtest [flags]

Flags:
  -c, --concurrency int        concurrency specifies the maximum events to run at the same time
  -D, --delay duration         delay specifies the time to wait in each event to simulate slow tasks
  -d, --duration duration      duration specifies the total time to run the load test (default 10s)
  -F, --eventFanout int        eventFanout specifies the number of events to fanout (default 1)
  -e, --events int             events per second (default 10)
  -f, --failureRate float32    failureRate specifies the rate of failure for the worker
  -h, --help                   help for loadtest
  -l, --level string           logLevel specifies the log level (debug, info, warn, error) (default "info")
  -P, --payloadSize string     payload specifies the size of the payload to send (default "0kb")
  -s, --slots int              slots specifies the number of slots to use in the worker
  -w, --wait duration          wait specifies the total time to wait until events complete (default 10s)
  -p, --workerDelay duration   workerDelay specifies the time to wait before starting the worker
```

### 在 Kubernetes 上运行基准测试

你可以使用以下 Pod 清单在 Kubernetes 上运行负载测试（请确保填入 `HATCHET_CLIENT_TOKEN`）：

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: loadtest1a
  namespace: staging
spec:
  restartPolicy: Never
  containers:
    - image: ghcr.io/hatchet-dev/hatchet/hatchet-loadtest:v0.56.0
      imagePullPolicy: Always
      name: loadtest
      command: ["/hatchet/hatchet-load-test"]
      args:
        - loadtest
        - --duration
        - "60s"
        - --events
        - "100"
        - --slots
        - "100"
        - --wait
        - "10s"
        - --level
        - warn
      env:
        - name: HATCHET_CLIENT_TOKEN
          value: "your-token"
        - name: HATCHET_CLIENT_NAMESPACE
          value: "loadtest1a"
      resources:
        limits:
          memory: 1Gi
        requests:
          cpu: 500m
          memory: 1Gi
```

## 测试环境

所有测试均在 AWS 上的 Kubernetes 集群中运行，配置如下：

- **Hatchet engine 副本数：**2（使用 `c7i.4xlarge` 实例以确保 CPU 不是瓶颈）
- **数据库：**`m7g.2xlarge` 实例类型（Amazon RDS）
- **Hatchet 版本：**`v0.55.26`
- **AWS 区域：**`us-west-1`

选择这样的数据库配置是为了在达到较高吞吐量之前避免磁盘和 CPU 争用。我们观察到，在每秒约 2000 个事件以内，所选的数据库实例规模都能跟上，没有出现明显的性能下降。Hatchet engine 部署了 2 个副本，每个 engine 实例在 `c7i.4xlarge` 节点上都有充足的 CPU 余量。
