# 手动降级数据库 Schema

本指南介绍如何安全地将 Hatchet 数据库 schema 降级到先前的版本。

> **Info:** 对于生产关键型工作负载，请参阅[升级与降级](<18. upgrading-downgrading.md>)指南，其中涵盖数据库快照、升级和安全回滚策略。

> **Warning:** 降级可能导致数据丢失。请务必先在非生产环境中测试降级。

## 概述

降级 Hatchet 涉及两个步骤：

1. 运行 down migration 以回退数据库 schema 变更
2. 部署较旧的 Hatchet 版本

## 前置条件

- **关键：**降级前备份数据库
- 确保目标版本支持数据库中的当前数据
- 具备运行 `hatchet-migrate` 命令的权限
- 验证当前版本与目标版本之间的所有 migration 都有对应的 down migration

## 查找目标 Migration 版本

要降级到特定的 Hatchet 版本，你需要确定该版本中包含的最后一个 migration。

访问对应目标版本的 Hatchet GitHub 仓库目录：

```
https://github.com/hatchet-dev/hatchet/tree/{GIT_TAG}/cmd/hatchet-migrate/migrate/migrations
```

将 `{GIT_TAG}` 替换为你的目标版本（例如 `v0.71.0`）。

找到该目录中最后一个 migration 文件——文件名开头的时间戳就是你的目标 migration 版本。

**示例：**

- 目标 Hatchet 版本：`v0.71.0`
- 最后一个 migration 文件：`20250813183355_v1_0_36.sql`
- Migration 版本：`20250813183355`

## 运行 Down Migration

> **Info:** 请使用 [Hatchet releases 页面](https://github.com/hatchet-dev/hatchet/tags)上
>   `hatchet-migrate` 二进制文件的稳定版本（避免 alpha 标签），以确保
>   down migration 正常工作。

确定目标 migration 版本后，使用带 `--down` 标志的 `hatchet-migrate` 命令：

```bash
hatchet-migrate --down 20241023223039
```

该命令将：

1. 使用 `DATABASE_URL` 环境变量连接到你的数据库
2. 检查当前 migration 版本
3. 运行从当前版本到目标版本之间的所有 down migration
4. 显示进度并在完成时确认

## 部署较旧版本

成功运行 down migration 后，部署较旧的 Hatchet 版本：

### Docker Compose

更新你的 `docker-compose.yml`：

```yaml
services:
  hatchet-engine:
    image: ghcr.io/hatchet-dev/hatchet/hatchet-engine:v0.71.0
    # ... rest of configuration

  hatchet-dashboard:
    image: ghcr.io/hatchet-dev/hatchet/hatchet-dashboard:v0.71.0
    # ... rest of configuration
```

然后重启：

```bash
docker-compose down
docker-compose up -d
```
