# Docker Compose 部署

本指南介绍如何使用 Docker Compose 部署 Hatchet，以获得可用于生产环境的部署。如果你想快速上手，也可以按照此处的教程使用 `hatchet-lite` 镜像部署 Hatchet：[Hatchet Lite 部署](<02. hatchet-lite.md>)。

本指南使用 RabbitMQ 作为 Hatchet 的消息代理（message broker）。这是可选的：如果你想使用 Postgres 作为消息代理，请在 `docker-compose.yml` 文件中的 `setup-config` 服务里添加以下环境变量，并删除所有 RabbitMQ 相关内容：

```sh
SERVER_MSGQUEUE_KIND=postgres
```

## 快速开始


### 前置条件

此部署方式要求本地已安装 [Docker](https://docs.docker.com/engine/install/)。

### 创建文件

我们将在你的仓库根目录下创建一个 `docker-compose.yml` 文件：

```
root/
  docker-compose.yml
docker-compose.yml
```

```yaml filename="docker-compose.yml" copy
version: "3.8"
services:
  postgres:
    image: postgres:15.6
    command: postgres -c 'max_connections=1000'
    restart: always
    hostname: "postgres"
    environment:
      - POSTGRES_USER=hatchet
      - POSTGRES_PASSWORD=hatchet
      - POSTGRES_DB=hatchet
    ports:
      - "5435:5432"
    volumes:
      - hatchet_postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -d hatchet -U hatchet"]
      interval: 10s
      timeout: 10s
      retries: 5
      start_period: 10s
  rabbitmq:
    image: "rabbitmq:3-management"
    hostname: "rabbitmq"
    ports:
      - "5673:5672" # RabbitMQ
      - "15673:15672" # Management UI
    environment:
      RABBITMQ_DEFAULT_USER: "user"
      RABBITMQ_DEFAULT_PASS: "password"
    volumes:
      - "hatchet_rabbitmq_data:/var/lib/rabbitmq"
      - "hatchet_rabbitmq.conf:/etc/rabbitmq/rabbitmq.conf" # Configuration file mount
    healthcheck:
      test: ["CMD", "rabbitmqctl", "status"]
      interval: 10s
      timeout: 10s
      retries: 5
  migration:
    image: ghcr.io/hatchet-dev/hatchet/hatchet-migrate:latest
    command: /hatchet/hatchet-migrate
    environment:
      DATABASE_URL: "postgres://hatchet:hatchet@postgres:5432/hatchet"
    depends_on:
      postgres:
        condition: service_healthy
  setup-config:
    image: ghcr.io/hatchet-dev/hatchet/hatchet-admin:latest
    command: /hatchet/hatchet-admin quickstart --skip certs --generated-config-dir /hatchet/config --overwrite=false
    environment:
      DATABASE_URL: "postgres://hatchet:hatchet@postgres:5432/hatchet"
      SERVER_MSGQUEUE_RABBITMQ_URL: amqp://user:password@rabbitmq:5672/
      SERVER_AUTH_COOKIE_DOMAIN: localhost:8080
      SERVER_AUTH_COOKIE_INSECURE: "t"
      SERVER_GRPC_BIND_ADDRESS: "0.0.0.0"
      SERVER_GRPC_INSECURE: "t"
      SERVER_GRPC_BROADCAST_ADDRESS: localhost:7077
      SERVER_INTERNAL_CLIENT_INTERNAL_GRPC_BROADCAST_ADDRESS: hatchet-engine:7070
    volumes:
      - hatchet_certs:/hatchet/certs
      - hatchet_config:/hatchet/config
    depends_on:
      migration:
        condition: service_completed_successfully
      rabbitmq:
        condition: service_healthy
      postgres:
        condition: service_healthy
  hatchet-engine:
    image: ghcr.io/hatchet-dev/hatchet/hatchet-engine:latest
    command: /hatchet/hatchet-engine --config /hatchet/config
    restart: on-failure
    depends_on:
      setup-config:
        condition: service_completed_successfully
      migration:
        condition: service_completed_successfully
    ports:
      - "7077:7070"
    environment:
      DATABASE_URL: "postgres://hatchet:hatchet@postgres:5432/hatchet"
      SERVER_GRPC_BIND_ADDRESS: "0.0.0.0"
      SERVER_GRPC_INSECURE: "t"
    volumes:
      - hatchet_certs:/hatchet/certs
      - hatchet_config:/hatchet/config
  hatchet-dashboard:
    image: ghcr.io/hatchet-dev/hatchet/hatchet-dashboard:latest
    command: sh ./entrypoint.sh --config /hatchet/config
    ports:
      - 8080:80
    restart: on-failure
    depends_on:
      setup-config:
        condition: service_completed_successfully
      migration:
        condition: service_completed_successfully
    environment:
      DATABASE_URL: "postgres://hatchet:hatchet@postgres:5432/hatchet"
    volumes:
      - hatchet_certs:/hatchet/certs
      - hatchet_config:/hatchet/config

volumes:
  hatchet_postgres_data:
  hatchet_rabbitmq_data:
  hatchet_rabbitmq.conf:
  hatchet_config:
  hatchet_certs:
```

### 启动 Hatchet

要启动各项服务，请在你的仓库根目录下运行以下命令：

```bash
docker compose up
```

等待 `hatchet-engine` 和 `hatchet-dashboard` 服务启动完成。

### 访问 Hatchet

Hatchet 实例运行后，你可以通过 [http://localhost:8080](http://localhost:8080) 访问 Hatchet UI。

默认情况下，系统会创建一个使用以下凭据的用户：

```
Email: admin@example.com
Password: Admin123!!
```

## 在 Hatchet 实例上运行 task

要在此实例上运行 task，你首先需要为 worker 创建一个 API token。有两种方式可以完成：

1. **使用 CLI 命令**：

   你可以运行以下命令来创建 token：

   ```sh
   docker compose run --no-deps setup-config /hatchet/hatchet-admin token create --config /hatchet/config --tenant-id 707d0855-80ab-4e1f-a156-f1c4546cbf52
   ```

2. **使用 Hatchet 仪表盘**：
   - 登录 Hatchet 仪表盘。
   - 进入"Settings"页面。
   - 点击"API Tokens"标签页。
   - 点击"Create API Token"。

现在你已经有了一个 API token，请参阅[此处](https://docs.hatchet.run/home/setup)的指南了解如何运行你的第一个 task。


## 重新拉取镜像

上面的 docker compose 文件中所有镜像都使用了 `latest` 标签。这意味着如果你想拉取最新版本的镜像，可以运行以下命令：

```bash
docker compose pull
```

## 从 Docker 内部连接到 engine

如果你也将 worker 应用运行在 `docker-compose` 内部，则应修改 `setup-config` 服务中的 `SERVER_GRPC_BROADCAST_ADDRESS` 环境变量，将主机名改为 `hatchet-engine`。例如：

```yaml
SERVER_GRPC_BROADCAST_ADDRESS: "hatchet-engine:7070"
```

请确保你的 worker 依赖于 hatchet-engine：

```yaml
worker:
  depends_on:
    hatchet-engine:
      condition: service_started
```

> **Info:** **注意：**修改 GRPC 广播地址或服务器 URL 后，需要
>   重新签发 API token。

## 其他 Docker 配置

### 增加 Postgres 共享内存

默认情况下，容器只有 64 MB 的共享内存段（`/dev/shm`）。对于较大规模的 Hatchet 部署，这可能太小，会导致查询缓慢或仪表盘无响应。请为 `postgres` 服务增加共享内存大小：

```yaml filename="docker-compose.yml" copy
# ...
services:
  postgres:
    image: postgres:15.6
    shm_size: 1g # Increase shared memory (adjust as needed)
    command: postgres -c 'max_connections=1000'
    restart: always
    hostname: "postgres"
    environment:
      - POSTGRES_USER=hatchet
      - POSTGRES_PASSWORD=hatchet
      - POSTGRES_DB=hatchet
    ports:
      - "5435:5432"
    volumes:
      - hatchet_postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -d hatchet -U hatchet"]
      interval: 10s
      timeout: 10s
      retries: 5
      start_period: 10s
# ...
```

## 在不启用认证的情况下运行

> **Warning:** 禁用认证的模式仅适用于本地开发。

上面的 compose 技术栈是完全启用认证的。如果要在没有登录界面的情况下运行，请将 `setup-config`、`hatchet-engine` 和 `hatchet-dashboard` 服务替换为对应的 `-dev` 变体，这些镜像在编译时就去掉了认证功能：

```yaml filename="docker-compose.yml"
setup-config:
  image: ghcr.io/hatchet-dev/hatchet/hatchet-admin-dev:latest
  # ... rest of the service unchanged
hatchet-engine:
  image: ghcr.io/hatchet-dev/hatchet/hatchet-engine-dev:latest
  # ... rest of the service unchanged
hatchet-dashboard:
  image: ghcr.io/hatchet-dev/hatchet/hatchet-dashboard-dev:latest
  # ... rest of the service unchanged
```

Worker 仍会使用 dev 镜像内置的固定 worker token 通过 gRPC 进行认证，你可以在仪表盘的 **Settings → API Tokens** 下查看该 token。

如果你只想要一个单容器的本地实例，可以运行 `hatchet server start --disable-auth`，它会运行一体化的 `hatchet-lite-dev` 镜像。详见[本地运行 Hatchet](<../reference/05. running-hatchet-locally.md#running-without-authentication>)。
