# 配置选项

Hatchet 服务器和 engine 通过环境变量进行配置，并按前缀分组。本页面按组件记录可用的选项。

## 环境变量前缀

Hatchet 使用以下环境变量前缀：

- **`SERVER_`** - 主服务器配置：运行时、认证、加密、监控和集成
- **`DATABASE_`** - PostgreSQL 连接和连接池
- **`READ_REPLICA_`** - 读副本数据库配置
- **`ADMIN_`** - 用于初始种子数据的管理员用户
- **`DEFAULT_`** - 默认租户配置
- **`SCHEDULER_`** - 调度器并发和轮询间隔
- **`CACHE_`** - 仓库层查询的缓存时长

## 必需的环境变量

以下变量是 Hatchet 成功启动**绝对必需**的：

### 加密密钥

**方案 A：本地加密密钥**

```bash
SERVER_ENCRYPTION_MASTER_KEYSET="<base64-encoded-keyset>"
SERVER_ENCRYPTION_JWT_PUBLIC_KEYSET="<base64-encoded-jwt-public>"
SERVER_ENCRYPTION_JWT_PRIVATE_KEYSET="<base64-encoded-jwt-private>"
```

**方案 B：基于文件的密钥**

```bash
SERVER_ENCRYPTION_MASTER_KEYSET_FILE="/path/to/master.keyset"
SERVER_ENCRYPTION_JWT_PUBLIC_KEYSET_FILE="/path/to/jwt-public.keyset"
SERVER_ENCRYPTION_JWT_PRIVATE_KEYSET_FILE="/path/to/jwt-private.keyset"
```

**方案 C：Google Cloud KMS**

```bash
SERVER_ENCRYPTION_CLOUDKMS_ENABLED=true
SERVER_ENCRYPTION_CLOUDKMS_KEY_URI="gcp-kms://your-key-uri"
SERVER_ENCRYPTION_CLOUDKMS_CREDENTIALS_JSON="<credentials-json>"
```

### 认证密钥（必需）

```bash
SERVER_AUTH_COOKIE_SECRETS="<secret1> <secret2>"
```

### 数据库连接

**方案 A：连接字符串**

```bash
DATABASE_URL="postgresql://user:password@host:port/dbname"
```

**方案 B：独立参数**（未设置时各自回退到默认值）

```bash
DATABASE_POSTGRES_HOST=127.0.0.1
DATABASE_POSTGRES_PORT=5432
DATABASE_POSTGRES_USERNAME=hatchet
DATABASE_POSTGRES_PASSWORD=<your-password>
DATABASE_POSTGRES_DB_NAME=hatchet
DATABASE_POSTGRES_SSL_MODE=disable
```

## 最小配置示例

> **Warning:** 此示例适用于 Hatchet 连接到同一主机上运行的 PostgreSQL 的本地开发
>   环境。对于 Docker Compose 部署，请在 `DATABASE_URL` 中使用数据库服务名
>   （例如 `postgres`）而不是 `127.0.0.1`。请参阅
>   [Docker Compose 部署指南](<03. docker-compose.md>)。

```bash
# Database
DATABASE_URL='postgresql://hatchet:hatchet@127.0.0.1:5431/hatchet'

# Encryption (using key files - recommended for development)
SERVER_ENCRYPTION_MASTER_KEYSET_FILE=./keys/master.key
SERVER_ENCRYPTION_JWT_PRIVATE_KEYSET_FILE=./keys/private_ec256.key
SERVER_ENCRYPTION_JWT_PUBLIC_KEYSET_FILE=./keys/public_ec256.key

# Authentication
SERVER_AUTH_COOKIE_SECRETS="your-secret-key-1 your-secret-key-2"
SERVER_AUTH_SET_EMAIL_VERIFIED=true

# Basic server config
SERVER_PORT=8080
SERVER_URL=http://localhost:8080

# Development settings (optional but recommended)
SERVER_GRPC_INSECURE=true
SERVER_INTERNAL_CLIENT_BASE_STRATEGY=none
SERVER_LOGGER_LEVEL=error
SERVER_LOGGER_FORMAT=console
DATABASE_LOGGER_LEVEL=error
DATABASE_LOGGER_FORMAT=console
```

使用 `hatchet-admin` 镜像生成加密密钥。这会将 `master.key`、`private_ec256.key` 和 `public_ec256.key` 写入 `./keys`：

```bash
docker run --rm -v "$(pwd)/keys:/keys" \
  ghcr.io/hatchet-dev/hatchet/hatchet-admin:latest \
  /hatchet/hatchet-admin keyset create-local-keys --key-dir /keys
```

### NATS 发布/订阅

NATS 仅可用于尽力而为（best-effort）的发布/订阅；持久任务队列仍使用
RabbitMQ 或 Postgres。它使用核心 NATS（不含 JetStream），因此交付语义
为至多一次（at-most-once）。

NATS 服务器必须配置 `max_payload: 16777216`（16MiB）。task 流事件
经常超过 NATS 默认的 1MiB，Hatchet 在面对通告更小限制的服务器时会拒绝
启动，而不是在稍后发布超大消息时才失败。

建议在 `SERVER_MSGQUEUE_PUBSUB_NATS_URL` 中使用裸主机名，并单独设置
用户名和密码。当客户端通过 gossip 得知集群对等节点并重连时，嵌入 URL
中的凭据不会被重新应用。

设置 `SERVER_MSGQUEUE_PUBSUB_NATS_TLS_ENABLED=true` 以要求带 TLS 优先
握手的可验证 TLS：握手发生在服务器发送 `INFO` 消息之前，因此服务器必须
在其 tls 块中设置 `handshake_first`，并且带有此标志的客户端无法连接到
INFO 优先的 TLS 或明文服务器。如果没有 CA 文件，服务器证书将针对系统根
证书进行验证。如果服务器证书由私有 CA 签发，还需将
`SERVER_MSGQUEUE_PUBSUB_NATS_TLS_ROOT_CA_FILE` 指向一个 PEM CA 包，
该配置在客户端重连到重新发现的集群对等节点时同样适用。CA 文件仅在
启用 TLS 时生效，因此如果在 `SERVER_MSGQUEUE_PUBSUB_NATS_TLS_ENABLED`
为 false 时设置了它，Hatchet 会拒绝启动。

与在连接层面隔离部署实例的其他后端不同（RabbitMQ 的 vhost、Postgres 的
数据库），NATS 通过 subject 进行隔离。设置
`SERVER_MSGQUEUE_PUBSUB_NATS_SUBJECT_PREFIX` 可避免共享同一 NATS 服务器的
多个部署实例看到彼此的消息。

### 消息队列缓冲区

Hatchet 通过按 `(tenant, message)` 划分的发布和订阅缓冲区来批量处理消息队列写入。以下设置对两类缓冲区都适用；相关指导请参阅[提升性能](<10. improving-performance.md#tuning-buffer-settings>)。

变量，说明，默认值

`SERVER_DEFAULT_BUFFER_SIZE`，缓冲区提前刷新前累积的最大消息数，`10`
`SERVER_DEFAULT_BUFFER_FLUSH_INTERVAL`，缓冲区刷新前的等待时间，`10ms`
`SERVER_DEFAULT_BUFFER_CONCURRENCY`，最大并发在途刷新数，`1`（发布）/ `10`（订阅）
