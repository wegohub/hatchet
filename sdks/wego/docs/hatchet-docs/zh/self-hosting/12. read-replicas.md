# 读副本支持

对于高吞吐量的生产部署，Hatchet 支持数据库读副本（read replica）来分散数据库负载并提升读取性能。此功能允许你将读查询定向到单独的数据库实例，同时继续将写操作发送到主数据库。**这可以在读密集型工作负载中显著提升性能，且无需修改应用程序。**

你可以通过设置以下环境变量来启用读副本支持：

```bash
READ_REPLICA_ENABLED=true
READ_REPLICA_DATABASE_URL='postgresql://hatchet:hatchet@127.0.0.1:5432/hatchet'
READ_REPLICA_MAX_CONNS=200
READ_REPLICA_MIN_CONNS=50
```

## 配置选项

- `READ_REPLICA_ENABLED`：设为 `true` 以启用读副本支持
- `READ_REPLICA_DATABASE_URL`：读副本数据库的连接字符串
- `READ_REPLICA_MAX_CONNS`：读副本连接池的最大连接数
- `READ_REPLICA_MIN_CONNS`：读副本连接池要维持的最小连接数

## 限制

- 复制延迟可能导致读操作返回的数据略有滞后或缺失
- 读副本仅由分析型查询使用（用于在 UI 中加载 workflow run、task run 和指标）
