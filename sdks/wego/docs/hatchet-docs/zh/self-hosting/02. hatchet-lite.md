# Hatchet Lite 部署

为了快速上手，你可以通过 `hatchet-lite` 镜像进行部署。该镜像专为开发和低流量使用场景设计。


### 前置条件

此部署方式要求本地已安装 [Docker](https://docs.docker.com/engine/install/)。

### 启动 Hatchet Lite

#### Hatchet CLI

启动 Hatchet Lite 最简单的方式是使用 Hatchet CLI。只需运行以下命令：

```sh
hatchet server start
```

> **Info:** 本地开发时，你可以添加 `--disable-auth` 来运行 `hatchet-lite-dev`
> > 镜像，该镜像在编译时去掉了认证功能。Worker 仍会使用 dev 镜像内置的
> > 固定 worker token 通过 gRPC 进行认证（可在仪表盘横幅中查看）。详情请参阅
> > [本地运行 Hatchet](<../reference/05. running-hatchet-locally.md#running-without-authentication>)。

#### 使用 Postgres（默认）

要将 Postgres 同时用作数据库和消息队列，请将以下 `docker-compose.hatchet.yml` 文件复制到你的仓库根目录：

> **Info:** 如果你已有正在运行的 Postgres 实例，只需将 `DATABASE_URL` 指向该
> > 实例，并忽略下面 docker-compose 文件中的 `postgres` 服务部署即可。

```yaml filename="docker-compose.hatchet.yml" copy
version: "3.8"
name: hatchet-lite
services:
  postgres:
    image: postgres:15.6
    command: postgres -c 'max_connections=200'
    restart: always
    environment:
      - POSTGRES_USER=hatchet
      - POSTGRES_PASSWORD=hatchet
      - POSTGRES_DB=hatchet
    volumes:
      - hatchet_lite_postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -d hatchet -U hatchet"]
      interval: 10s
      timeout: 10s
      retries: 5
      start_period: 10s
  hatchet-lite:
    image: ghcr.io/hatchet-dev/hatchet/hatchet-lite:latest
    ports:
      - "8888:8888"
      - "7077:7077"
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      # Refer to https://docs.hatchet.run/self-hosting/configuration-options
      # for a list of all supported environment variables
      DATABASE_URL: "postgresql://hatchet:hatchet@postgres:5432/hatchet?sslmode=disable"
      SERVER_AUTH_COOKIE_DOMAIN: localhost
      SERVER_AUTH_COOKIE_INSECURE: "t"
      SERVER_GRPC_BIND_ADDRESS: "0.0.0.0"
      SERVER_GRPC_INSECURE: "t"
      SERVER_GRPC_BROADCAST_ADDRESS: localhost:7077
      SERVER_GRPC_PORT: "7077"
      SERVER_URL: http://localhost:8888
      SERVER_AUTH_SET_EMAIL_VERIFIED: "t"
      SERVER_INTERNAL_CLIENT_INTERNAL_GRPC_BROADCAST_ADDRESS: localhost:7077
    volumes:
      - "hatchet_lite_config:/config"

volumes:
  hatchet_lite_postgres_data:
  hatchet_lite_config:
```

然后运行 `docker-compose -f docker-compose.hatchet.yml up` 启动 Hatchet Lite 实例。

#### 使用 Postgres + RabbitMQ

要将 Postgres 用作数据库、RabbitMQ 用作消息队列，请将以下 `docker-compose.hatchet.yml` 文件复制到你的仓库根目录：

> **Info:** 如果你已有正在运行的 Postgres 实例，只需将 `DATABASE_URL` 指向该
> > 实例，并忽略下面 docker-compose 文件中的 `postgres` 服务部署即可。

```yaml filename="docker-compose.hatchet.yml" copy
version: "3.8"
name: hatchet-lite
services:
  postgres:
    image: postgres:15.6
    command: postgres -c 'max_connections=200'
    restart: always
    environment:
      - POSTGRES_USER=hatchet
      - POSTGRES_PASSWORD=hatchet
      - POSTGRES_DB=hatchet
    volumes:
      - hatchet_lite_postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -d hatchet -U hatchet"]
      interval: 10s
      timeout: 10s
      retries: 5
      start_period: 10s
  rabbitmq:
    image: "rabbitmq:3-management"
    hostname: "rabbitmq"
    ports:
      - "5672:5672"
      - "15672:15672"
    environment:
      RABBITMQ_DEFAULT_USER: "user"
      RABBITMQ_DEFAULT_PASS: "password"
    volumes:
      - "hatchet_rabbitmq_data:/var/lib/rabbitmq"
      - "hatchet_rabbitmq.conf:/etc/rabbitmq/rabbitmq.conf"
    healthcheck:
      test: ["CMD", "rabbitmqctl", "status"]
      interval: 30s
      timeout: 10s
      retries: 5
  hatchet-lite:
    image: ghcr.io/hatchet-dev/hatchet/hatchet-lite:latest
    ports:
      - "8888:8888"
      - "7077:7077"
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      SERVER_MSGQUEUE_KIND: rabbitmq
      SERVER_MSGQUEUE_RABBITMQ_URL: "amqp://user:password@rabbitmq:5672/"
      # Refer to https://docs.hatchet.run/self-hosting/configuration-options
      # for a list of all supported environment variables
      DATABASE_URL: "postgresql://hatchet:hatchet@postgres:5432/hatchet?sslmode=disable"
      SERVER_AUTH_COOKIE_DOMAIN: localhost
      SERVER_AUTH_COOKIE_INSECURE: "t"
      SERVER_GRPC_BIND_ADDRESS: "0.0.0.0"
      SERVER_GRPC_INSECURE: "t"
      SERVER_GRPC_BROADCAST_ADDRESS: localhost:7077
      SERVER_GRPC_PORT: "7077"
      SERVER_URL: http://localhost:8888
      SERVER_AUTH_SET_EMAIL_VERIFIED: "t"
    volumes:
      - "hatchet_lite_config:/config"

volumes:
  hatchet_lite_postgres_data:
  hatchet_lite_config:
  hatchet_rabbitmq_data:
  hatchet_rabbitmq.conf:
```

然后运行 `docker-compose -f docker-compose.hatchet.yml up` 启动 Hatchet Lite 实例。

### 访问 Hatchet Lite

Hatchet Lite 实例运行后，你可以通过 [http://localhost:8888](http://localhost:8888) 访问 Hatchet Lite UI。

默认情况下，系统会创建一个使用以下凭据的用户：

```
Email: admin@example.com
Password: Admin123!!
```

登录后，按照 UI 中的步骤创建你的第一个租户并运行你的第一个 workflow！

> **Info:** 要通过反向代理在 URL 子路径下提供仪表盘服务，请设置
> > `LITE_FRONTEND_BASE_PATH`（例如 `/hatchet/`），并按照
> > [在 URL 子路径下提供 Hatchet 服务](<09. networking.md#serving-hatchet-under-a-url-subpath>)
> > 中的说明配置代理。
