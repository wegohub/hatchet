# 高可用

如果你在高吞吐量的生产环境中运行 Hatchet，你可能需要设置 HA（高可用，High Availability）配置，以确保系统在基础设施故障或其他问题发生时仍能保持可用。

可以在多个层级上将 Hatchet 配置为高可用：

- 在**数据库层面**，使用支持 HA 选项的托管 Postgres 提供商，如 AWS RDS 或 Google Cloud SQL。
- 在 **RabbitMQ 层面**，将 RabbitMQ 集群配置为在同一个区域的多个可用区中拥有至少 3 个副本。
- 在 **Hatchet Engine/API 层面**，在负载均衡器后面运行多个 Hatchet engine 实例，并将不同的 Hatchet 服务拆分为独立的部署。

本指南将重点介绍最后一层的高可用。


要查看使用 Terraform 在 GCP 上配置 Hatchet 高可用的端到端示例，请查看此处的 GCP 部署指南：[链接](https://github.com/hatchet-dev/hatchet-infra-examples/blob/main/self-hosting/gcp)


## HA Helm Chart

Hatchet 提供了一个 HA Helm chart，可用于以高可用配置部署 Hatchet。要使用此 Helm chart：

```sh
helm repo add hatchet https://hatchet-dev.github.io/hatchet-charts
helm install hatchet-ha hatchet/hatchet-ha
```

此 chart 的顶层 `api`、`frontend`、`postgres` 和 `rabbitmq` 对象接受与 `hatchet-stack` 相同的参数，此外你还可以配置以下服务：

```yaml
grpc:
  replicaCount: 4
controllers:
  replicaCount: 2
scheduler:
  replicaCount: 2
```

有关配置 Hatchet Helm chart 的更多信息，请参阅 [Helm 配置](<05. kubernetes-helm-configuration.md>)指南。
