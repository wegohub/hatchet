# 自托管 Hatchet 控制平面

自托管 Hatchet 意味着运行你自己的 **Hatchet 控制平面**实例——管理 workflow、调度 task、协调 worker 执行的中央编排系统。这与运行 worker 不同：worker 可以连接到任何 Hatchet 实例（自托管或 Hatchet Cloud）。

## 你在自托管什么

自托管 Hatchet 时，你部署的是：

- **API Server** — 用于 workflow 管理的 REST API
- **Engine** — 用于核心 workflow 编排和 task 调度的 gRPC API
- **Database** — PostgreSQL，存储 workflow 状态和元数据
- **Message Queue（可选）** — RabbitMQ，用于服务间通信和高吞吐实时更新
- **Dashboard** — 用于监控 workflow 和调试的 Web UI

你的 **worker**（执行 workflow 步骤的进程）会连接到你自托管的控制平面并执行 task。

## 部署方式

在本地跑起一个 Hatchet 实例最快的方式是使用 [Hatchet CLI](/cli)（封装了 Hatchet Lite）：

```sh
hatchet server start
```

本地开发请参见[本地运行 Hatchet](<../v1/01. get-started（入门）/04. running-locally.md>)，了解更轻量的选项，包括无需 Docker 和 token 的 embedded 模式。

目前支持三种自托管控制平面的方式：

Docker：

1. [Hatchet Lite](<02. hatchet-lite.md>) — 单个 docker 镜像，内置 engine 和 API（开发、测试或低吞吐生产）
2. [Docker Compose](<03. docker-compose.md>) — 带 PostgreSQL 和 RabbitMQ 的多容器部署（生产）

Kubernetes：

1. [Helm 快速开始](<04. kubernetes-quickstart.md>) — 生产级 Helm chart（生产）
