# 安装并设置 Hatchet CLI

以下是供 AI agent 安装 Hatchet CLI 并配置 profile 的指令。请按顺序执行每个步骤。

## 步骤 1：检查是否已安装

```bash
hatchet --version
```

如果输出版本号，说明 CLI 已安装。跳到步骤 3（选择连接模式）。

如果命令未找到，继续步骤 2。

## 步骤 2：安装 CLI

在 macOS、Linux 或 WSL 上：

```bash
curl -fsSL https://install.hatchet.run/install.sh | bash
```

或者，在 macOS 上通过 Homebrew：

```bash
brew install hatchet-dev/hatchet/hatchet --cask
```

安装完成后，验证是否成功：

```bash
hatchet --version
```

## 步骤 3：选择连接模式

- **本地开发（默认）**：使用 embedded 模式。它在 worker 进程内运行一个完整的 Hatchet engine，无需 API token、账户或服务器。请遵循 `local-dev-embedded.md` 并跳过本文档的其余部分。
- **Hatchet Cloud 或自托管实例**：你需要一个由 API token 支持的 profile。继续步骤 4。

## 步骤 4：检查现有 profile

```bash
hatchet profile list
```

如果已存在连接到正确 Hatchet 实例的 profile，记下其名称，并在后续所有命令中将其用作 `-p` 标志。至此完成。

如果不存在 profile 或缺少正确的 profile，继续步骤 5。

## 步骤 5：创建 profile

你需要目标部署（Hatchet Cloud 或自托管实例）的 Hatchet API token。如果没有，请向用户索取。然后创建 profile：

```bash
hatchet profile add --name HATCHET_PROFILE --token 
```

将 `HATCHET_PROFILE` 替换为描述性名称（例如 `local`、`staging`、`production`），将 `` 替换为实际 token。

要将其设为默认 profile（这样后续命令中 `-p` 可省略）：

```bash
hatchet profile set-default --name HATCHET_PROFILE
```

## 步骤 6：验证连通性

通过列出 workflow 运行来测试 profile 是否可用：

```bash
hatchet runs list -o json -p HATCHET_PROFILE --since 1h --limit 1
```

如果返回 JSON 响应（即使 rows 列表为空），说明 profile 已正确配置并连接成功。

## 故障排除

- 安装后出现 **"command not found"**：CLI 二进制可能不在 PATH 上。检查 `~/.local/bin/hatchet` 或重新运行安装脚本。
- **认证错误**：API token 可能无效或已过期。向用户索取新 token 并运行 `hatchet profile update`。
- **连接被拒绝**：profile 指向的服务器未在运行。embedded 模式无需服务器；本地开发优先使用它（参见 `local-dev-embedded.md`）。仅当用户明确需要完整的本地技术栈（仪表盘、独立服务）时才使用 `hatchet server start`。
