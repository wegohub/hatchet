# 以开发模式启动 Hatchet Worker

以下是供 AI agent 使用 CLI 启动 Hatchet worker 的指令。请按顺序执行每个步骤。

## 前置条件

这些步骤假定已有一个指向 Hatchet 部署的 profile。对于本地开发，worker 可以改用 embedded 模式运行，无需 token 或 profile；参见 `local-dev-embedded.md`。

你需要在项目根目录有一个 `hatchet.yaml` 文件。如果不存在，请按以下结构创建：

```yaml
dev:
  runCmd: "python src/worker.py"
  files:
    - "**/*.py"
  reload: true
```

请调整 `runCmd` 以匹配项目的语言和入口：

- Python：`poetry run python src/worker.py` 或 `python src/worker.py`
- TypeScript/Node：`npx ts-node src/worker.ts` 或 `npm run dev`
- Go：`go run ./cmd/worker`

`files` 列表包含用于文件监视的 glob 模式。`reload: true` 设置启用在受监视文件变更时自动重启 worker。

## 启动 Worker

在**后台终端**中运行以下命令（worker 是必须保持存活的长时间运行进程）：

```bash
hatchet worker dev -p HATCHET_PROFILE
```

worker 将使用指定的 profile 连接到 Hatchet 并开始监听 task。

## 重要说明

- 在触发任何 workflow 之前，worker **必须处于运行状态**。如果在没有 worker 运行的情况下触发 workflow，task 将无限期保持 QUEUED 状态。
- 设置 `reload: true` 后，任何受监视文件变更时 worker 会自动重启。这意味着你可以编辑 task 代码，worker 会自动应用变更，无需手动重启。
- 要禁用自动重载，可添加 `--no-reload`。
- 要在不编辑 `hatchet.yaml` 的情况下覆盖运行命令，可使用 `--run-cmd "your command here"`。
- 如果 worker 启动失败，请检查 profile 是否存在（`hatchet profile list`）以及 Hatchet 服务器是否可达。

## 可选：前置命令

你可以添加在 worker 启动之前运行的设置命令：

```yaml
dev:
  preCmds:
    - "poetry install"
    - "npm install"
  runCmd: "poetry run python src/worker.py"
  files:
    - "**/*.py"
  reload: true
```

这些命令在 worker 每次启动时（包括重载时）各运行一次。
