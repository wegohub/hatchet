# 触发 Workflow 并等待完成

以下是供 AI agent 触发 Hatchet workflow 并轮询直至其完成的指令。请按顺序执行每个步骤。

## 前置条件

- 必须有一个正在运行的 Hatchet worker（`hatchet worker dev -p HATCHET_PROFILE`）。如果没有 worker 运行，task 将永远保持 QUEUED 状态。
- 你必须知道 workflow 名称并准备好输入 JSON。
- 这些命令需要 profile。如果 worker 以 embedded 模式进行本地开发，请改为在 worker 进程中通过代码触发；参见 `local-dev-embedded.md`。

## 步骤 1：将输入写入临时文件

将输入 JSON 写入一个唯一命名的临时文件，以避免与其他会话冲突：

```bash
HATCHET_INPUT_FILE="/tmp/hatchet-input-$(date +%s)-$$.json"
cat > "$HATCHET_INPUT_FILE" << 'ENDJSON'
INPUT_JSON
ENDJSON
```

将 `INPUT_JSON` 替换为 workflow 的实际 JSON payload。

## 步骤 2：触发 Workflow

```bash
RUN_ID=$(hatchet trigger manual -w WORKFLOW_NAME -j "$HATCHET_INPUT_FILE" -p HATCHET_PROFILE -o json | jq -r '.runId')
```

`-o json` 标志使命令向 stdout 输出 `{"runId": "...", "workflow": "..."}`。上面的命令会直接将 run ID 捕获到 `$RUN_ID` 中以供后续步骤使用。

## 步骤 3：轮询直至完成

每 5 秒运行以下命令，直到 run 达到终态：

```bash
hatchet runs get  -o json -p HATCHET_PROFILE
```

解析 JSON 响应并检查状态：

- 查看 `.run.status` 获取整体 run 状态，查看 `.tasks[].status` 获取各个 task 的状态。
- 终态包括：`COMPLETED`、`FAILED`、`CANCELLED`。
- 非终态包括：`QUEUED`、`RUNNING`。看到这些时继续轮询。

## 步骤 4：处理失败

如果 run 状态为 `FAILED`，收集诊断信息：

### 获取日志

```bash
hatchet runs logs  -p HATCHET_PROFILE
```

这会打印应用级别的日志输出（例如 print 语句、task 代码中的 logger 调用）。查找错误消息、堆栈跟踪或意外输出。

### 获取事件

```bash
hatchet runs events  -o json -p HATCHET_PROFILE
```

这会返回展示 task 如何被分发、启动和失败的生命周期事件日志。查看 `eventType` 和 `message` 字段以理解失败过程。

## 步骤 5：清理

```bash
rm -f "$HATCHET_INPUT_FILE"
```

## 常见问题

- **Task 一直保持 QUEUED**：worker 未运行，或 workflow/task 名称与 worker 注册的不匹配。请启动或重启 worker。
- **Task 立即 FAILED**：检查日志中的堆栈跟踪。task 代码很可能抛出了异常。
- **Task CANCELLED**：有外部操作取消了 run。查看事件以确定取消来源。
