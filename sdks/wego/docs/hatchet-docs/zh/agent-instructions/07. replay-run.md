# 重放 Hatchet Run

以下是供 AI agent 重放先前执行的 Hatchet run（可选择修改输入）的指令。请按顺序执行每个步骤。

这些命令需要 profile。本地开发时 worker 可以改用 embedded 模式运行，其循环由代码驱动；参见 `local-dev-embedded.md`。

## 步骤 1：检查原始 Run

首先，了解原始 run 中发生了什么：

```bash
hatchet runs get RUN_ID -o json -p HATCHET_PROFILE
```

从响应中记下：

- `.run.displayName` —— workflow 名称（用新输入重新触发时需要）
- `.run.input` —— 原始输入 JSON
- `.run.status` —— 你可能要重放的原因（例如 `FAILED`）
- `.tasks[].status` 和 `.tasks[].errorMessage` —— 哪些具体的 task 失败了以及原因

## 步骤 2a：以相同输入重放

如果你想用相同的输入重新运行完全相同的 workflow（例如在修复了 task 代码中的 bug 之后）：

```bash
hatchet runs replay RUN_ID -o json -p HATCHET_PROFILE
```

这会以相同输入创建同一 workflow 的新 run。响应中的 `.ids[]` 包含新的 run ID。

## 步骤 2b：以新输入重放

如果你需要修改输入（例如修正错误的输入数据），必须触发一个新 run 而不是使用重放：

将新的输入 JSON 写入一个唯一命名的临时文件：

```bash
HATCHET_INPUT_FILE="/tmp/hatchet-input-$(date +%s)-$$.json"
cat > "$HATCHET_INPUT_FILE" << 'ENDJSON'
NEW_INPUT_JSON
ENDJSON
```

然后使用步骤 1 中的 workflow 名称触发一个全新的 run：

```bash
RUN_ID=$(hatchet trigger manual -w WORKFLOW_NAME -j "$HATCHET_INPUT_FILE" -p HATCHET_PROFILE -o json | jq -r '.runId')
```

清理临时文件：

```bash
rm -f "$HATCHET_INPUT_FILE"
```

## 步骤 3：观察新 Run

在步骤 2a 或 2b 之后，你都有一个新的 run ID。轮询直至完成：

```bash
hatchet runs get  -o json -p HATCHET_PROFILE
```

每 5 秒检查一次 `.run.status` 和 `.tasks[].status`，直到全部达到终态（`COMPLETED`、`FAILED`、`CANCELLED`）。

如果新 run 也失败，请使用调试指令：

1. `hatchet runs logs  -p HATCHET_PROFILE` 获取应用日志
2. `hatchet runs events  -o json -p HATCHET_PROFILE` 获取生命周期事件

## 常见重放工作流

agent 迭代 task 代码时的典型流程：

1. 触发一个 run，它失败了
2. 阅读日志/事件以理解原因
3. 修复代码（如果 `hatchet.yaml` 中设置了 `reload: true`，worker 会自动重载）
4. 用 `hatchet runs replay RUN_ID -o json -p HATCHET_PROFILE` 重放该 run
5. 如果再次失败，从步骤 2 开始重复
