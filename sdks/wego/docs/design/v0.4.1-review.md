# v0.4.0 专项复审与修复（SDK 0.4.1）

评审日期：2026-10-13。协议保持 **6**。本轮只修改 `sdks/wego/**`，未修改 Hatchet 源码、根依赖或历史验收报告。

## 结论与范围

围绕真实提交、Worker 执行、结果上报和关闭链路复审，修复下列 9 类边界问题。主要涉及 `internal/wire`、`internal/rpc`、`internal/stream`、`internal/backend`，并核查 `internal/client`、`internal/features`、`internal/engine` 和 Server 生命周期的接入关系。没有新增公开接口、协议字段或兼容分支。

本报告区分本轮验证与 0.4.0 历史验收；不将历史的 28 个官方文件／74 个片段和 embedded 全量验收计入本轮通过项。

## 发现与修复

| 级别 | 问题与触发条件 | 修复与回归 |
|---|---|---|
| P2 | 显式协议接受重复键、`Response` 大小写别名、`response:null`；响应契约由宽松 JSON 解码隐式决定 | 标记消息的外层和协议头拒绝重复字段，已定义头字段拒绝大小写别名和 null；未知可忽略扩展、未标记的业务对象仍按约定解释。`TestReviewV6AmbiguousHeader` |
| P2 | 非法 UTF-8 metadata 或超限协议头在上传／加密之后才失败 | 在 codec I/O 前检查明文协议头；测试断言 Encode 调用次数为零。`TestReviewV6HeaderValidationPrecedesCodec` |
| P2 | 执行 deadline 在业务输入解码后才恢复，过期任务仍下载或解密 | 普通任务与四种 RPC 的输入解码使用恢复后的执行 context；历史读取仍使用观察者预算，不能因旧任务 deadline 过期而无法恢复。`TestReviewV6RPCDeadlineBeforeCodec`、`TestReviewV6ExecutionDeadlineDoesNotExpireHistory` |
| P2 | unary 拦截器可返回另一种 protobuf，只要 JSON 字段相同就可能被当作合法输出 | 根据注册输出描述校验具体消息类型，复用到流输入输出校验。`TestReviewV6UnaryOutputBinding` |
| P1 | CLAIM 首次读回未绑定 RunID，其他运行的日志可能通过部分身份检查 | 候选 RunID 必填，读回解释器同时固定 TaskRunID、RunID、方法和摘要。`TestClaimReadbackBoundaries/wrong_run` |
| P1 | handler 返回后迟到 Send 仍可发布；客户端关闭清空状态后，迟到解码或背压唤醒仍可入队 | 服务端在发送锁内封闭终态；客户端在解码和背压等待后重新检查关闭状态。`TestReviewV6ServerTerminalBarrier`、`TestReviewV6ClosedClientRejectsLateFrame` |
| P2 | 混合 Batch 整批失败时，原生成员收到 wego 错误载体；结果超限转失败也忽略原生契约 | START 时记录每个成员契约，最终上报逐项选择错误格式，终态确认后释放登记；不修改原事件容器。单元测试及真实混合 Batch 成功／失败测试覆盖 |
| P2 | Filter payload 解码先于执行取消登记，关闭不能及时取消此阶段下载 | 先登记本地执行取消能力，再解码 Filter；错误和取消均注销登记。`TestReviewV6FilterDecodeRegisteredForCancellation` |
| P2 | 关闭时排空取消、注销失败和监听退出超时互相覆盖，真实清理故障可能消失 | 分阶段合并错误，并发关闭只执行一次清理。`TestReviewV6ClosePreservesCleanupFailure`（确定性取消并保留故障） |

## 代码组织

将长函数中的候选身份准备、codec 前置校验、消息类型检查、背压等待、START 登记及单个 Batch 上报处理提取为同包内函数；不增加包或公开转发层。复杂度门禁阈值未调整：`Claim` 为 18，流客户端 `accept` 为 24，均低于既有上限 25。

新测试使用可控屏障复现迟到回调、下载中取消和并发关闭。必要声明与并发约束使用中文注释。

## 性能与保证边界

本地基准覆盖 16 B、1 KiB、64 KiB、1 MiB 的无 codec、gzip、AES、组合发送链。1 KiB 无 codec 的传输尺寸仍为 1076 B、13 次分配；AES 的前置头校验从 18 次增加至 20 次分配。编码成本与校验收益需要同时看待，不将本轮修复表述为性能提升。耗时采样与真实验收并行执行，不作为严格的跨版本速度结论。

AES 无 AAD、外层 routing／metadata 不获得密文认证绑定，仍是协议 6 的明确契约；本次未改变。原生实时流仍不提供持久恢复；旧原生输入已经发生的服务端数值精度损失无法恢复。业务 handler／自定义 codec 必须遵守 context，不承诺强制终止任意 Go goroutine。

本轮未重跑全部 28 个官方示例及 embedded 独立进程验收；它们的历史结果仍保存在 0.4.0 报告中。
