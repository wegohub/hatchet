# wego SDK 0.3.0：统一客户端与消息链路

SDK 版本 `0.3.0`，协议版本 `5`，发行依赖和本机官方引擎均为 Hatchet `v0.110.5`。本次仅修改 `sdks/wego/**`；根模块、官方源码与模块缓存不修改。PostgreSQL MQ 与 MinIO 用于真实验收。

## 目标与边界

所有业务输入输出执行同一封包及 codec：生成客户端、Run 系列、普通 JSON/protobuf StandaloneTask、durable、DAG、Batch、Cron、Schedule、Event、Filter 和原生实时输出。网络 gRPC 入口直接执行标准 handler，不应用任务封包或 routing。

任务类型由注册绑定及调用地址确定。完整 `/package.Service/Method` 是 RPC 地址；普通任务不得占用该地址空间。protobuf 只决定 ProtoJSON 序列化，不决定是否为 RPC；普通 StandaloneTask 可以收发 protobuf。未注册、非 wego、类型或协议不兼容的目标明确失败。绑定解析按 workflow 版本缓存，名称每次重新解析当前版本。

保留单任务流、可靠输出、Worker checkpoint 和 Server 的 Serve/Stop/GracefulStop。任务 bidi 先整批提交输入、再流式输出；交互式双向通信使用网络入口。

## 使用方式

```go
cfg := []runtime.Option{
    // 此处按部署配置 token、gRPC/API 地址与 TLS。
    runtime.WithRoutingDefaults("process-message", map[string]any{"group": "default"}),
    runtime.WithRoutingDefaults(pb.Greeter_SayHello_FullMethodName, map[string]any{"group": "default"}),
    runtime.WithEventRoutingDefaults("message:created", map[string]any{"group": "event"}),
    runtime.WithPayloadLimits(runtime.PayloadLimits{
        MaxMessageBytes: 1 << 20, MaxEncodedBytes: 4 << 20,
        EncodeTimeout: 10*time.Second, DecodeTimeout: 10*time.Second,
    }),
}
opts := []client.RunOption{
    client.WithRouting(map[string]any{"group": "group-a", "cost": 3}),
    client.WithRunPriority(1), // 官方优先级范围 1–3。
    client.WithRunMetadata(map[string]string{"source": "api"}),
}

// 生成客户端和原生提交使用同一组选项。
reply, err := pb.NewGreeterClient(conn).SayHello(ctx, request, client.WithRunOptions(opts...))
result, err := conn.Run(ctx, pb.Greeter_SayHello_FullMethodName, request, opts...)
result, err = conn.Run(ctx, "process-message", map[string]any{"message": "hello"}, opts...)

// Cron、Schedule、Event 和 Filter 可以显式提供业务值与 routing。
input := model.Input{Value: request, Routing: map[string]any{"group": "group-a"}}
err = conn.Events().Push(ctx, "message:created", input)

// 提交幂等键仅用于流；普通任务使用定义级 CEL 幂等策略。
stream, err := pb.NewGreeterClient(conn).WatchHellos(ctx, request,
    client.WithRunOptions(client.WithStreamIdempotencyKey(operationKey)))
```

routing 合并顺序为 Runtime 默认值 → `model.Input.Routing` → 本次 RunOption。顶层覆盖，嵌套对象整体替换；保存独立 JSON 快照。循环引用、NaN/Infinity 和不安全整数拒绝提交，超过 JSON 安全整数范围的调度值应使用字符串。routing 数字按服务端 JSON float64 规范化，例如 1e3 与 1000.0 都保存为 1000，避免封包内外数值表示不一致。业务载荷中的大整数仍可准确传输。

官方命名保留 WithRunKey/Sticky/Priority/Metadata/DesiredWorkerLabels；RunKey 是父任务中的稳定子调用键。旧 WithRPCRouting、context 配置入口与 model.RPCInput 不保留。

## 协议与执行

```mermaid
flowchart LR
    A[生成客户端 / Run / 触发器] --> B[验证注册绑定与选项]
    B --> C[JSON / ProtoJSON 快照]
    C --> D[统一封包与 codec]
    D --> E[Hatchet 明文 routing 调度]
    E --> F[Worker 逆序 codec 与解码]
    F --> G[业务 handler]
    G --> H[输出统一封包]
    H --> I[结果 / 父输出 / 客户端还原]
```

外层保存版本、作用域、codec 标识、routing 及流幂等字段；内层保存序列化类型、protobuf 类型名、业务数据、metadata、trace 与执行 deadline。内层整体执行 codec，任务 JSON 出口统一 base64，包括未配置 codec 的情况。引擎的浮点 map 不接触业务大整数。

protobuf 使用 ProtoJSON/UseProtoNames，普通 JSON 动态值使用 UseNumber。合法 null 与缺少结果区分。声明的 protobuf 类型必须匹配，解码成功且消息限制通过后才修改调用方结果。

DATA、CLAIM、HEADERS、结束帧与 Worker 通知整体执行 codec 一次。原生 StreamEvent 使用独立业务帧，SubscribeToStream 还原后交付字节，不交付 RPC 控制帧。可靠流的 CLAIM、代次过滤、producer 去重和终态对账保持共同解释器。

普通任务、durable、Batch 成员结果分别编码；DAG ParentOutput 使用调用 context 还原父输出。WaitForEventInto 共用一次持久等待，可解码 protobuf；Filter payload 在进入 handler 前还原，Info 不触发远程 I/O。

事件按事件键封包并使用事件 routing 默认值，支持多目标。Cron/Schedule 创建 context 的绝对 deadline 不写入未来任务。静态 Cron/Filter 输入通过 codec 前内容摘要复用已注册封包，不使用固定加密 nonce；并发首次注册不承诺原子单版本。外部 HTTP 请求由应用验证后调用 Events.Push/Run；官方 Webhook 管理不隐式接入裸 JSON handler。

## 调用语义与资源

| 入口 | context 取消 |
|---|---|
| 同步 Run、生成 unary、新建流 | 请求取消本次拥有的运行；durable eviction 不取消已记录子运行 |
| RunNoWait、RunMany | 停止提交，已确认运行继续，不固化执行 deadline |
| RunRef.Result、ResumeStream | 只结束当前观察或消费 |
| RunRef.Cancel | 显式取消共享运行 |

RunMany 在 codec I/O 前检查全批选项、快照、序列化和类型；按官方限制分批，不明确提交后停止后续批次。保留已确认 RunRef、失败/未提交/不明确索引；无法证明 RunID 对应位置时 InputIndex=-1，不猜测顺序，不自动重试普通任务。

Result.Raw 返回存储格式快照；业务读取使用 Into/IntoContext，统一还原 codec 并返回错误。恢复只验证存储运行身份及输入，已有 RunID 不依赖当前 workflow 定义仍存在。消费凭证仅在消息成功交付后推进；恢复拒绝新的调度选项。

Worker CallOption 支持 WithRunOptions、Header、Trailer、MaxCallSendMsgSize、MaxCallRecvMsgSize、OnFinish、StaticMethod。消息限制最后一次设置生效，零允许空 protobuf，负数报错；不支持的传输选项明确失败。拦截器短路不遗留登记，OnFinish 在锁外执行一次。

Payload 必须提供稳定 CodecID 和 DecodeLimit，遵守 context 且并发安全。编码、下载、解压、中间字节和完整请求分别受预算约束。普通消息默认原文 1 MiB、封包 4 MiB、编码/解码各 10 秒；流限制独立。所有 SDK codec/结果/订阅/上报 I/O 登记到 Engine；强制停止使用独立清理预算。

## 包职责

| 包 | 职责 |
|---|---|
| client / internal/client | 统一 RunOption、目标解析、提交所有权、RunRef 与结果视图 |
| runtime / internal/spec | 配置快照、默认 routing、载荷限制与校验 |
| internal/wire | JSON/ProtoJSON、通用封包、有界 codec、控制与业务帧 |
| internal/rpc | 标准桩、CallOption、拦截器、输入封包及流恢复 |
| internal/features | 触发器、事件、Filter 与原生输出消费 |
| internal/engine | 实例 I/O、取消、资源所有权及排空 |
| internal/backend | 官方绑定、注册、执行器与协议转换；唯一 Hatchet 依赖边界 |

callctx 只承载执行身份、trace、metadata 和消费状态，不另存一套运行选项。
