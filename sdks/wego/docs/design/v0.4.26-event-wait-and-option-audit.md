# wego 0.4.26：事件等待选项与可选字段复核

核验日期：2026-10-14。SDK `0.4.26`，消息协议 `6`，依赖未经修改的官方 Hatchet `v0.110.5`。

## 事件等待 API

两个入口统一使用函数选项，不再接收 `model.EventWait` 实参：

```go
now, err := task.Now(ctx)
if err != nil {
    return err
}
opts := []task.EventWaitOption{
    task.WithEventScope("user:123"),
    task.WithConsiderEventsSince(now.Add(-time.Minute)),
}

// map 结果与类型化结果入口二选一，分别只登记一次持久等待。
event, err := task.WaitForEvent(ctx, "user:update", "", opts...)
err = task.WaitForEventInto(ctx, "user:update", "", target, opts...)
```

规则：

- 省略 scope 表示不限制范围；`WithEventScope("")` 表示明确匹配空范围。
- 不传回溯选项则不读取历史事件；显式时间包括合法的零值时间，不会用 `IsZero` 判断是否配置。
- 回溯必须同时设置 scope；nil 选项、缺少 scope、超出官方 Timestamp UTC 公元 1–9999 年范围的时间在登记等待前失败。
- 重复选项最后一次生效；每次应用生成独立的参数指针，同组选项可以并发复用。
- `model.EventWait` 保留为后端接收的已解析快照，内部指针保留字段存在性。公共调用不需要取地址，不暴露 Hatchet 类型。
- 持久等待序号、事件解码、context 预算与 durable 重放路径均不增加第二次等待。

官方同样以值参数构造选项，并在内部保留可选指针，见 [condition.go](../../../../pkg/worker/condition/condition.go)。历史查询要求 scope 和时间均存在，见 [durable_events.go](../../../../pkg/repository/durable_events.go)。

## 此前指针改值类型的复核

复核范围为此前迁移过的配置字段、backend 转换及官方校验和默认值；并非将所有指针都视作可删除。结论：当前迁移没有丢失已核验的合法配置，但数字零值改为未指定属于明确的 SDK 契约，不能称为所有输入行为完全不变。

| 字段／入口 | 当前规则 | 判断 |
|---|---|---|
| DesiredWorkerLabel.Comparator | 零值显式发送 EQUAL，官方省略时同样默认 EQUAL | 合理；绑定当前默认相等语义，全部比较枚举仍可表达。 |
| Concurrency.LimitStrategy | 空字符串不发送；有效枚举原样映射 | 合理；空字符串不冒充任何策略。 |
| RateLimit.Duration | 空字符串不发送周期；非空合法枚举映射官方周期 | 合理；保留官方周期默认，不将 nil 强行写成 SECOND。 |
| Cron／Schedule.Priority | 0 不发送；1–3 显式发送，其他值报错 | 合理；官方有效范围不包含 0，SDK 将它明确保留为未指定。 |
| Concurrency.MaxRuns | 0 不发送，当前官方缺省为 1；正数发送，负数报错 | 合理；静态 0 不是官方合法暂停配置。需要暂停时使用动态表达式返回 0。 |
| Concurrency.MaxRunsExpression | 空字符串不发送；非空表达式包括 `"0"` 原样发送 | 合理；空表达式不是有效 CEL，数字零表达式没有丢失。 |
| RateLimit.KeyExpr／UnitsExpr／LimitValueExpr | 空字符串不发送；非空 CEL 原样发送 | 合理；`"0"` 和字符串字面量表达式 `"''"` 均非空，仍能表示零消耗或空字符串结果。 |
| Batch.MaxInterval | 0 不发送，官方缺省 1000ms；显式值 1ms–24h | 合理；官方显式 0 不在合法窗口范围内。 |
| Batch.GroupMaxRuns | 0 不发送，官方缺省 100；显式值 1–10000 | 合理；官方显式 0 不在合法并发范围内。 |
| Batch.GroupKey | 空字符串不发送，使用官方默认分组表达式；非空 CEL 原样发送 | 合理；官方创建入口也将空字符串视作使用默认分组。 |
| Events.Push 的可选 scope 字符串 | 不传参数保留 nil，传 `""` 保留非 nil 空字符串 | 合理；参数存在性保留，不是单个 string 零值代替可选指针。 |
| EventWait.Scope／ConsiderEventsSince | 公开改函数选项，内部继续保留 nil 与显式值 | 必须保留存在性；直接使用零值判断会改变 scope 匹配与回溯行为。 |

依据：[官方配置校验](../../../../pkg/repository/workflow.go)、[创建与 Batch 默认值](../../../../internal/services/admin/v1/server.go)、[SQL 缺省映射](../../../../pkg/repository/sqlcv1/workflows.sql)、[wego 转换](../../internal/backend/definitions.go)、[事件发布入口](../../internal/features/triggers.go)。

以下字段继续保留可选指针或 `option.Option`：

- RateLimit.Units：nil 与显式 0 分别表示未指定和零消耗。
- RunOptions.Key／Sticky／Priority：省略与显式键、false、优先级覆盖需要区分；`WithRunPriority(0)` 明确报错。
- EvictionPolicy.TTL／AllowCapacityEviction／Priority：显式 0、false 与继承默认需要区分。
- Runtime 的 TLS 配置：显式 nil 表示明文连接，必须保留是否配置的标记。
- Webhook 的可选开关与父运行、流终态等可选信息：不以零值伪造字段存在性。

这些结论针对当前官方契约。新增合法零值、服务端默认值变化或配置合并需要显式清除时，应再次核验存在性，而不是继续机械移除指针。

## 修复与验证

TTL 事件驱逐示例同时配置回溯时间和 `eviction:resume` scope，发布端传递相同 scope，避免历史匹配配置无效。

以下检查通过：

- `GOWORK=off python3 scripts/unit.py -race -count=1`：SDK 单元测试、生成复现、中文注释和 API／依赖边界门禁；手动 feature/client 单独编译，不运行其服务依赖用例。
- `GOWORK=off go vet ./...` 及 e2e 包的 vet；feature/client 编译通过。
- 本机官方引擎上的 `TestEventWaitOptions`：两种入口各验证显式空 scope 和具体 scope，错范围事件不会匹配，四个历史事件读取均成功。
- `TestExamples/durable-event`：基本等待、CEL 过滤、scope 与 lookback。
- `TestExamples/eviction`：TTL 事件、TTL Sleep、容量驱逐与禁止驱逐；等待在重放后继续使用原记录。

真实验收命令（在 SDK 目录执行，令牌文件只传入子进程环境）：

```bash
WEGO_TOKEN_FILE=tests/feature/.env python3 scripts/local-test.py \
  env GOWORK=off go test -race -count=1 -v -tags=e2e ./tests/e2e \
  -run '^TestEventWaitOptions$|TestExamples/(durable-event|eviction)$' -timeout 5m
```
