```go
// Acquire 发布并确认 CLAIM
func (c *ClaimManager) Acquire(ctx context.Context) (Outcome, error) {
    // 1. 发布 CLAIM(seq=0)
    if err := c.publish(ctx, claimFrame); err != nil {
        return Uncertain, err
    }
    
    // 2. 读回验证
    for {
        entry := <-c.subscription
        frame := decode(entry)
        
        if frame.Kind == "CLAIM" && frame.Epoch == c.epoch {
            if frame.Writer == c.nonce {
                return Owned, nil  // 获胜
            } else {
                return Lost, nil   // 落选
            }
        }
    }
}
```

✅ **优点**：

### 2.3 并发安全 ✅ **优秀 (5/5)**

**锁的使用规范**：

**示例 1：taskClientStream 双向独立**（internal/rpc/stream_client.go）：
```go
type taskClientStream struct {
    sendMu  sync.Mutex  // 串行保护输入快照与 CloseSend
    recvMu  sync.Mutex  // 拒绝并发读取
    mu      sync.Mutex  // 保护接收状态
    changed chan struct{}  // 状态广播
}

func (s *taskClientStream) SendMsg(m any) error {
    s.sendMu.Lock()
    defer s.sendMu.Unlock()
    // 编码并保存快照
}

func (s *taskClientStream) RecvMsg(m any) error {
    s.recvMu.Lock()
    defer s.recvMu.Unlock()
    // 等待或读取缓冲
}
```

✅ **优点**：
1. 发送和接收独立锁，不相互阻塞
2. 禁止并发 RecvMsg（checkpoint 次序不明确）
3. 状态广播使用 channel，避免轮询

**示例 2：远程 I/O 在锁外执行**：
```go
func (s *taskClientStream) consume() {
    s.mu.Lock()
    needMore := len(s.queue) < PrefetchLimit
    s.mu.Unlock()  // ← 解锁后才执行 I/O
    
    if needMore {
        entry := <-s.subscription  // 锁外
        
        s.mu.Lock()
        s.queue = append(s.queue, entry)
        broadcast(s.changed)
        s.mu.Unlock()
    }
}
```

✅ **优点**：
1. 避免持锁等待 I/O
2. 减少锁竞争
3. 中文注释明确说明："网络 I/O 永远在此锁外执行"
