# v0.3.3：RPC 默认事件与 CodecID 解码

协议保持 5；业务、控制帧、结果和通知仍使用 wego 封包。不接入 Console 或官方 SDK 的裸 JSON。仅修改 wego SDK，Hatchet 实现与根依赖不变。

## 组件注册与发送链

复用 `middleware.Payload`、`WithPayload`，组件必须提供稳定 CodecID、Encode、Decode 与有界 DecodeLimit，支持并发调用并遵守 context。

- `WithMiddleware` 注册接收组件，也决定未显式配置时的编码顺序。
- `WithEncodingCodecs(ids...)` 独立选择发送链；重复配置最后一次生效。显式空链保留接收能力，仍生成封包。
- Runtime 验证并冻结只读 ID 注册表及发送链；Worker 局部配置独立准备。
- nil、typed nil、空或非法 UTF-8 ID、重复组件 ID、未注册的发送 ID 在初始化资源前失败。
- 发送链允许重复 ID，保留每次变换。接收时先确认完整 ID 列表存在，再逆序 DecodeLimit。未知 ID 不触发下载、解密或解压。
- 接收端可注册额外组件；两端注册和发送顺序可不同。持久消息的 ID 列表是解码依据，不能用当前发送链解释历史。

示例组件常量为 `payload.GzipCodecID`、`payload.AESGCMCodecID`、`payload.S3ObjectCodecID`，字符串分别为 `example.gzip.v1`、`example.aes256-gcm.v1`、`example.s3-object.sha256.v1`。相同 ID 必须有兼容的解码配置，ID 不解决密钥、bucket、目录或历史对象缺失。

所有 wire 入口接收冻结 Runtime：任务、RPC、durable、DAG、Batch、结果、事件等待、Filter、流帧、实时任务消息、Worker 通知。静态输入摘要采用存储消息的实际编码链，排除随机 nonce 和对象路径。仅改变接收组件顺序不会改变静态输入的解释。

## 默认事件

启用 RPC 的最终事件集合为生效自定义 Events 加 FullMethodName；过滤禁用方法、合并策略后加入，再按官方 namespace 规则生成 key 并稳定去重。纯网络模式不创建任务事件。

`Events.Push(ctx, key, model.Input{Value, Routing})` 仍使用统一封包。unary／server stream 使用单个请求；client stream／bidi 使用 protobuf 数组，空流为 `[]`。数组逐项 ProtoJSON，拒绝 nil 和混合 protobuf 类型。

事件 routing 采用事件默认值与显式覆盖，不借用接收方法默认值。发布 deadline 只限制本次发布。事件 scope 绑定 key，可同时触发多个 RPC。

每次 Push 生成独立调用身份；同次发布冻结身份和内容摘要。流事件幂等前缀包含 namespace 和方法，避免不同方法互相抑制。直接 RPC 的幂等行为不变，不承诺多次 Push 自动去重。

Worker 根据注册描述验证输入。Reliable 先确认 CLAIM 再解码；获胜者报告解码／类型错误，落选者不报告失败。一次执行只解码一次。CLAIM、checkpoint、结束清单与引擎终态仍用现有验证；Realtime 发布经过 codec 的 wego 帧。

## 升级与验收

字节布局及 CodecID 字符串值不变；启用不同发送链前升级 Client 与 Worker，因为旧接收端会校验相同顺序。历史解码所需的组件、密钥和对象需保留到历史过期。

新增本机测试 `TestRPCEventsCodecIDs`：四种默认事件、共享事件双方法、空数组、gzip／AES／S3／组合／空链，Client 和 Worker 注册与发送顺序不同；读取实际持久结果和输出日志验证数据及执行身份。单元覆盖未知 ID 零 I/O、重复步骤、配置快照、静态摘要及无效流输入的获胜者失败上报。

验收状态与实际命令记录在 [专项报告](v0.3.3-report.md)，完整配置示例见 [worker.md](worker.md)。
