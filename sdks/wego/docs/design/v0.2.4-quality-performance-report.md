# 0.2.4 代码质量与性能评审处理报告

日期：2026-10-09。输入为 [代码质量评审](v0.2.0-code-quality-review.md) 与 [性能评审](v0.2.0-performance-review.md)。SDK 为 `0.2.4`，通信协议保持 `4`；真实环境使用官方 Hatchet `v0.110.5`、PostgreSQL MQ、MinIO。没有修改 Hatchet 源码或根模块依赖。

确认的问题已修复并验证。评审中的推测、示意代码和预期收益逐项核对，没有直接当成事实或实现依据。原始评审保留，完整数值、命令、RunID 和清理身份见 [结构化报告](v0.2.4-quality-performance-report.json)。

## 逐项处理

| 评审项 | 处理结果与依据 |
|---|---|
| `run.go` 528 行、职责混合 | 拆为结果等待 `run.go`、请求冻结与提交 `submit.go`、选项及提交锁 `run_options.go`。仍在同一 backend 包，不引入转发层。名称验证、输入预编码、父子身份绑定独立，部分提交和幂等错误汇总保持完整。 |
| `stream_receive.go` 518 行 | 输出观察/背压/统一关闭进入 `stream_observe.go`；消费、metadata 与唯一响应解码留在 `stream_receive.go`。相关文件均低于 400 行。 |
| “I/O 均在锁外” | 发现 client stream 唯一响应在状态锁内执行业务 codec，可能被 S3 下载阻塞。改为锁外解码，应用独立 DecodeTimeout，再锁内核对终态。Stop 与下载并行；迟到成功不能覆盖取消或推进 responseRead。屏障回归覆盖取消、超时、迟到响应。 |
| 每帧两次序列化、多次分配 | 保持 protobuf 外层格式，使用 `protowire` 追加封装字段。无 codec 时直接将内层 protobuf 追加到最终独立缓冲；有 codec 时仍提供独立输入，最终结果复制 codec 输出。长度 varint 边界、封装预算、UTF-8 格式标识和快照隔离有回归。 |
| 对象池建议 | 不池化逃逸到消息队列、checkpoint 或自定义 codec 的对象/字节。一次分配的封装已经降低分配成本，无池保留和重用导致的数据覆盖风险。没有采用未经测量的“40–60% 收益”承诺。 |
| CLAIM 编码缓存 | 当前 CLAIM 在一次竞争中已经只编码一次，不明确 ACK 使用同一 producer/序号/字节重试。跨执行 nonce 缓存没有额外收益，还会增加保留状态。补齐获胜/落选/起点丢失/预算/拒绝的单元测试和实际引擎竞争回归。 |
| Clone / copy-on-write | 保留公共配置、metadata、结束帧及 checkpoint 的独立快照。内部子提交只读取冻结的父身份，避免为三个身份字符串复制业务 metadata/labels。未引入缺乏所有权契约的共享可变 map 或引用计数。 |
| envelope 元数据缓存 | 不缓存按方法复用的 metadata：deadline、trace、调用幂等身份和业务 metadata 都按调用变化。无 codec 的 ProtoJSON 本来就保留 JSON 对象，仅变换路径使用 base64；修正评审关于所有输入都增加 base64 的描述。 |
| 批量读回/发布 | 官方订阅已按一批 Entries 接收，backend 再逐项解释。RunMany 已按数量和完整协议字节分块提交。持久发布仍遵守 producer 串行序号、冻结重试，不为了减少调用次数改变协议或提前提交不完整输入。 |
| 执行索引 TTL 清理 | `latest`、`pending`、`cancels` 已按执行退出回收，不为仍活跃的长期/durable 执行加入 TTL 删除。新增 1024 个独立落选候选回归，等待实际索引清零；不把 race 通过当作无泄漏证明。 |
| 未量化覆盖率 | 保存原始 profile、按语句加权的原始全量/生产/包级报告。核心协议最低 70%；其他包按已测基线防退步，未宣称整个 SDK 单元覆盖率已达到 70%。 |
| “无复杂度 >15 函数” | 实际扫描不支持这一结论。降低日志解释器及提交路径复杂度；固定 `gocyclo v0.6.0`，显式登记现存复杂函数，禁止新增 >15 或现有复杂度增长，包含互斥 build tag 的最高值。 |
| 性能与资源观测缺失 | 增加 FrameCodec、ProtoJSON envelope、CLAIM、长日志解释基准，保存 CPU/heap profile。增加实例 encode/decode 次数/耗时及预取字节指标，默认关闭，身份/游标不作为标签。真实负载记录吞吐、P50/P95/P99、进程 heap/分配/GC/goroutine 峰值。 |
| 独立模块验收 | 发现 embedded 子模块缺少 MinIO 示例引入的 AWS S3 间接依赖与校验和。补齐两个独立模块，实际启动独立数据库/嵌入引擎，调用后关闭并删除测试库。 |

## 实测结果

本机 Apple M2 Max，Go 1.26.7。微基准前后各三次，表中耗时为中位数。分配变化更稳定；这些数值不是跨机器保证。

| 路径 | 修改前 | 修改后 |
|---|---|---|
| 无 codec，1 KiB 帧编码 | 840.7 ns，2400 B，3 allocs | 400.4 ns，1152 B，1 alloc |
| AES-GCM，1 KiB 帧编码 | 1349 ns，3584 B，6 allocs | 1283 ns，3488 B，5 allocs |
| 无 codec，64 KiB 帧编码 | 22928 ns，147553 B，3 allocs | 9767 ns，73729 B，1 alloc |
| CLAIM 本地发布与读回 | 2291 ns，2480 B，36 allocs | 2068 ns，2288 B，34 allocs |
| 一万条有效输出日志解释 | 95094 ns，0 alloc | 113060 ns，0 alloc |

日志解释器拆分提高了校验可读性与复杂度约束，微基准显示约 18.9% 的扫描 CPU 增量，即每帧约 1.8 ns；没有隐瞒或称为性能提升。当前没有分配，真实路径仍包含持久写入、订阅及调度，不据此修改恢复保证。

真实引擎负载：100 路调用、32 业务 slots、每路十条 1 KiB 输出，合计 100 个独立运行和 1000 条输出；全部顺序、RunID、checkpoint 和权威 EOF 断言通过。最终版本在 race 模式下观测到约 15.42 calls/s、154.23 messages/s，端到端 P50/P95/P99 为 4.486/5.537/6.481 秒；采样峰值 Go heap 约 26.5 MiB、goroutine 1000。它们是本测试进程数据，包含 race 开销和调用排队，不是整个 Hatchet/PostgreSQL 资源，也不代表长期容量上限。

没有执行“1000 QPS 持续十分钟”耐久负载，也没有宣称达到该指标。`WEGO_PERF_CALLS`、`WEGO_PERF_CONCURRENCY`、`WEGO_PERF_MESSAGES` 可配置以复现实验；使用 deadline 和实际输出断言，避免仅提交成功就算吞吐。

## 覆盖率和质量边界

| 范围 | 本轮单元语句覆盖率 |
|---|---:|
| 原始全量，包含生成/示例/工具代码 | 32.345% |
| 生产代码，排除 `.pb.go`、examples、tests、scripts | 51.469% |
| internal/stream | 83.668% |
| internal/wire，排除生成协议代码 | 72.260% |
| internal/backend | 52.921% |
| internal/rpc | 48.983% |
| server | 73.684% |

整个 SDK 的单元覆盖仍有提升空间。真实引擎的 252 条场景断言不能冒充单元覆盖率。CI 同时保存原始 profile 与明确排除项，不通过删除未测的生产文件制造 70%。

固定工具发现 41 个现存生产函数复杂度 >15，已显式登记最大值。日志解释器入口从 36 降到 ≤15，提交入口从 57 降到 33。剩余复杂函数没有为满足数字机械拆成转发方法；本轮门禁防止增长，不宣称复杂度债务全部消失。

`tests/feature/client` 是手动调用入口，依赖单独启动的 Worker 和私有配置。保留用户当前的普通测试入口，增加连接关闭和 deadline。`scripts/unit.py` 明确排除此一个包，不排除 SDK、质量检查或新增包；必需 RPC 场景由 `tests/e2e` 实际运行。直接 `go test ./...` 仍会执行该手动入口，环境未准备会失败。该排除项写入机器报告，门禁工具自身有范围回归。

## 验证与清理

- SDK 单元入口、race、vet、中文声明注释、公开 API/错误类型隔离、包边界、生成可复现检查通过；脚本 19 项回归通过。
- 官方 Go SDK、底层 client/worker 上游回归通过；源码边界检查通过。
- 30 个普通示例场景、252 条真实断言通过；覆盖普通验收 manifest。embedded 独立进程与数据库验收补齐第 28 个官方源文件。
- 三种流、故障矩阵、MinIO codec、重启恢复、实时输出、定向/广播、提交响应丢失、CLAIM 和最终状态隔离通过真实引擎 race 验证。
- 帧解码及日志解释器 fuzz 通过；资源回收单独验证，不由 race 推断。
- 取消与引擎超时回归采用独立预算，避免 2 秒执行超时抢先终结控制台取消场景。P0 保留期测试显式启用隔离故障 fixture，未 Skip。
- 普通场景删除自己创建的定义与触发器；额外删除本轮 14 个 P0 定义，保留用户的六个业务定义。运行/topic/对象历史按保留策略留存，embedded 测试库已删除。报告不记录凭证。
- CI 模板已加入覆盖率、复杂度、分配基准和 profile 产物；自托管启动点继续显式关闭 security check，使用 PostgreSQL MQ。托管 CI 未运行。
