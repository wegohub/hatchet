# v0.2.0 P0 协议可行性报告

验证日期：2026-10-09。SDK `0.2.0-dev.1`，公开 RPC 协议仍为 `3`，持久日志原型为 `4`。本报告证明 P0 组合协议和执行门禁的可行性，不表示生成客户端的单任务流、恢复 API 或 Worker 事件已经交付。

## 环境与工程边界

- 独立模块使用未经修改的官方发行依赖 `v0.110.5`，所有发行检查使用 `GOWORK=off`。
- 本机使用官方 `hatchet-engine:v0.110.5`，镜像 digest 为 `sha256:185c4311d23fad2faecd5fdd771369a369f33cbfa0e9f4083a952c4fe1c15808`；API `localhost:8080`，gRPC `localhost:7077`，PostgreSQL MQ。
- 部署初始化为本机验收租户启用 Durable Streams entitlement；SDK 不操作数据库配置。
- 所有代码改动在 `sdks/wego/**`。没有修改官方源码、根模块依赖或使用发行版之外的补丁。
- 受控历史删除仅作用于本次 `p0-*` namespace 的指定 topic/producer，由显式启用的本机 fixture 完成。

```bash
python3 sdks/wego/scripts/local-test.py env GOWORK=off WEGO_P0_FAULT_FIXTURES=1 \
  go -C sdks/wego test -tags=e2e ./internal/backend \
  -run 'TestDurableStreams.*P0|TestGated.*P0' -count=1 -v -timeout 4m
```

两次 fuzz 分别执行 269,495 和 335,573 次，未发现失败。发行依赖检查、公开类型/动态错误隔离、中文注释、生成可复现与 acceptance manifest 门禁通过。

## 实测决定与后续限制

1. 官方执行器的 task-only cancelMap 无公开清理屏障。Reliable 普通任务使用 wego 私有按代次执行路径，复用官方注册、连接、分配及 slots；其余任务继续官方执行器。没有改动上游。
2. 结果通知只是查询触发器；成功判定读取正式 GetRunDetails 的当前权威终态。成功任务的空字符串错误字段不当成失败。
3. 官方幂等 key 在 tenant 内共享，必须纳入 namespace 与 fullMethod。仅把 key 放入输入而不隔离作用域会误恢复另一运行。
4. Realtime 没有订阅就绪 ACK；后续实现必须通过序号和最终清单把漏帧变成明确失败，不能保证网络断开时完整交付。
5. 失去 epoch=0 CLAIM 的完整历史不可恢复；producer 水位失效不能自动换身份续写。这些错误牺牲可用性以避免静默输出损坏。
6. 输出过滤不阻止旧 Worker 的物理写入，也不保证外部业务副作用只发生一次。
7. 当前崩溃窗口通过传输读回失败、晚写和门禁故障注入验证。完整进程 kill/restart、公开 checkpoint/ResumeStream、事件订阅关闭和单任务三种流仍属于 P2–P5。

所有测试 Worker 已关闭，实际 slots 已回收。测试定义、运行和 topic 历史按引擎保留策略保留；本阶段未删除共享资源或既有业务数据。
